## 1. 概述

### 1.1 定位与边界（先读这一节）

会议模块不重新设计任何媒体能力。**通话（05 篇）解决"媒体怎么连"，会议解决"一场会怎么约、怎么开、怎么收尾"**。分工如下：

| 能力 | 归属 | 本篇态度 |
|---|---|---|
| 房间/SFU/simulcast/编解码/弱网降级/节点迁移/TURN | **05 篇 §5/§7** | 直接复用，零重复 |
| 通话信令（rtc.* 事件）与主/被叫状态机、质量摘要 call_member.quality | **05 篇 §4/§6.1** | 会议入会＝"加入一场预约好的群通话"，状态机不重画；质量摘要记录页直接读取 |
| 会中聊天 | **04 篇** | 绑定临时会话（§4.7） |
| 会议材料/纪要附件/转写存档 | **07 篇** | 一律 file_id / 对象键引用，不另建存储 |
| ASR 与 LLM | **19 篇 ai-gateway** | 转写与纪要的唯一模型通道 |
| 外部邮箱邀请（iCal 附件） | **22 篇 mail-svc** | 仅作为发送/回执通道（§4.4） |

新增服务：**meeting-svc**（预约/日历/纪要编排），部署上并入模块化单体（02 篇 §1），**回填 02 篇 §3 服务清单**。

### 1.2 场景

| # | 场景 | 说明 |
|---|---|---|
| S1 | 即时会 | 通话面板/会话内一键"立即开会"，生成会议号即可拉人 |
| S2 | 预约会 | 预约弹窗选人选时间，忙闲冲突提示，邀请落日历 |
| S3 | 周期会 | 部门周会/日报站会，RRULE 简化子集循环展开 |
| S4 | 会中协作 | 议程跟随、材料共享、会中聊天、主持控制 |
| S5 | 会后收尾 | AI 纪要→确认→一键分发（群/知识库/邮件），记录归档 |

### 1.3 非目标

外部访客入会（阶段四，安全前置条件见 §7.3）、会议录制（阶段四，租户策略默认禁）、物理会议室预订（开放问题 §9）、PSTN/SIP 入会、跨租户会议（开放问题）、Web 端入会页面（仅预留链接落地页拉起客户端）。

## 2. 角色与场景

| 角色 | 会议行为 |
|---|---|
| 组织者 | 预约/改期/取消、编议程、挂材料、开转写、确认纪要并分发 |
| 主持人 | 默认=组织者，可移交；会中全员静音/移除/锁定/等候室准入 |
| 参与者 | RSVP、入会、会中聊天与材料查看、收到纪要（外部访客=阶段四，§7.3） |
| 租户管理员 | 会议策略（并发/时长/录制/访客/转写）、会议室利用率统计 |
| 审计合规员 | 会议元数据（时间/参与者/纪要操作）只读检索，媒体与转写内容不入审计正文 |

| 关键约束 | 说明 |
|---|---|
| 一场会一活动通话 | meeting 与 call_session 一对多（重开算新场次），同一时刻最多 1 场活动 |
| 单设备单活动通话 | 沿用 05 篇（busy 自动回绝）；会议=群通话超集，入会后媒体/超时/重连全按 05 篇执行 |

## 4. 核心流程

### 4.1 会议实体与生命周期

```
会议实体: meeting_id(雪花) + meeting_no(9 位会议号, 租户内唯一)
          + 双形态链接: bbw://meeting/{id}?t={join_token} (深链) /
                        https://meet.{租户域名}/m/{meeting_no} (落地页→拉起)
类型: instant 即时会 / scheduled 预约会 / recurring 周期会(系列→多场)

生命周期(业务态, 与 05 篇通话态正交):
 scheduled ──到点/主持人入会──► live ──全员退出30s或主持结束──► ended
    │                           │                              │
    └──组织者取消──► canceled    └──重开(新 call_session)──► live ┴─► archived
                                                              (纪要发布+保留期满)
 周期系列: meeting_recurrence(规则) 1─n meeting(每场一行, series_id 关联)
```

### 4.2 预约与周期展开（RRULE 简化子集）

| 项 | 约定 |
|---|---|
| 频率 | 仅四种：每日 / 每周(选周几) / 每两周 / 每月(按日或"第 N 个周 X") |
| 结束 | 按场次上限（默认 ≤ 52 场）或截止日期，二者取先到 |
| 跳节假日 | 可配开关；节假日来源=租户节假日日历（管理员维护/导入法定安排）；命中节假日的场次**跳过不顺延** |
| 展开 | 服务端预展开成 meeting 行（每场独立会议号可选共用系列号；默认各场独立会议号、邀请与纪要独立） |
| 系列编辑 | 范围三选一：本场 / 本场及之后（拆分新系列）/ 整个系列 |

非法子集（如 BYSETPOS、INTERVAL>2 的周频、无限循环无上限）→ 5023。

### 4.3 忙闲查询与冲突检测（free/busy）

```
组织者提交预约 ─► meeting-svc:
  ① 聚合参与者 calendar_event(busy=真, 含 tentative):
     GET /calendar/free-busy {user_ids, from, to} → 各人忙段
  ② 计算与拟定时间的重叠 → 有重叠?
     ├ 无 → 落库+发邀请(§4.4)
     └ 有 → 返回 code=5022(警告级, 可覆盖错误) + conflicts 明细
            客户端弹"仍要预约/换时间" → 确认则带 force=true 重发 → 落库
```

约定：忙闲只聚合"忙"时段与全天事件（按 event.busy 标记）；外部访客与未连接日历者无忙闲（提示"无法检测"）；非工作时段不视为忙但展示为底色。5022 为**警告级**：首次请求被拒绝不落库，明细随错误返回，force 重试才生效。

### 4.4 邀请分发（应用内 + 群卡片 + 邮件 iCal）

| 通道 | 流程 |
|---|---|
| 应用内 | 参与者收 `meeting.updated{kind: invited}` + 通知中心待办；RSVP：接受/暂定/拒绝（写 meeting_participant.rsvp 并回写组织者） |
| 群绑定 | 创建/改期时在绑定群自动落 `meeting_card` 消息（**04 篇消息类型新增 14，回填 04 篇 §1.2**；body：meeting_id/会议号/标题/时间/状态，进行中带 [加入]）；状态变化更新卡片（不发新消息） |
| 邮件 iCal | 参与者含外部邮箱（或勾选"邮件通知"）→ meeting-svc 调 **22 篇 mail-svc** 以组织者邮箱发送 text/calendar(REQUEST) 附件；外部回执阶段三仅登记组织者手动更新 RSVP，自动解析 REPLY 列为阶段四 |

### 4.5 会前提醒

会前 15 min 与 5 min：meeting-svc 定时扫描 → WS 推送 `meeting.reminder{meeting_id, kind: 15min|5min|starting}` + 系统通知（notify）；绑定群内卡片置顶提示一次（不@全体）。错误提醒（已取消/已结束）静默跳过。

### 4.6 入会（四入口 + 等候室 + 锁定）

```
入口: ①会议号输入(PMT-01/通话Tab) ②双形态链接 ③日历[加入] ④群会议卡片[加入]
   ▼
meeting-svc: 解析 meeting (号/链接 token) ──不存在/过期──► 5020/5034
   ├ 校验: 已结束(5024, 提供记录页) · 租户并发上限(5025) · 策略禁用(5012 复用)
   ├ 参与者(在邀请名单)? 
   │   ├ 是 ──► 锁定中? ──是──► 5027 · 否──► 准入
   │   └ 否 ──► 等候室开放? 
   │         ├ 是 ──► 等候室(lobby 队列) → 主持人[准入→定向 meeting.updated
   │         │        {kind: admitted} / 拒绝]
   │         └ 否 ──► 5028 (基础版: 非邀请者一律需主持人准入=等候室常开)
   ▼ 准入 = 走 05 篇群通话加入路径(建/复用 call_session, rtc.* 信令, 状态机同 05)
```

### 4.7 会中：主持控制与聊天

| 主持动作 | 实现 | 广播 |
|---|---|---|
| 全员静音（可自我解除开关） | 经 media 面向全体关 Producer | `rtc.state`（05 篇，媒体变化） |
| 移除参与者 | 结束其 call_member 并标记禁再入 | `rtc.state{removed}`（05 篇）+ `meeting.updated` |
| 锁定/解锁 | meeting.settings.lock | `meeting.updated{kind: lock}` |
| 移交主持 | meeting.host_id 变更 | `meeting.updated{kind: host}` |
| 等候室准入/拒绝 | lobby 队列操作 | 定向 `meeting.updated{kind: admitted/denied}` |
| 开/停转写 | §4.8 | `meeting.updated{kind: transcript}` + 全员提示条 |

会中邀请他人复用 05 篇 `rtc.call.invite`（同 call_id 追加被叫）。会中聊天：**首次进入 live 时自动创建临时会话**（04 篇 conversation 类型扩展 `meeting_chat`，复用 group 全套机制，**回填 04 篇 §5**）；成员=本场参与者；会后默认只读保留 30 天（租户可配），组织者可"转正"为普通群。议程/材料/纪要区见 PMT-04；材料共享=预览+引导 05 篇屏幕共享，材料可"发到聊天"（文件消息，07 篇）。

### 4.8 实时转写与 AI 纪要（阶段三亮点）

```
①会中(组织者/主持人开启, 租户策略允许): 「本会议正在转写」提示条常驻
   + 新入会者弹知情提示(可退会)
   media-svc 插件位旁路混音(05 篇预留录制/纪要插件位)
     ──► meeting-svc 转写 worker ──► ai-gateway ASR(19 篇, 租户可配私有模型)
     ──► 增量转写文本(说话人+时间轴) 落对象存储 + 会中侧栏实时区滚动展示
②会议结束: meeting-svc 汇总转写全文+议程+材料清单+参与者名单
     ──► 推 meeting.updated{kind: minutes_ready}
③纪要生成(P1 默认): 主持人端编排层 Agent, 预置技能「会议纪要」(10 篇分发)
   拉取转写 ──OBO token──► ai-gateway LLM
   产出结构化草稿: 摘要 / 议题结论 / 决议 / 行动项[{内容, 责任人@, 截止}]
   (P2 兜底: 主持人 24h 未处理或技能未安装 → meeting-svc 服务端模板编排直调
    ai-gateway; 计量与审计主体=组织者; 租户策略可只留 P2 或全关)
④主持人确认编辑(PMT-05) → 定稿落 meeting_minutes(锁定)
⑤一键分发: [分享到群] 纪要卡片(meeting_card kind 扩展) / [入知识库] 纪要
   md 走 07 篇上传得 file_id → 11 篇摄入管线(来源④ Agent 产出, 组织者确认
   =显式确认, source_ref=meeting_id, 回填 11 篇) / [邮件发送] 经 22 篇外发
```

转写与纪要的模型用量计量归**组织者**；审计事件 `meeting.transcript.start/stop`、`meeting.minutes.confirm/publish`（subject=操作者）。合规开关：租户策略 `transcription_enabled`（默认开）与 `minutes_agent_enabled`（默认开）；关闭后入会提示条消失、菜单项隐藏。

### 4.9 会后与会议记录

结束后：记录页（PMT-03）聚合各场次时长/参与者/质量摘要（05 篇 call_member.quality）+ 纪要状态 + 材料清单；导出=纪要+议程+参与者 CSV（走 07 篇下载票据）。保留期：会议元数据默认 1 年（租户可配 90 天–3 年）；转写全文与纪要保留期同租户策略，删除会议=元数据软删 + 转写对象按保留策略清除（13 篇保留期表回填）。

| 字段 | 类型 | 说明 |

## 7. 边界与安全

### 7.1 边界与异常

| 场景 | 处理 |
|---|---|
| 并发上限 | 入会时计数判定（5025）；创建不占额度，策略默认 200 场/租户 |
| 单场时长/全员退出 | 默认 4 h（租户可配，同 05 篇）到点提示后结束；全员退出复用 05 篇"30 s 自动结束"，ended 后重开=新场次 |
| 改期/时区/DST | 重新校验忙闲（5022）+更新日历/卡片/重发 iCal；UTC 存储，周期按组织者时区展开、跨时区本地渲染，DST 重叠在展开时消解 |
| 组织者离职 | 交接：host 移交最近主持人或部门管理员（12 篇离职交接联动） |
| 媒体面异常 | 全部按 05 篇（重连/迁移/降级/设备异常），本篇仅透传错误 |
| 转写中断 | ASR 失败转 failed（5031），已转写段落保留；纪要走 P2 兜底或人工补记 |
| 会议号遍历 | 9 位随机 + join 限流（单用户 10 次/min）+ 链接 token 独立随机 |

### 7.2 安全

| 项 | 约定 |
|---|---|
| 链接防猜测 | 双形态链接带 join_token（独立于会议号）；token 随取消/结束失效 |
| 转写合规/审计 | 开启即全员提示条+新入会知情；转写内容仅组织者/参与者可见，**不用于模型训练**（租户策略，对齐 15 篇）；预约/取消/主持动作/准入/转写开关/纪要定稿与分发全量入 audit（元数据级） |
| 访客数据 | 阶段四前不落任何外部主体数据；iCal 外发仅含会议元数据 |

### 7.3 外部访客安全前置（阶段四评审门）

邮箱验证码核身、强制等候室、屏幕水印（15 篇水印策略联动）、访客会议默认禁录制禁转写、访客链接短时效（≤24 h）、访客不进入知识库/纪要分发范围。以上任一不满足则该能力不发布。

## 9. 开放问题

1. 物理会议室预订：投屏/大屏设备与 IT 资产域联动，是否引入"资源型日历"（会议室即被邀者）待与客户场景确认。
2. ASR 私有化选型（经 ai-gateway 路由的本地模型 vs 云端）：金融类租户要求转写不出边界，需 19 篇定路由策略与成本模型。
3. 跨租户会议（集团多子公司）：访客模型（阶段四）与租户隔离红线（00 篇原则 5）的折中——受控"互联域"是否成立。
4. 周期会"到场者差异"：连续多场的纪要与行动项是否需要系列级聚合视图；纪要 P1/P2 双路径的模型计量归属一致性需与 19 篇口径对齐。
5. 00 篇里程碑将"会议纪要"列于阶段四，本篇按纪要=阶段三建议（依赖 ai-gateway/技能分发就绪），回填 00 篇时需对齐。
