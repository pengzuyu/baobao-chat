## 1. 概述

### 1.1 定位与入口形态

管理后台是"让管理员一个后台管住整个组织"的落点（00 篇 §2），覆盖**平台运营域**与**租户管理域**两个权限域。入口形态为一套前端、两个载体：

| 入口 | 形态 | 说明 |
|---|---|---|
| 客户端内嵌 | 桌面客户端主导航"⚙️ 管理"（00 篇 §4） | **按权限显隐**：用户持有任一 `admin:*` / `platform:*` 权限点即显示；进入后模块树再按权限点逐项渲染 |
| Web 管理台 | 浏览器访问 `https://admin.<内网域名>`（nginx 路由到同一前端构建产物） | 复用同一 React 组件库（01 篇 §3：管理后台以 AntD 为主 + ECharts）；登录走同一 auth 服务（03 篇） |

两个入口的差异约束：

| 维度 | 客户端内嵌 | Web 管理台 |
|---|---|---|
| 凭据存储 | 系统钥匙串（refresh token，03 篇 §2.2） | **不落地 refresh token**：仅内存持有，页签关闭即登出；重开需重新认证 |
| 会话保护 | 跟随客户端主会话 | 闲置 15 min 自动锁定遮罩，重验口令/MFA 解锁（15 篇客户端加固） |
| 适用场景 | 管理员日常、兼顾 IM | IT 批量操作、大屏监控、无客户端环境 |

### 1.2 设计原则

| # | 原则 | 说明 |
|---|---|---|
| 1 | 权限驱动渲染 | 所有页面/按钮/接口三层的可见性由权限点决定；前端显隐仅为体验，**服务端是唯一判定方**（03 篇 §1） |
| 2 | 一切管理操作留痕 | 管理操作写 `admin_operation` 明细账，同时进入审计哈希链（00 篇原则 4、15 篇） |
| 3 | 批量操作异步化 | 超过阈值（导入 > 100 行、导出 > 1,000 条）一律转异步任务 `admin_task`，进度经 WS 推送 |
| 4 | 高危操作强确认 | 敏感操作二次验证矩阵（§4.1）：口令重验 / MFA / 双人审批分层施加 |
| 5 | 平台域与租户域硬分离 | `platform:*` 与 `admin:*` 权限点、URL 前缀（`/api/v1/platform/*` vs `/api/v1/admin/*`）、审计双写策略均分离 |

## 2. 角色与场景

### 2.1 角色与模块可见性

角色定义沿用 00 篇 §3 与 03 篇 §4.2；可见性矩阵（●可见可操作 / ○只读 / —不可见）：

| 模块 | 部门管理员 | 租户管理员 | 应用管理员 | 审计合规员 | 平台运营 |
|---|---|---|---|---|---|
| 组织树 | ●(本部门子树) | ● | — | — | ○(全租户) |
| 用户生命周期 | ●(本部门) | ● | — | — | ○ |
| 角色与权限编辑器 | ●(受限) | ● | — | — | — |
| 安全策略 / 消息合规策略 | — | ● | — | ○ | — |
| 生态应用与技能 | — | ○ | ● | — | ○(跨租户) |
| 知识库治理 | ●(部门空间) | ● | — | — | ○ |
| 审计中心 | ○(本部门) | ● | — | ●(只读+导出) | ●(跨租户) |
| 用量与配额 | ○(本部门) | ● | — | — | ●(可改) |
| 租户生命周期 / 套餐配额 / 平台监控 | — | — | — | — | ● |

> 部门管理员的"受限"= 权限点同租户管理员但数据范围收敛为"本部门及以下"（03 篇 §4.3），由服务端统一判定。

## 3. 页面结构与信息架构

### 3.1 模块地图（树状）

```

└─ 租户管理域（admin:*，本租户）

    └─ 用量与配额       存储水位/AI token(按部门、按用户)/通话并发峰值/文件流量
```

### 3.2 导航与显隐规则

1. 客户端主导航"管理"入口：`GET /api/v1/me/permissions`（03 篇 §7）返回的权限摘要含任一 `admin:*`/`platform:*` 权限点 → 显示。
2. 进入管理后台后：左侧导航按 §3.1 模块地图 × 用户权限点取交集渲染；页面内按钮级显隐同理。
3. 权限变更实时生效：收到 WS `perm.changed`（14 篇 §3.2）→ 重新拉取权限摘要 → 重算导航（不可用模块立即隐藏，进行中的操作在服务端被拒）。
4. Web 管理台同一规则，登录后首屏即拉取权限摘要。

## 4. 核心交互流程

### 4.1 敏感操作二次验证矩阵

二次验证三档：**A=口令重验**（重输口令换取 5 min 单用途操作票据，`X-Second-Auth` 头携带）；**B=MFA**（TOTP，若租户策略启用）；**C=双人审批**（第二管理员审批，审批人须持对应权限点且**不得为发起人**，24 h 未决自动过期）。

| 操作 | 验证档 | 说明 |
|---|---|---|
| **平台运营域（全部需要）** | | |
| 创建/修改租户 | A+B | |
| 停用租户 / 注销租户 | A+B+C | 注销延迟 72 h 执行（可撤销） |
| 调整租户套餐配额 | A | |
| 跨租户查询/读取任何数据 | A | 且**双审计**（§7.3） |
| 平台级 Agent 冻结开关 | A+C | `platform:agent:killswitch`（15 篇止损） |
| **租户管理域（高危需要）** | | |
| 批量导入执行（>500 人） | A | ≤500 人免重验（仍全量审计） |
| 禁用用户 / 解绑用户 MFA | A / A+C | 解绑 MFA 双人审批防账号接管 |
| 离职交接执行 | A | 租户策略可加 C |
| 角色权限变更（涉及任何 `admin:*` 授予） | A+C | 防自我提权 |
| 安全/合规策略变更 | A | 含收紧与放宽 |
| 应用发布 / 下架 | C | 发起=应用管理员，审批=租户管理员 |
| 审计导出 | A(+B 若启用) | 内容项导出另受 §7.2 限制 |
| 知识库敏感标记变更 / 空间删除 | A | |
| 其余常规写操作（部门/群/普通角色编辑等） | — | 仅常规审计 |

### 4.2 流程①：批量导入用户

步骤：

1. **下载模板**：`GET /api/v1/admin/users/import-template` → CSV（UTF-8 with BOM）。列：`工号,姓名,邮箱,手机,部门路径,角色名(可多个,分号分隔),直属上级工号`。
2. **上传 CSV**：`POST /api/v1/admin/users/import`（≤10 MB、≤5,000 行）→ 创建 `admin_task(type=user_import_preview)`，异步逐行校验。
3. **逐行校验**：工号/邮箱格式；部门路径存在性（`/研发/后端` 按物化路径匹配，03 篇 §3.1）；角色名存在性；行内重复。
4. **冲突预览**（三色）：🟢新增（工号不存在）/ 🔵更新（工号已存在，非空列覆盖）/ 🔴错误（不可执行，附行级原因）。
5. **确认执行**：勾选参与行（默认排除错误行）→ 按矩阵二次验证（>500 人需口令重验）→ `POST .../execute` → `admin_task(type=user_import_exec)`。
6. **结果报告**：任务完成推送 `admin.task.updated`；报告（成功/失败明细 CSV）落对象存储供下载，保留 7 天。

```

交互规则：

1. 权限点树按域分组（im/rtc/doc/file/kb/agent/admin/platform），支持父子联动勾选与**半选态**（父域显示 n/m）；权限点字典来自服务端注册表（03 篇 §4.1，`GET /api/v1/admin/perm-points`），前端不硬编码。
2. 数据范围四选一（03 篇 §4.3），仅作为该角色成员授权时的默认值。
3. 内置角色（03 篇 §4.2）整卡只读（🔒），提供"克隆为自定义"；被内置角色引用导致不可删的自定义角色给出引用计数提示。
4. 保存 diff 预览（新增/移除权限点高亮）→ 二次验证 → 落库 + `perm.changed` 推送受影响用户。
5. 变更历史经审计流水回溯（§5 admin_operation），角色详情页含"最近变更"只读列表。

### 4.4 流程③：应用发布流（生态应用与技能）

技术细节（清单 schema、签名链、客户端同步安装）以 **10 篇**为准；本篇定义管理台侧流程：

1. **上传清单**：应用管理员上传应用清单与签名包 → app-registry 校验签名与结构（失败即 8004）。
2. **安全审查清单勾选**（发布前强制）：权限声明范围 / 凭证方式（是否需服务端代持，10 篇 §7）/ 数据是否出边界 / 工具风险等级（09 篇分级）——逐项勾选留痕入 `admin_operation.params`。
3. **灰度范围选择**：按部门 / 按在线百分比 / 白名单用户，三者可组合；灰度命中客户端经 `app.updated` 推送拉取（14 篇 §3.2）。
4. **审批**：双人审批（§4.1 矩阵：发起=应用管理员，审批=租户管理员）。
5. **发布看板**：安装率 / 版本分布 / 灰度进度 / 错误上报（客户端签名校验失败数）；提供"暂停灰度 / 全量 / 回退版本 / 下架"操作（下架=二次验证，客户端收到撤销同步）。

```
发布看板（示意）
 应用「审批助手」v2.3.0   灰度 20% ▓▓░░░░░░░░  [暂停][提至50%][全量][回退v2.2]
 安装 3,210/4,001 在线端 · 失败 12（8004×3, 超时×9）· 审批: 王IT ✅ 2026-06-01 10:00
```

│ ├────────────┼──────────────┼──────────────────┼────────────┼────┼─────┤ │
│ │ 10:32:11   │ 张三(E1001)  │ doc.file.download│ doc:8821   │ ✔  │ 用户 │ │

│ └────────────┴──────────────┴──────────────────┴────────────┴────┴─────┘ │
│ 行展开：参数摘要 / IP / UA / actor=agent:{会话} ；trace_id 一键复制         │
└──────────────────────────────────────────────────────────────────────────┘
```

规则：

1. 过滤维度即上表六项 + trace_id 精确匹配；结果 ≤1,000 条同步返回，超出强制转导出。
2. **trace_id 跳转**：复制后可到平台监控的日志检索（16 篇 §6.2）定位全链路日志；租户侧无日志平台权限时仅展示 trace_id 供上报排障。
3. **导出为异步任务**：`admin_task(type=audit_export)`，完成后生成带**水印**文件（每行/每页眉含"导出人工号+姓名+时间+任务ID"）；文件 7 天过期；导出行为本身入审计。
4. 检索走 audit 服务（02 篇 §3），租户内默认只能检索本租户事件；平台运营跨租户检索走二次验证 + 双审计（§7.3）。

## 7. 边界与异常

### 7.1 管理员自助操作限流

- 敏感写操作（矩阵内）：10 次/min/操作人；审批发起 5 次/min。
- 异步任务：同类型 pending/running 并发 1/操作人（表约束）；租户并发导入任务 ≤3。
- 审计检索：60 次/min/操作人，导出 10 次/天/操作人（防拖库式遍历）。
- 超限返回 9003（14 篇），并计入安全告警指标（15 篇 §6）。

### 7.2 审计只读角色的导出限制

- 审计合规员导出**仅元数据**（时间/人/动作/资源/结果/trace_id），**不含内容项**（消息正文、文件名、检索片段等）。
- 含内容项导出需：租户策略显式开启 + 租户管理员双人审批 + 单次授权 24 h 有效；全程留痕。
- 导出文件强制水印（§4.5）；下载链接绑定操作人设备指纹、7 天过期。

### 7.3 平台运营跨租户操作双审计

- 任一跨租户读写产生**两份审计事件**：平台域事件（subject=平台运营，记录目标租户）+ 目标租户事件（本租户审计链内可见"由平台运营执行"标记），两侧哈希链各自收录（15 篇 §4.2）。
- 平台运营对租户数据的检索同样受 §4.1 矩阵（口令重验）与 §7.1 限流约束。

### 7.4 其它边界

| 场景 | 处理 |
|---|---|
| 执行中审批人离职/被禁用 | 工单自动过期回退 pending→expired，通知发起人重新发起 |
| 导入执行中服务重启 | admin_task 幂等续跑（按行 checkpoint）；不可恢复则标记 failed 可重试 |
| 仪表盘数据滞后 | 用量快照 T+1min 刷新，页面标注统计时点 |
| 管理服务故障 | 管理台降级只读（展示缓存快照）；应急操作（强制下线/停用）由运维走 16 篇预案通道，事后补录审计 |
| 部门树深度 | ≤10 级；循环父子关系服务端拒绝 |
| Web 管理台弱网 | 操作票据 5 min 过期即重验，不缓存口令 |
