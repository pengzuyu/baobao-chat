## 1. 分层总览

```
┌─────────────────────────── 接入层 ───────────────────────────┐
│  客户端(Tauri×3平台)   Web管理台(复用前端)   内部API调用方(预留) │
└───────────────────────────────────────────────────────────────┘
     │WSS(信令/推送/IM)   │REST+presigned   │WOPI/HTTPS   │RTP/SRTP(UDP)
┌─────────────────────────── 服务层 ───────────────────────────┐
│ gateway ──► auth │ org │ message │ file │ doc │ kb │          │
│            app-registry │ admin │ audit │ notify │ ai-gw     │
│ media-svc(mediasoup SFU, 独立节点)   OnlyOffice DS   coturn   │
└───────────────────────────────────────────────────────────────┘
┌─────────────────────────── 数据层 ───────────────────────────┐
│ PostgreSQL16(+pgvector/zhparser/按月分区)  Redis7  MinIO(S3)   │
│ 本地：客户端 SQLite(消息缓存/Agent会话)  系统钥匙串(凭据)        │
└───────────────────────────────────────────────────────────────┘
```

**部署形态**：上表服务层为**逻辑服务**。小规模部署时除 media/OnlyOffice 外编译为单进程（模块化单体，模块间 Go interface 调用）；规模增长后按伸缩需求拆分部署（见 §8 与 16 篇）。

## 2. 客户端架构（Tauri 进程模型）

```
┌────────────────────────── BaobaoWork 客户端进程树 ──────────────────────────┐
│                                                                             │
│  UI 进程（WebView: React/TS）                                               │
│   ├ 消息/通话/文档/知识库/管理后台 各视图（多窗口：主窗 + 通话浮窗/PiP）        │
│   └ 本地状态: Zustand + SQLite(经Rust命令异步读写)                           │
│         ▲ Tauri IPC（commands + events，双向）                              │
│  Rust 核心（Tauri 主进程）                                                   │
│   ├ 连接管理器: WSS 单连接(自动重连/心跳/游标同步) + REST 客户端               │
│   ├ 本地存储: SQLite(消息缓存/会话/传输记录/Agent会话镜像)                    │
│   ├ 凭据保管: 系统钥匙串(Keychain/DPAPI/libsecret) 存 refresh token           │
│   ├ 传输引擎: 分片上传/下载、断点续传、秒传指纹                               │
│   ├ 系统能力: 托盘/通知/屏幕捕获/自启动/自动更新                              │
│   ├ Agent 管理: sidecar 进程启停/健康监控/崩溃恢复/stdio JSONL 转发           │
│   └ OBO 令牌代理: 向 Agent Runtime 按需发放降权短时效 token(03篇§6)           │
│         ▲ stdio（JSONL 消息，LSP 风格）                                      │
│  Agent Runtime（独立 sidecar 进程，Rust）                                    │
│   ├ 会话管理/上下文引擎/工具注册表/权限门控/审计日志(JSONL追加)                │
│   └ LLM 流式调用 ──(用户token)──► ai-gateway ──► 模型                        │
└─────────────────────────────────────────────────────────────────────────────┘
```

设计要点：

| # | 要点 | 说明 |
|---|---|---|
| 1 | **单一 WSS 连接** | IM、通话信令、生态应用更新通知、强制下线等复用一条连接（14 篇），由 Rust 核心持有，UI 重载不断线 |
| 2 | **UI 与原生层薄耦合** | UI 只通过 IPC commands/events 与 Rust 通信；为"方案 B：Electron 迁移"保留可能（01 篇§2.2） |
| 3 | **Agent 进程隔离** | Runtime 是独立进程：崩溃不影响客户端；可被暂停/终止；版本可与主程序独立热更（10 篇） |
| 4 | **令牌不出设备原则** | 模型 Key 只在 ai-gateway；用户 refresh token 只在钥匙串与 Rust 内存；Agent 拿到的是**降权、短时效（≤15 min）、绑定 agent 会话的 OBO token**（03 篇§6） |
| 5 | **离线优先的 IM 缓存** | 消息先落本地 SQLite 再渲染，弱网可浏览历史、重发队列；上线后按 seq 游标增量同步（04 篇） |

## 3. 服务清单

| 服务 | 职责 | 关键依赖 | 伸缩性 |
|---|---|---|---|
| gateway | WSS 接入（认证、信封路由、推送扇出、在线状态）、REST 反向路由、**全局搜索聚合**（Cmd+K：联邦查询 message/doc/kb/org 四域 search API 并聚合排序，规则见 D01 §14-3/D03 §PIM-07） | auth、Redis | 无状态水平扩展（连接经 Redis pub/sub 路由） |
| auth | 登录/SSO(OIDC)/MFA、令牌签发与轮换、设备管理、OBO 令牌签发 | PG、Redis | 无状态 |
| org | 租户/组织树/用户/岗位、部门异动 | PG | 无状态 |
| message | 会话与消息、seq 分配、漫游、已读、撤回、全文检索 | PG、Redis、MinIO | 分区 + 读副本；检索可外移 |
| file | 分片上传/秒传/预签名、缩略图、配额、病毒扫描钩子 | MinIO、PG | 无状态 + worker |
| media | WebRTC SFU（mediasoup）：房间、转发、simulcast | 独立节点（UDP 端口段） | 按通话并发扩容 |
| doc | 文档中心（元数据/权限/版本）、WOPI 主机、预览转换 | PG、MinIO、OnlyOffice | 无状态 + 转换 worker |
| kb | 知识库空间/摄入管线/混合检索/重排、KB API（供 Agent） | PG(pgvector)、ai-gateway | 摄入 worker 独立队列 |
| ai-gateway | OpenAI 兼容模型代理、路由/计量/脱敏、嵌入与重排 | 模型上游 | 无状态 |
| app-registry | 生态应用清单/版本/灰度/签名、技能包发布与分发 | PG、MinIO | 无状态 |
| admin | 管理后台聚合 API（组织/角色/策略/用量） | 各域服务 | 无状态 |
| audit | 审计事件收集（哈希链）、检索、导出、告警 | PG、Redis Stream | 追加写为主 |
| notify | 系统通知中心、告警通道（邮件/webhook） | Redis、PG | 无状态 |

## 4. 关键链路时序（简要）

### 4.1 登录与同步

```
客户端 ─► auth: 登录(口令/SSO/MFA) ─► 返回 access(15m)+refresh(30d,设备绑定)
客户端 ─► gateway: WSS /connect (access token) ─► 在线注册(Redis)
客户端 ─► message: GET /sync?cursors={convId:seq,...} ─► 各会话增量消息+全局未读
客户端本地: SQLite 合并 → UI 渲染 → 更新游标
```

### 4.2 发消息（含弱网）

```
UI ─IPC→ Rust核心: 消息先落SQLite(state=sending) → WS msg.send(client_msg_id)
message-svc: 校验权限/敏感词策略 → 分配seq → 落库(按月分区) → 返回ack(seq,ts)
message-svc → Redis fanout → 各端 gateway 推送 msg.new
发送端收到ack: SQLite 更新 state=sent；失败→state=failed+重试按钮
```

### 4.3 文件上传（分片+秒传）

```
UI选文件 → Rust: 计算 sha256 → REST file: POST /uploads/check → 命中=秒传(返回file_id)
未命中 → 申请分片预签名URL(4MB/片) → 并行直传MinIO → POST /uploads/complete
file-svc: 校验分片完整 → 合并 → 生成缩略图(图片) → 落 file 表 → 发送文件消息
```

### 4.4 发起多人通话

```
主叫 UI → WS rtc.call.invite(conv, members, media)
message/media: 建房间 → 被叫端 gateway 推 rtc.ringing(含房间/主叫信息)
被叫接听 → 各端与 media-svc 交换 SDP/ICE(rtc.signal) → P2P(1v1)或SFU(多人)建立
挂断 → rtc.bye → 通话卡片落会话消息流 → media 回收房间
```

### 4.5 打开文档（WOPI）

```
UI点击文档卡片 → REST doc: POST /files/{id}/session → 返回 WOPI action URL+短期token
WebView iframe 打开 OnlyOffice 编辑器 → OnlyOffice ←WOPI→ doc-svc 读写 MinIO
doc-svc 每次请求校验: 用户token + 文档ACL → 允许则流式返回内容
保存: OnlyOffice 回调 → doc-svc 写新版本 → 参与者收到 doc.updated 推送
```

### 4.6 Agent 工具调用（含 OBO 与审计）

```
用户在Agent视图输入任务 → Runtime 组装上下文 → ai-gateway(用户token) 流式生成
模型返回工具调用(如 kb_query) → Runtime 权限门控(kb_query=低危自动放行)
Runtime →(OBO token, act=agent会话)→ kb-svc /api/v1/kb/query
kb-svc: 按用户权限过滤检索 → 返回带引用结果 → Runtime 回填上下文继续循环
审计: kb-svc 写 audit(subject=用户, actor=agent会话); Runtime 本地JSONL记录工具调用
```

### 4.7 生态应用同步

```
管理员发布应用新版本(签名) → app-registry 落库+生成版本清单
在线客户端收到 WS 推送 app.updated → Rust核心: 校验签名/灰度命中
→ 增量下载(MinIO) → 原子安装到用户目录 → 通知 Agent Runtime 热加载工具/技能
```

## 5. 数据流与租户隔离

| 关注点 | 方案 |
|---|---|
| 隔离单元 | 所有业务表带 `tenant_id`；PG 启用 RLS，服务端连接池按租户设置会话变量；审计表同 |
| 对象隔离 | MinIO 单桶多租户前缀 `t/{tenant_id}/...`（小规模）或桶级隔离（高合规租户，部署选项） |
| 缓存隔离 | Redis key 一律 `t:{tenant_id}:...` 前缀 |
| 跨租户 | 仅平台运营角色可跨租户（显式 `platform:` 权限点），且全部审计 |
| Agent 数据 | 会话/上下文在用户本地；服务端只存：审计事件、（可选）会话云端备份（租户策略开关，默认关） |

## 6. 横切关注点

| 关注点 | 方案 |
|---|---|
| 可观测性 | OTel 全链路（trace_id 贯穿 WS→服务→MinIO）；指标/日志/追踪规范见 16 篇 |
| 配置 | 服务配置集中（etcd/consul 或 k8s config）；租户级策略（保留期、配额、水印）入库由 admin 下发 |
| 时间 | 全部服务端 UTC 存储，展示按本地；消息排序以服务端 `seq+ts` 为准 |
| ID | 雪花 ID（趋势递增，字符串透出）；会话内仍用单调 `seq` 保证有序 |
| 国际化 | 前端 i18n 资源随客户端分发；服务端错误消息带 code，文案端侧渲染 |
| 灰度 | 客户端按更新通道（stable/beta）；服务端特性开关（feature flags，租户级） |

## 7. 失败域与降级

| 故障 | 影响 | 降级策略 |
|---|---|---|
| WSS 断连 | 消息/信令断 | 指数退避重连；本地队列重发；重连后游标增量同步补洞 |
| media 节点故障 | 进行中通话掉线 | 客户端 3s 内自动重拨到备用节点；1v1 自动转 P2P |
| OnlyOffice 故障 | 无法编辑 | 降级为只读 PDF 预览（转换缓存）；恢复后提示重新编辑 |
| ai-gateway/模型故障 | Agent 不可用 | 明确错误提示；IM 等基础功能不受影响（Agent 独立进程） |
| MinIO 故障 | 文件不可传 | 消息文本不受影响；传输管理器挂起自动重试 |
| PG 主库故障 | 写入中断 | 同步从库 + 定期切换演练（16 篇）；读流量走副本 |

## 8. 部署拓扑（摘要，详见 16 篇）

```
小规模(≤2k用户): 单VM docker-compose
  [app单进程×2(负载) | pg | redis | minio | onlyoffice | media | coturn | 更新源]

中大规模(≤20k用户/租户): K8s
  [gateway×N(HPA按连接数) | app模块按域拆分 | media×N(UDP hostNetwork) |
   onlyoffice×N | pg主从+读副本 | redis哨兵 | minio分布式 | 更新源CDN内网化]
```
