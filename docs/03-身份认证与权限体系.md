## 1. 功能概述

身份与权限体系是所有模块的地基，回答四个问题：

1. **你是谁**（认证）：口令/SSO/MFA/设备/令牌生命周期。
2. **你在哪个组织**（多租户与组织树）。
3. **你能做什么**（RBAC 权限点 + 数据范围 + 资源级 ACL 三层过滤）。
4. **"Agent 替你做事"时算谁**（OBO：一切以用户身份，动作可归因）。

权限判定总顺序（所有服务端统一中间件执行）：

```
认证(token有效?) → 租户(所属/状态) → 会话(是否被强制下线)
 → RBAC(角色含权限点?) → 数据范围(部门维度边界)
 → 资源ACL(对该具体资源: owner/组/授权)  → 放行 + 审计(按策略)
```

## 2. 认证设计

### 2.1 登录方式

| 方式 | 说明 | 默认 |
|---|---|---|
| 账号口令 | 工号/邮箱/手机号 + 口令；argon2id 存储；防爆破（失败锁定+验证码） | 启用 |
| 企业 SSO（OIDC） | 对接公司 IdP（Keycloak/钉钉扫码/企业微信扫码等，OIDC 兼容）；首次登录自动建户（映射租户规则由管理员配置） | 可选，租户级开关 |
| LDAP / AD 同步 | 定期同步组织与用户（不用于直连认证，只做账源） | 可选 |
| MFA | TOTP（RFC 6238）；租户策略：关闭/可选/强制管理员强制 | 可选 |
| **浏览器会话免密（一键登录）** | 桌面端拉起默认浏览器，检测到门户/SSO 已登录会话后**一次点击确认**即完成桌面端登录（§2.1.1） | 启用（默认推荐入口） |

#### 2.1.1 浏览器会话免密登录（一键登录）

```
桌面端 ──POST /auth/browser-login/request──► auth ──► {login_req_id, user_code(6位), 300s}
桌面端 ──sys_open_url──► 默认浏览器 /login/desktop?req=...
浏览器: 无会话→先常规登录; 有会话→确认页(设备信息+6位码核对) →「确认登录」
回传: 深链 bbw://auth/callback?code=... (首选) / 轮询 poll (3s 兜底)
桌面端 ──POST /auth/exchange (code, did绑定)──► access + refresh → 进入主窗
```

安全要点：login_req_id 一次性 5 min；**6 位确认码双端一致核对**（防伪造桌面端发起的钓鱼）；code 一次性 60 s 且绑定发起设备；高安全租户可在浏览器确认时要求重输口令；「7 天内该设备免确认」仅租户可选策略（默认关）；限流（单设备 1 min ≤5 次发起）；审计 `auth.browser_login`。错误码：1010 请求过期/已使用 · 1011 已拒绝 · 1012 确认码不匹配 · 1013 code 无效。详细交互与页面见 detail/D12。

### 2.2 令牌模型

| 令牌 | 有效期 | 存储 | 说明 |
|---|---|---|---|
| Access Token（JWT, ES256） | 15 min | 仅内存（Rust 核心），**不落盘** | 载荷：`sub`(用户) `tenant` `scope`(权限摘要) `did`(设备) `jti` |
| Refresh Token | 30 天，滑动过期 | 系统钥匙串（Keychain/DPAPI/libsecret） | 一次性轮换（每次刷新作废旧值）；设备绑定（did + 设备指纹） |
| OBO Token（Agent 用） | ≤ 15 min | 仅 Agent Runtime 内存 | 见 §6，access token 的受限派生（含 `act` 声明） |

- 刷新流程：静默刷新（到期前 2 min）；轮换失败（疑似被盗/重放）→ 全设备下线 + 通知用户。
- **多端在线**：每设备独立凭据；管理后台/用户可查看在线设备并强制下线（`force.logout` 推送，14 篇）。
- 登出：吊销 refresh + 广播下线；Agent Runtime 收到宿主通知后立即销毁 OBO token 并暂停会话。

### 2.3 登录交互（客户端）

```
启动 → 读取钥匙串
 ├ 无凭据 → 登录页: [浏览器一键登录(默认推荐)] / [SSO(若启用)] / [账号+口令] → MFA(若策略) → 进入
 └ 有凭据 → 静默刷新
      ├ 成功 → 直达主界面（同步会话/未读）
      └ 失败(refresh过期/吊销) → 登录页（保留工号预填）
```

细节：密码错误 5 次锁定 10 min（提示剩余次数）；登录页展示租户名与 Logo（租户域名/服务器地址映射）；支持"记住服务器地址"多环境切换（测试/生产）。

## 3. 多租户与组织模型

### 3.1 实体关系

```
tenant(租户) 1 ── n dept(部门,树)          dept 1 ── n user(多对多,含主部门)
tenant 1 ── n user                        user 1 ── n role(经 user_role,含范围)
tenant 1 ── n role(角色模板可复制)          user 1 ── n device
```

| 实体 | 关键字段 | 说明 |
|---|---|---|
| tenant | id, name, status, plan(配额), settings(策略JSON) | 平台运营管理 |
| dept | id, tenant_id, parent_id, path(物化路径), sort | 树形，path 如 `/1/7/23/` 便于"本部门及以下"判定 |
| user | id, tenant_id, employee_no, display_name, status, joined_at | 唯一索引 (tenant_id, employee_no) |
| user_dept | user_id, dept_id, is_primary | 多部门支持 |
| role | id, tenant_id, name, permissions[](权限点), is_builtin | 内置角色不可删 |
| user_role | user_id, role_id, scope(数据范围) | 同角色可不同范围 |

### 3.2 隔离实现

- PG RLS：`current_setting('app.tenant')` 过滤；服务端连接池在请求上下文设置租户。
- 高合规租户（部署选项）：独立数据库/独立 schema（管理后台注册租户时选择隔离级别）。
- 跨租户仅平台运营（`platform:tenant:manage`），显式二次确认 + 审计。

## 4. RBAC：角色、权限点与数据范围

### 4.1 权限点命名

格式 `域:动作:对象`（可带修饰符）。全集由各功能篇定义并在管理后台"权限点字典"注册，本篇定义框架。示例：

| 域 | 示例权限点 |
|---|---|
| im | `im:message:send` `im:group:create` `im:group:manage` `im:message:recall_any`(管理员撤回他人) |
| rtc | `rtc:call:start` `rtc:meeting:schedule` |
| doc | `doc:file:create` `doc:file:edit` `doc:share:create` `doc:template:manage` |
| file | `file:upload` `file:share:create` `file:manage_all`(管理员) |
| kb | `kb:space:create` `kb:space:admin` `kb:doc:contribute` `kb:query:use` |
| agent | `agent:session:use` `agent:tool:run_command`(执行脚本) `agent:mode:full_auto` `agent:app:install`(可选) |
| bot | `bot:manage`(机器人管理，默认应用管理员) · `bot:install`(拉机器人入会话，群主默认) —— 20 篇 |
| meeting / mail | `rtc:meeting:schedule`(已列) · `meeting:minutes:manage` · `admin:meeting:policy` —— 21 篇；`mail:use`(默认成员) · `mail:agent_tool`(默认关) · `admin:mail:govern` —— 22 篇 |
| admin | `admin:org:manage` `admin:user:manage` `admin:role:assign` `admin:app:publish` `admin:audit:read` `admin:policy:manage` |
| platform | `platform:tenant:manage` `platform:quota:manage` |

### 4.2 内置角色（租户级）

| 角色 | 权限概要 | 数据范围默认 |
|---|---|---|
| 普通成员 | im/rtc/doc/file 基础 + `kb:query:use` + `agent:session:use`（不含 run_command 时 Agent 只能读写不能执行，见 09 篇） | 本人 |
| 部门管理员 | + 本部门用户/群/部门 KB 管理 | 本部门及以下 |
| 租户管理员 | admin:* 全集（除 platform:*） | 全租户 |
| 应用管理员 | `admin:app:publish` + 应用域管理 | 全租户（仅应用域） |
| 审计合规员 | `admin:audit:read` + 导出，只读 | 全租户（仅审计域） |
| 平台运营 | platform:*（跨租户） | 跨租户 |

支持**自定义角色**：权限点树勾选 + 数据范围选择（复用 12 篇角色编辑器）。

### 4.3 数据范围（Data Scope）

| 范围 | 判定 |
|---|---|
| 本人 | resource.owner = user 或本人会话 |
| 本部门 | 所属部门（任一）直接成员 |
| 本部门及以下 | dept.path 前缀匹配 |
| 全租户 | tenant 内（受资源 ACL 仍过滤） |
| 跨租户 | 仅 platform 角色 |

### 4.4 资源级 ACL（第三层）

适用对象：文档、知识库空间/节点、群、文件分享链接。模型统一：

```
resource_acl(resource_type, resource_id, grant_type, grant_target, perm)
  grant_type: user | dept | role | tenant(租户内公开)
  perm:       viewer | commenter | editor | owner
```

- 有效权限 = 逐层取最大（显式授权 > 继承 > 默认）；"拒绝"仅显式黑名单场景（知识库敏感节点，11 篇）。
- 继承链：知识库空间 → 目录 → 文档（可打破继承）；文档中心以"所在文件夹"为继承链。
- 判定结果短时缓存（Redis，`t:{tid}:acl:{user}:{res}`，TTL 60 s；授权变更时主动失效）。

### 4.5 部门异动与权限收敛

用户调岗 → user_dept 变更 → 触发：部门 KB 空间权限重算、部门群自动进出（策略可选）、缓存失效、审计事件 `org.user_transfer`。离职能量：status=disabled → 全端 `force.logout`、令牌吊销、Agent 本地会话锁定（宿主收到事件后冻结 Runtime，需要重新激活）。

## 5. Agent 生态下的两个特殊主体

1. **Agent Runtime（本地进程）**：不是独立账号，是用户会话的"手臂"（§6 OBO）。
2. **生态应用（Ecosystem App）**：不是账号，是"工具声明 + 服务端连接器"。应用代表用户调用目标系统时同样走 OBO；仅当目标系统只接受服务间凭证（如固定 API Key）时，由 app-registry **服务端代持**该凭证并在服务端代为转发（客户端与 Agent 永远接触不到该凭证），且每次调用仍携带用户上下文供对方系统审计。详见 10 篇 §7。

## 6. Agent 用户代理（OBO）机制 ★核心

### 6.1 目标与原则

| # | 原则 | 落地 |
|---|---|---|
| 1 | Agent 永远没有独立身份 | 一切内部 API 调用携带**用户**的 OBO token |
| 2 | 权限不超过用户本人 | OBO token 的 scope 是用户权限的**子集**（按任务需要收敛） |
| 3 | 动作可归因 | token 含 `act`（agent 会话 ID）；服务端审计双记录 subject=user / actor=agent |
| 4 | 生命周期跟随用户会话 | 用户下线/令牌吊销 → OBO 立即失效（短时效 + 在线校验） |
| 5 | 凭证不落盘 | OBO token 仅存 Runtime 内存，到期由宿主按需续发 |

### 6.2 令牌签发流程

```
用户创建/恢复 Agent 会话
 → 宿主(Rust核心)向 auth: POST /obo/token
    请求: 用户access token + agent_session_id + 申请的scope子集
    (首次或涉及高危scope时: UI显式提示"Agent 将以你的身份访问X"，用户确认)
 → auth 校验: 用户token有效 & 用户本身具备所申请scope
    (申请的权限 > 用户权限 → 签发失败，不静默降级)
 → 签发 OBO JWT: {sub: 用户, tenant, scope: 子集, act:{agent_session}, exp≤15min}
 → Runtime 内存持有；到期前由宿主静默续签
```

### 6.3 服务端校验与审计

- 各服务中间件识别 `act` 声明：按 `sub`（用户）鉴权，**不因是 Agent 而放宽或收紧**（除了可配置的额外限流：Agent 调用速率上限，防失控循环）。
- 审计事件统一字段：`subject`(用户) `actor`("agent:"+agent_session_id) `action` `resource` `result` `trace_id`。
- 高敏动作（删文档、发消息到群、生态应用写操作）在租户策略开启时：即使权限允许，Agent 触发也要求"预授权清单"（用户在会话中已批准的具体动作），未列其中则拒绝并提示 Agent 向用户申请（09 篇权限门控联动）。

### 6.4 撤销与失效

| 触发 | 动作 |
|---|---|
| OBO 到期 | Runtime 请求续签；宿主检查会话与权限仍有效 |
| 用户登出/被下线/禁用 | 宿主销毁 OBO、暂停 Runtime；auth 将 jti 加入吊销名单（Redis） |
| 权限被收回（如调岗） | 续签时重算 scope，收敛或拒绝 |
| 管理员吊销 Agent 会话 | `agent.revoked` 推送 → 宿主终止该会话（管理侧应急能力） |

### 6.5 反模式（禁止清单）

- ❌ 给 Agent 配置服务账号/超管账号直连数据库或内部系统。
- ❌ 把用户主 access token 长期交给 Runtime 且不设 act 标记。
- ❌ 生态应用在客户端内置固定 API Key。
- ❌ 用"Agent 权限"做资源授权（资源 ACL 只认用户/组/角色）。

## 7. 接口设计（REST，摘要）

| API | 说明 |
|---|---|
| POST /api/v1/auth/login | 口令登录 → 两种 token + 设备注册 |
| POST /api/v1/auth/sso/{provider} | OIDC 回调交换 |
| POST /api/v1/auth/refresh | 刷新令牌（轮换） |
| POST /api/v1/auth/mfa/verify | TOTP 校验 |
| POST /api/v1/auth/logout / /api/v1/auth/logout-all | 登出/全端下线 |
| GET /api/v1/auth/devices / DELETE .../devices/{did} | 设备列表与下线 |
| POST /api/v1/auth/obo/token | OBO 签发与续签（§6.2） |
| GET /api/v1/org/tree / POST /api/v1/org/depts ... | 组织管理（12 篇） |

WS 事件：`force.logout`、`perm.changed`（权限变更，端侧刷新 UI 显隐）、`agent.revoked`。

错误码段（14 篇）：1xxx 认证（1001 口令错误、1002 MFA 需要、1003 token 过期、1004 被吊销、1005 设备锁定、1006 OBO scope 超出、1007 登录锁定、1008/1009 MFA 错误/票据过期、1010–1013 浏览器一键登录…）、2xxx 组织/权限（2001 无权限点、2002 数据范围不足、2003 资源 ACL 拒绝、2004 租户禁用、2005 用户禁用、2006/2007 部门删除/移动非法…）。

## 9. 边界与异常

| 场景 | 处理 |
|---|---|
| SSO 与本地口令并存 | 租户策略二选一或并存；并存时 SSO 用户无本地口令 |
| 用户被移出部门但其是某文档 owner | owner 权限不随部门变；数据范围类权限收敛 |
| OBO 续签时用户权限已变化 | 按"续签即重算"收敛；进行中调用以调用时刻校验为准 |
| 多 Agent 会话并发 | 每会话独立 OBO（act 不同），审计可区分 |
| 权限缓存与实际不一致窗口 | ≤60 s；高危操作绕过缓存实时判定 |

## 10. 依赖与开放问题

- 依赖：14 篇（事件与错误码）、09 篇（权限门控使用 OBO scope）、10 篇（应用凭证代持）、12 篇（角色编辑器 UI）。
- 开放：① SSO 提供方清单待客户环境确认；② 审计合规员是否需要"Break-glass"特殊通道（记录但跳过部分限制）；③ 会话内"预授权清单"的粒度（动作级 vs 资源级）需在 Agent 联调时验证易用性。
