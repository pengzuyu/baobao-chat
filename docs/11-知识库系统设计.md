## 1. 功能概述

知识库域（kb-svc）把企业分散的文档沉淀为**可检索、可引用、权限正确**的知识资产，服务两类消费者：人（检索页/详情页）与 Agent（`kb_query` 工具，OBO 鉴权）。核心链路：

```
内容来源(五种) → 摄入管线(解析→清洗→分块→嵌入→索引) → 双索引(pgvector HNSW + PG FTS)
                                                            │
检索(人/Agent) → 混合检索(BM25+向量, RRF) → 权限前置过滤 → 重排(bge-reranker) → 引用溯源
```

技术基线（01 篇 §5.2/5.5，冻结）：PG16 + pgvector(HNSW) + zhparser；bge-m3（嵌入）与 bge-reranker-base（重排）经 ai-gateway 统一暴露；对象与源文件在 MinIO。规模假设：单租户活跃文档 ≤ 500 万、向量 ≤ 千万级（超出再评估 OpenSearch/Milvus，01 篇 §7）。

## 2. 三级空间模型

### 2.1 空间类型对比

| 维度 | 个人知识库 | 部门知识库 | 公司知识库 |
|---|---|---|---|
| space_type | personal | dept | company |
| 数量 | 每人 1 个，首次使用自动开通，不可删除 | 每部门可建多个（默认随部门创建 1 个） | 每租户可建多个 |
| 治理者 | 本人 | 部门管理员 + 被委派治理员 | 租户治理员（应用管理员/知识治理岗） |
| 默认授权 | 仅本人；他人须**显式授权**（user 粒度） | 默认按**部门树**授权（本部门及以下 reader，可配置为 contributor），管理员可调 | 租户内全员 reader，写入收敛到贡献者 |
| 谁可创建 | 自动 | `kb:space:create` + 部门管理员 | `kb:space:create` + 租户管理员 |
| 典型内容 | 个人笔记、Agent 会话结论 | 部门规范、项目文档、会议纪要 | 公司制度、产品手册、FAQ |
| 配额 | 个人配额（租户策略） | 部门配额 | 公司配额 |

### 2.2 空间 → 目录 → 文档 三级结构

- `kb_space`（空间）→ `kb_node`（目录/文档树，node_type=dir|doc）→ 文档本体（kb_doc_meta 引用源文件，不复制内容，MinIO 引用计数共享）。
- 目录层数上限 10 层；文档挂目录，节点 path 物化路径（同 03 篇 dept.path 风格）。

### 2.3 权限继承与打破（对齐 03 篇 §4.4）

```
kb_space ──继承──► dir(kb_node) ──继承──► doc(kb_node)
                     │可"打破继承"(inherit_acl=false)：该节点起另立 ACL 起点
有效权限 = 逐层取最大(显式授权 > 继承 > 空间默认)，敏感节点可显式"拒绝"(deny)压过授权 ★仅 KB 域支持
```

- 存储：统一写 `resource_acl`（resource_type = kb_space / kb_node）；`kb_acl` 为域内投影视图（同事务双写），并冗余 `role`（空间治理角色）。
- 判定复用 03 篇三层（RBAC `kb:*` → 数据范围 → resource_acl），结果缓存 `t:{tid}:acl:{user}:{res}` TTL 60s，变更主动失效。
- 部门异动（03 篇 §4.5）：user_dept 变更 → 部门空间权限重算 + 受影响 chunk 的 ACL 标签刷新（§4.4）。

### 2.4 空间治理角色

治理角色仅在 kb_space 资源上授予，是 resource_acl 四档 perm 的域内语义包装（折叠映射，不在 03 篇全局枚举中新增值）：

| 治理角色 | 折叠为 resource_acl.perm | 域内能力 |
|---|---|---|
| owner（治理者） | owner | 空间全治理：成员/目录/配额/归档策略/删除空间/转让（kb_space.owner_id 唯一标识） |
| admin（管理员） | owner + role=admin 标记 | 管理成员与目录、敏感标记、空间审计查看；**不可**删除/转让空间 |
| contributor（贡献者） | editor | 上传/编辑/移动授权范围内文档 |
| reader（读者） | viewer | 检索与阅读（+评论者 commenter 档保留给 KB 评论场景） |

## 4. 核心流程

### 4.1 内容来源（五种）

| # | 来源 | 入口 | 说明 |
|---|---|---|---|
| ① | 手动上传 | 空间浏览页 [+上传] | doc/docx/pdf/md/xlsx/ppt/图片（图片 OCR 预留，阶段四）；走 07 篇分片上传得 file_id 后建 kb_doc_meta |
| ② | IM 收藏一键入库 | 消息右键/收藏夹 | 消息文本（含 Agent 卡片结论）或聊天文件 → 指定空间/目录；source_ref=msg_id/file_id |
| ③ | 文档中心同步 | 文档卡片/KB 页 [从文档中心同步] | 勾选 doc_file 进 KB；KB 侧只存引用，doc_file 更新（doc.updated）触发按策略重摄入 |
| ④ | Agent 产出保存 | Agent 会话结论/生成文档 [保存到知识库] | **经用户显式确认**（09 篇权限门控），OBO 写入，subject=user/actor=agent 双审计 |
| ⑤ | 定时抓取内部系统 | 管理后台（阶段四预留） | 连接器抓 Confluence/禅道等；本期仅预留 source_type=crawl 与 `kb:crawl:manage` 权限点 |

### 4.2 摄入管线（状态机）

```
五种来源 ──创建 kb_doc_meta + kb_ingest_job──►
                                             ┌──────────────────────────────────────────────┐
                                             │ pending ─► parsing ─► chunking ─► embedding ─► ready │
                                             │   (队列)   LibreOffice  结构感知   bge-m3        双索引 │
                                             │            headless   分块+清洗   ai-gateway    就绪  │
                                             └──────────────────────────────────────────────┘
                                                   ▲ 任一阶段失败 → failed(stage, error, attempt)
                                                   │   可重试：从失败阶段续跑（阶段幂等）
                                                   └ 删除/更新走 purging/re-ingest 分支
各阶段职责：
  parsing   : LibreOffice headless → 文本层 + 结构感知（标题层级/表格/列表/页码锚点）
  清洗(内含) : 去页眉页脚/水印噪声/重复空行/控制字符；敏感词命中打标（供治理复核）
  chunking  : 结构感知分块——标题层级优先切分；目标 512 token、重叠 64；表格整块
              （超长表按行组切分并保留表头）；记录 heading_path 供引用锚点
  embedding : bge-m3（1024 维）批量经 ai-gateway；失败指数退避重试（§7.2）
  indexing  : kb_chunk 落库，embedding(vector) + fts(tsvector, zhparser) 双列双索引
```

| 状态 | 含义 | 触发 |
|---|---|---|
| pending | 已登记待处理 | 来源创建 |
| parsing / chunking / embedding | 管线进行中 | worker 消费 |
| ready | 双索引就绪，可被检索命中 | 索引提交 |
| failed | 失败（记录 stage+error+attempt） | 任一阶段异常；可重试（自动 3 次，之后人工"重新摄入"） |
| purging | 删除清除中 | 删除请求 |

**增量更新**：来源内容 sha256 变化（doc_file 新版本/重传）→ 新一轮管线，完成后**同事务**替换（先删旧 chunk 向量+FTS 再插新，检索无中间态）；doc_meta.version 递增。
**删除（GDPR 式）**：删除节点 = purging → **物理清除** kb_chunk（向量+FTS）、kb_doc_meta、kb_node；"文档中心同步"类仅清 KB 侧引用不动源文件；用户注销/数据主体请求 → 按 user 维度级联清除其个人空间（12/15 篇流程）。

### 4.3 检索设计（核心）

```
query(用户 / Agent kb_query, OBO)
  │ ①查询嵌入 bge-m3（经 ai-gateway）
  ├──────────► A 路: pgvector HNSW ANN, topN(默认50) ─────────┐
  │                            (WHERE space/node ACL 前置注入)  │
  ├──────────► B 路: PG FTS BM25 风格打分(zhparser + pg_trgm    ├─► RRF 融合去重
  │              兜底中英混合/错拼), topN ─────────────────────┘        │
  ▼                                                                    │
候选 ≤ 50 ──► ②bge-reranker-base 重排(ai-gateway, query×chunk) ──► top10
  ▼
引用溯源: chunk 原文 + <mark>高亮</mark> + 跳转锚点(node_path + heading_path + chunk seq)
降级: reranker 故障→跳过②(RRF 序直出) │ 向量路故障→纯 B 路(FTS) │ 全故障→9005/7002 提示
```

**权限前置过滤实现（P0 安全不变量）**：

1. 摄入时每个 kb_chunk 冗余 `acl_tags jsonb` 快照：`{space_id, visibility(personal|dept|company), dept_ids[], user_ids[], sensitive}`（user_ids=显式授权用户，含个人空间被授权者）。
2. 查询时以**当前用户身份**（部门树展开 + 显式授权 + 空间可见性）实时生成"可见 doc_id/node_id 集合"，**注入 A/B 两路检索 SQL 的 WHERE**（`node_id = ANY($可见集)`）——过滤发生在 ANN/FTS 扫描阶段，**绝不做检索后过滤**，避免无权限内容参与召回挤占名额（漏检/泄露两头都不出）。
3. 双保险：top50 候选送重排前再做一次**实时 ACL 复核**（03 篇判定接口，绕过 60s 缓存），拦截标签滞后导致的越权命中；标签刷新窗口见 §4.4。
4. 每次查询落 `kb_query_log`（谁、经哪个 Agent、查了什么、命中哪些 doc）。

**引用溯源**：响应携带 `{doc_id, node_path, heading_path, chunk_seq, snippet, highlight_range}`；客户端据此跳转原文档锚点；Agent 答案引用 KB 内容时强制附引用清单（08 篇约定）。

### 4.4 权限变更与 ACL 标签刷新

| 变更 | 生效路径 | 窗口 |
|---|---|---|
| 收紧（撤销/移出部门/敏感标记） | ACL 缓存主动失效（即时）+ chunk 标签异步刷新 + §4.3-3 实时复核兜底 | 越权风险 ≈ 0（复核兜底） |
| 放宽（新授权/换部门获得权限） | 标签异步重算（按 space/node 批量 UPDATE，Redis Stream 任务） | ≤ 5min 内生效（期间新权限用户暂不可见，可接受） |

窗口说明写入用户文档：权限放宽后最长 5 分钟内可检索到新授权内容；收紧立即生效。

### 4.5 空间治理

| 治理项 | 设计 |
|---|---|
| 配额 | kb_space.quota_bytes；上传/同步前预检（7012→7004）；个人配额默认 5GB、部门/公司租户策略定 |

| kb_doc_meta | id, tenant_id, node_id, space_id, source_type(upload/im/doc_sync/agent/crawl), source_ref(file_id/msg_id/doc_file_id/agent_session_id), source_sha256, doc_format, page_count, status(管线状态机镜像), version(摄入代次), sensitive(bool), last_error, updated_at | 源引用与摄入状态 |
| kb_chunk | id, tenant_id, doc_meta_id, node_id, space_id, seq, heading_path, content, token_count, embedding vector(1024), fts tsvector, acl_tags jsonb, created_at | 向量+FTS 双列+ACL 标签；HNSW(embedding) 与 GIN(fts) 双索引；按 tenant_id+space_id 分区预留 |
| kb_acl | id, tenant_id, resource(space/node), space_id, node_id, grant_type, grant_target, perm(viewer/commenter/editor/owner), role(admin 标记，可空), granted_by, expires_at, created_at | resource_acl 域内视图 |
| kb_ingest_job | id, tenant_id, space_id, doc_meta_id, source_type, stage(pending/parsing/chunking/embedding/ready/failed/purging), attempt, last_error, priority, created_at, updated_at | 摄入任务（Redis Stream 消费 + 表持久化） |
| kb_query_log | id, tenant_id, user_id, actor(agent_session 或 null), query_text, filters jsonb, hit_doc_ids[], hit_count, latency_ms, created_at | 按月分区；审计与"被引用位置"来源 |

MinIO：KB 不复制对象，引用源（file/doc 域对象键）；抓取类(⑤)源文件存 `t/{tid}/kb/crawl/{job}/{name}`。

## 7. 边界 / 异常 / 降级

| # | 场景 | 处理 |
|---|---|---|
| 1 | 超大文档（> 2000 页 / 解析产物 > 32MB 文本） | 拒入 7006，提示拆分；已入的按目录/章节拆为多 doc_meta 分卷（保留来源引用） |
| 2 | 嵌入/重排服务故障（ai-gateway 不可用） | 摄入：队列**暂停不丢**（job 停留 failed-pending，退避重试，7008 透出状态）；检索：reranker 跳过→RRF 序直出；向量嵌入失败→纯 FTS；双失败→9005 明确报错 |
| 3 | 权限变更后标签滞后 | §4.4：收紧即时（缓存失效+实时复核），放宽 ≤5min；写入产品文案 |
| 4 | 中英混合/错拼检索 | zhparser 中文分词 + pg_trgm 兜底（英文词干/编辑距离），FTS 查询表达式组合 `zhparser_query || similarity()`；嵌入路天然跨语言（bge-m3） |
| 5 | LibreOffice 解析崩溃（损坏文件/宏病毒） | worker 沙箱隔离 + 超时杀死（120s/文档）→ failed 可重试；连续崩溃标记源文件可疑并告警 |
| 6 | 检索质量劣化（无结果） | 前端提示改写关键词/放宽筛选；记录 kb_query_log 供相关性评估（离线） |
| 7 | kb 文档与源（doc_file/IM）不一致 | 同步策略默认"手动重摄入"；doc.updated 推送后列表标"源已更新"；自动跟随为空间级可选策略 |
| 8 | 个人空间主人离职 | 空间冻结 30 天（只读）待管理员处置：移交治理者或按 GDPR 清除（12 篇流程） |

## 9. 开放问题

1. OCR 引擎选型（PaddleOCR 自托管 vs 云 API 经网关）与图片/扫描件入库时点（阶段四）。
2. FTS 打分采用 ts_rank 近似 BM25；若相关性不达标，是否引入 OpenSearch（>500 万活跃文档或相关性验收失败时触发，01 篇 §7）。
3. kb_chunk 分区与 HNSW 索引内存随规模增长：分区键选 tenant+space 还是仅 tenant？与 13/16 篇联测定。
4. 多模态预留：图片/图表是否进独立多模态嵌入索引（bge-m3 图文能力评估）。
5. 重排延迟预算：top50 重排 P95 目标 300ms，超预算降级阈值待压测。
6. 定时抓取连接器（⑤）的清单、凭证托管方式（复用 10 篇 app-registry 服务端代持）。
