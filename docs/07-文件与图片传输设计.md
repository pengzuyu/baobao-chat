## 1. 功能概述

文件域（file-svc + 客户端 Rust 传输引擎）为 IM 文件消息、文档服务（06 篇）、知识库摄入（11 篇）、头像/技能包分发（10 篇）提供统一的对象存储能力。核心链路沿用 14 篇 §6（check → 分片预签名直传 → complete → download-ticket），本篇做详设。

| 设计基线（00/02 篇） | 值 |
|---|---|
| 单文件上限 | 默认 **10 GB**（租户可配 100MB–10GB） |
| 分片 | 4 MB/片，客户端并行 3 |
| 传输路径 | 预签名 URL 直传/直下 MinIO，**大流量不经应用服务转发**（02 篇） |
| 去重 | sha256 **租户内**秒传（跨租户绝不去重，隔离红线） |
| 缩略图 | webp 240 / 720 / 原图三档 |
| 病毒扫描 | ClamAV 可选集成，打开前扫描钩子 |
| 存储 | MinIO 单桶多租户前缀 `t/{tenant_id}/...`（高合规租户桶级隔离为部署选项，02 篇 §5） |

### 1.1 非目标

在线预览 Office（06 篇负责）、网盘式个人空间/目录树（阶段四评估）、断点续传跨设备接力（传输状态仅本端）、>10GB 文件。

## 4. 核心交互流程

### 4.1 上传协议详设（14 篇 §6 展开）

```
本地预检 → check(秒传?) ─未命中→ 申请分片预签名(首批) → 并行直传 → 续批…→
 complete(校验合并/整体sha256) → 后处理(缩略图/病毒扫描) → 建file实例 → 发消息
```

| 步骤 | 说明 |
|---|---|
| ① 本地预检 | Rust 引擎校验：大小 ≤ 租户 max_file_size（策略本地缓存，超 4009）、扩展名/MIME 黑白名单（超 4002）、磁盘可写；不合规直接进失败列表，不发起网络请求 |
| ② 指纹计算 | 全量 sha256（分块并行读，10GB 约 20–60s，进度回传 UI；期间提示"校验中"） |
| ③ check 秒传 | `POST /api/v1/files/check {sha256, size, name, content_type}` → 服务端**策略再校验**（不信任端侧）→ 命中 blob → 直接建 file 实例（ref_count+1）→ 返回 `{file_id, dedup:true}`，跳至 ⑧ |
| ④ 申请上传 | `POST /api/v1/files/uploads {指纹, name, size, part_size=4MB}` → 服务端建 upload 会话（7 天有效）→ 返回 `{upload_id, part_total, parts:[{no, url, expires_at}]}`。**预签名按批发放（每批 ≤32 个 URL，时效 1h）**：10GB=2560 片，控制一次性签名量与 MinIO 压力；后续批次经 `GET /uploads/{id}?from_part=` 续签 |
| ⑤ 并行直传 | 传输引擎**并行 3 片** PUT 预签名 URL（Content-Length 固定）；单片失败指数退避重试 ≤3 次；进度/速度实时入传输管理器；弱网自动降并行度至 1 |
| ⑥ 断点续传 | 中断（退出应用/断网/暂停）后恢复：`GET /api/v1/files/uploads/{id}` 返回已收分片位图 → 跳过已传分片续传；本地 SQLite 镜像传输状态，重启即恢复队列 |
| ⑦ complete | `POST /api/v1/files/uploads/{id}/complete {parts:[{no, etag}]}` → 服务端校验分片集齐全与 etag → MinIO 服务端合并（compose）→ **流式计算整体 sha256 与声明一致**才建 blob（不一致 4006，上传作废）→ 删除 staging 分片。UK(tenant_id, sha256) 并发同文件：后到者复用既有 blob |
| ⑧ 后处理 | 图片/视频异步生成缩略图（webp 240/720、视频首帧 poster）；病毒扫描任务入队（ClamAV 启用时） |
| ⑨ 落库建实例 | 建 file 逻辑实例（引用 blob）→ 客户端按业务用途发消息（04 篇 image/file 消息）/ 设置头像 / 供 doc/kb 引用 |

**坏块重传**：complete 校验失败返回 `4003 {bad_parts:[no…]}` → 客户端仅重传指定分片（重新续签该分片 URL），不需整档重来。

### 4.2 上传/下载状态机（传输引擎，两端共用）

```
            ┌────────┐ 开始/恢复
            │ queued │ ─────────────┐
            └────────┘              ▼
            ┌───────────────────┐   │  分片全部PUT完成(上传) / 收到最后字节(下载)
   暂停⏸───►│ transferring 传输中 │───┴──────────────► processing(合并/扫描/落盘) ──► done
            └──┬────────────────┘                        │失败(4003/4006/4004…)
               │取消✕ / 致命错误                            ▼
               ▼                                          failed ──重试(幂等)──► queued
          canceled(清理半成品)          下载额外态: scanning(打开前扫描钩子,§4.4)
```

### 4.3 下载

| 步骤 | 说明 |
|---|---|
| ① 取票据 | `GET /api/v1/files/{id}/download-ticket` → 权限判定（会话成员/owner/分享有效）→ 返回 `{url, expires_in:120s, name, size}`；票据为**一次性短时效预签名 GET**，绑定用户与文件，超时/复用失败即重取 |
| ② 断点续传 | S3 原生 Range：中断后以 `Range: bytes=offset-` 续拉；同会话内进度复用 |
| ③ 落盘 | 默认目录 `~/Downloads/BaobaoWork/`（可改，3 平台一致默认）；**同名文件自动追加 ` (n)`** 不覆盖不报错 |
| ④ 病毒钩子 | 打开（双击/预览）前检查 `scan_status`：非 clean 按租户策略拦截或警告（§4.4）；下载中转扫描仅提示不阻塞 |
| ⑤ 大文件下载 | 与上传对称：并行 3 段 Range 拉取拼接，暂停/恢复/取消 |

### 4.4 病毒扫描（ClamAV 可选集成）

| 模式 | 行为 |
|---|---|
| 关闭（默认小规模部署） | 不扫描，scan_status=skipped |
| 宽松 | 上传后异步扫描；下载/打开放行，阳性事后处置（隔离 blob + 通知 + 审计） |
| 严格 | 上传后异步扫描，**扫描完成前打开拦截**（提示"安全扫描中"，通常 <30s）；阳性文件立即隔离：下载/预览/分享全链路 4004，仅管理员可处置 |

实现：file worker 队列消费 → clamd（unix socket/TCP）流式扫描；>100MB 文件跳过全扫仅校验类型嗅探（性能保护，策略可调）。阳性事件写 audit + 通知文件 owner 与管理员。

### 4.5 图片体验

| 项 | 约定 |
|---|---|
| 缩略图规格 | webp **240**（消息流/网格）、**720**（点开预加载）、**原图**（查看器按需）；服务端 complete 后异步生成；视频取首帧 poster 同规格 |
| 截图粘贴 | 输入框 paste 捕获剪贴板 image → Rust 写临时文件 → 进 §3.3 发送前预览 |
| 拖拽 | 拖文件入会话窗口即浮层提示"发送 N 个文件"；多选文件逐张成消息（图片逐条 image 消息，非图片合并为逐条 file 消息） |
| 发送前压缩 | 标准（默认）：长边 ≤1920、webp q80，典型 2–5MB 截图压至 300–800KB；原图：不压缩直传（走同一上传管线） |
| 查看器 | 缩放（滚轮/双击 100%）、旋转、画廊（会话内全部图片横滑）、前后切换、保存/另存为；导航快捷键 ←/→ |
| 渐进加载 | 消息流内 240 即时 → 查看器 720 → 放大时原图（>5MB 原图提示"加载原图"） |

### 4.6 分享链接

`POST /api/v1/files/{id}/shares {expire_mode, expires_at, max_times, password}`：
有效期（永不/1天/7天/30天）+ 次数上限 + 密码（可选）三要素；链接形如 `https://{host}/s/{code}`，**访问仍需登录**（企业内不匿名，`file:share:create` 可被租户禁用）；每次命中校验有效期/剩余次数/密码（4010/4012/4011），命中记录审计。取消分享即失效链接。

## 5. 数据模型（PG，RLS；blob/file 分离支撑秒传）

**file_blob** 物理去重对象（租户内 sha256 唯一）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | bigint | 雪花 |
| tenant_id | bigint | UK(tenant_id, sha256)——**跨租户绝不去重** |
| sha256 | text | 内容指纹（秒传键） |
| size | bigint | 字节数 |
| content_type | text | 嗅探后的真实 MIME |
| storage_key | text | `t/{tid}/blob/{sha256前2}/{sha256}`（§5.5） |
| ref_count | int | 引用计数（file 删除递减，0 触发延迟物理删除） |
| scan_status | smallint | 0 pending 1 clean 2 infected 3 skipped |
| first_uploaded_by / created_at | — | 首传者（审计用） |

**file** 逻辑文件实例（用户看到的是它）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | bigint | file_id（消息 body 引用此 id） |
| tenant_id / blob_id | bigint | 引用物理对象 |
| name / ext | text | 显示名（**不唯一，同名不冲突**：同一 blob 可多名多实例） |
| owner_id | bigint | 归属用户（配额按此统计） |
| source | smallint | 1 chat 2 doc 3 kb 4 avatar 5 app（来源域，清理策略区分） |
| conv_id | bigint | 冗余：会话内文件聚合（群文件页签）；非会话来源为空 |
| deleted_at | timestamptz | 软删除（回收站 30 天，§7.4） |

**file_share_link** 分享链接：`id, tenant_id, file_id, creator_id, code(UK), expire_mode(1 永不 2 时限 3 次数), expires_at, max_times, used_times, password_hash, status, created_at`。

**transfer_record** 传输记录（服务端镜像，多端可见）：`id, tenant_id, user_id, file_id, direction(1 up 2 down), state(queued/transferring/resuming/paused/processing/done/failed/canceled/expired), bytes_transferred, total_bytes, error_code, target_path(下载落盘路径), created_at, updated_at`。`resuming` 为断点续传恢复态（paused/网络中断后重新拉起；OQ-C29 回填）。客户端 SQLite 另存本地执行态（断点恢复源），服务端记录供跨端查询"我发过/收过什么"。

**file_usage** 配额聚合：`tenant_id + user_id(PK), used_bytes, file_count, updated_at`（上传/删除事务内增量 + 每日对账任务校正）。

### 5.5 MinIO 对象布局

```
{bucket}/
  t/{tenant_id}/blob/{sha256[0:2]}/{sha256}                ← 原始对象(immutable, ref_count>0 期间保留)
  t/{tenant_id}/thumb/{sha256[0:2]}/{sha256}/240.webp      ← 缩略图(随 blob 生灭)
  t/{tenant_id}/thumb/{sha256[0:2]}/{sha256}/720.webp
  t/{tenant_id}/staging/{upload_id}/{part_no:05d}          ← 分片暂存(complete 合并后即删)
```

高合规租户（部署选项，02 篇 §5）：每租户独立桶 `t_{tenant_id}`，路径同上（去 `t/` 前缀）。预签名 URL 仅授权单个对象、单操作（PUT 单片 / GET 单对象）、短时效（上传 1h / 下载 120s），不暴露 AK/SK。

| type | 方向 | 来源 | 说明 |
|---|---|---|---|
| file.transfer.expired | s→c | 14 篇 | 传输失效（上传会话过期/票据失效），端侧置 expired 态 |

### 6.3 错误码 4xxx（本篇扩充，回填 14 篇 §7 登记）

| code | 含义 |

| 4008 | 上传会话不存在或已过期（7 天） |
| 4009 | 超单文件大小上限（区别于 4001 配额） |
| 4010 | 分享链接过期或已取消 |
| 4011 | 分享密码错误 |
| 4012 | 分享次数用尽 |
| 4013 | 文件在回收站/已删除 |
| 4014 | 下载票据过期或已使用 |
| 4015 | 严格模式下文件尚在扫描中，暂不可打开 |

### 6.4 权限点（file:*，注册入 03 篇权限点字典）

| 权限点 | 默认角色 | 说明 |
|---|---|---|
| file:upload | 普通成员 | 上传（含图片/语音等一切经文件域的对象） |
| file:share:create | 普通成员 | 创建外发分享链接（租户策略可整体禁用） |

## 7. 边界/异常/降级

### 7.1 超大文件（10GB）

| 项 | 处理 |
|---|---|
| 分片规模 | 10GB = 2560 片；预签名分批（32/批）+ 到期自动续签；分片号 5 位定长命名排序 |
| 资源占用 | Rust 引擎流式读写（8MB 缓冲），sha256 分块并行（rayon），内存峰值 <100MB |
| 会话保活 | upload 会话 7 天有效，支持跨日续传；每次续传 GET 状态自校验 |
| MinIO 故障 | 02 篇 §7：传输挂起自动重试（指数退避），不影响 IM 文本消息 |

### 7.2 坏块与重传

分片 PUT 成功 ≠ 内容正确：complete 阶段逐片 etag 校验 + 整体 sha256 终验；`4003 {bad_parts}` 定点重传；连续 3 次 complete 失败 → 上传会话作废（4008），客户端提示重新上传（本地文件未变则 sha256 相同可直接秒传重试）。

### 7.3 同名文件策略

| 场景 | 策略 |
|---|---|
| 云端 | 同一 blob 可挂多个 file 实例，name 只是元数据：同名不冲突、不覆盖、不去重合并 |
| 下载落盘 | 同目录同名自动 `name (1).ext`、`name (2).ext` |
| 会话内 | 多人发同名文件各自成卡片，群文件页签并列展示（按上传者区分） |

### 7.4 过期清理任务（file worker，每日 02:00 低峰）

| 对象 | 策略 |
|---|---|
| staging 分片 | 上传会话 >7 天未 complete → 删除分片与会话 |
| 回收站 file | 软删除 >30 天 → 物理删 file 行（ref_count−1） |
| 孤儿 blob | ref_count=0 持续 >7 天（防竞态）→ 删 blob + 缩略图（对象不可变，删除即彻底） |
| 分享链接 | 到期/次数尽 → status=expired（保留记录 90 天供审计后清理） |
| 客户端下载缓存 | 本地 LRU 默认 2GB（可配），低磁盘水位自动清理最旧 |

清理全程审计（15 篇），批量物理删除需二次确认任务单（运维侧）。

### 7.5 群文件页签（会话维度聚合视图）

会话详情侧栏"文件"页签（04 篇 §3.3 入口）：按 `file.conv_id` 聚合 source=chat 的文件；筛选（全部/文档/图片/视频/其他）、排序（最新/最大）、文件名前缀搜索、批量另存；发送者被移出群不回收已发文件（消息流一致性）；群解散后会话只读，页签仍可访问。

### 7.6 配额

| 层 | 规则 |
|---|---|
| 用户配额 | 默认 20GB（租户可配），按**用户拥有的 file 逻辑实例**大小合计（file_usage 表） |
| 租户配额 | 套餐 plan（12 篇），按**物理 blob 合计**（去重后真实存储，去重收益租户侧只算一次） |
| 预检 | check/uploads 时双检：用户逻辑用量 + 租户物理余量，任一超额 4001（响应附当前用量/上限） |
| 超额提示与清理建议 | 4001 详情 + `file.quota.warning`（≥90%）→ 引导"我的文件"按大小排序 Top 列表 + 回收站清理入口 + 大附件转存建议（转发大文件给他人后删除本地实例引用不计他人配额——引用共享同一 blob，仅 owner 计用户配额） |

### 7.7 其他边界

| 场景 | 处理 |
|---|---|
| 弱网 | 并行度自适应降 1；速度 <50KB/s 持续 30s 提示"网络较慢，可稍后继续"；暂停态不占服务端资源 |
| 客户端退出/崩溃 | 本地 SQLite 镜像 + 服务端分片位图，双端状态对齐后续传 |
| 撤回文件消息（04 篇 §4.3） | 仅失效卡片；file 保留在发送者"我的文件"，不自动删 blob |
| 上传中策略变更 | 已建会话按会话创建时策略执行完毕（不中断进行中传输），新会话按新策略 |
| 头像/技能包等系统对象 | 走同一 blob/file 管线（source 区分），不计用户配额（source=avatar/app 由租户配额承担） |
| 隐私 | 预签名最小授权；下载/分享命中写审计（谁在何时取了谁的哪个文件）；秒传命中不暴露"谁先传过"（仅返回 dedup=true） |

## 9. 开放问题

1. ClamAV 集群规模与扫描延迟 SLO：严格模式下 >30s 的等待是否可接受，是否引入并行扫描节点。
2. 视频消息是否引入服务端转码统一 H.264（当前"客户端直传原档 + 首帧 poster"方案在大分辨率机型播放兼容性待验证）。
3. "我的文件"是否演进为轻量个人网盘（目录树/在线整理），与 06 文档中心的边界。
4. 跨设备接力下载（A 设备下到一半 B 设备继续）：分片位图在服务端已具备，产品价值待评估。
5. 秒传的安全风险面：仅 sha256（无服务端二次抽样校验）是否满足租户威胁模型，或增加双哈希（xxh3+sha256）。
