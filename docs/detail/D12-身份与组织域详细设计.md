## 1. 概述与范围

本篇覆盖身份与组织域的**领域机制 + 用户侧页面 + 接口 + 模型**：多租户隔离与租户生命周期、权限判定引擎与权限点全字典、角色与数据范围、组织树与用户生命周期（含异动引擎）、令牌与会话安全（轮换链/设备绑定/防盗/MFA/浏览器一键登录）、认证页族、通讯录、个人资料与账号安全、锁屏、首启引导。

**与 D10 的边界**：管理台的组织树/用户/角色/租户管理**页面外壳**（PAD-03~PAD-08）在 D10 详设；本篇只设计其背后的**领域机制、状态机、API、模型**，相关接口均标注"管理端页面见 D10"；批量导入、离职交接向导、二次验证矩阵等管理流程属 12 篇/D10，本篇仅定义其依赖的领域事件与状态机。术语沿用 00 篇 §7；错误码以 14 篇 §7 注册表为准；Redis/MinIO 布局沿用 13 篇 §5/§6。

## 2. 领域机制详细设计（前置章，本篇核心）

### 2.1 多租户模型与隔离实现

tenant（租户）是顶级隔离单元（00 篇术语表）。实体见 §7.1 DDL：`tenant(id, name, slug, logo_file_id, status, isolation, db_ref, settings jsonb, org_version, …)`；配额在 `tenant_quota`（admin 域，13 篇 §3.8，本篇不重复定义）。

#### 2.1.1 隔离三档

| 档 | 实现 | 创建流程 | 迁移归属 | 适用场景 | 切换代价 |
|---|---|---|---|---|---|
| **T0 共享 schema + RLS**（默认） | 单库单 schema，全表 `tenant_id` + RLS（15 篇 §3.2） | org 服务写 tenant 行 → 种子初始化（§2.2）→ 完成（同步，<1s） | 全局 `migrations/`（golang-migrate 全库一次执行，D02 §7） | 绝大多数租户 | →T1：需为该租户在全量表上按 schema 重放迁移并搬数，停写窗口分钟级 |
| **T1 独立 schema** | 同库 `tenant_{id}` schema，表结构同构，RLS 仍启用（防应用层 Bug） | 建 schema → 按域重放全部迁移至该 schema → 种子 → 注册连接路由 | org 服务编排 admin_task（异步，D10 可见进度）；全局迁移执行时**遍历所有租户 schema 重放** | 中合规、单租户表规模大 | →T2：跨库搬数 + 对象存储整桶迁移；→T0：反向搬数 |
| **T2 独立库** | 独立 PG 实例（可独立 KMS 密钥域，13 篇 §10），连接池按租户路由 | 建库（deploy 侧脚本/Operator）→ 迁移 → 种子 → `db_ref`（kms:// 引用）注册 | 租户库各自执行迁移；发布顺序按 16 篇 | 高合规（15 篇：独立库 + 独立 KMS + 整桶隔离） | 切回共享档需合规评估 + 数据导出迁移，通常单向 |

隔离档在**租户创建时选定**（12 篇：管理后台注册租户时选择），创建后变更走 T1/T2 迁移 admin_task（二次验证 + 双人审批，12 篇 §4.1）。

#### 2.1.3 跨租户操作判定路径（仅 platform:*）

```
请求 /api/v1/platform/* → gateway 路由层识别前缀
 → tenant 中间件【跳过 RLS 注入】（platform 连接池不 SET app.tenant）
 → perm 中间件校验 platform:* 权限点（2001）
 → 目标租户以显式请求参数 target_tenant_id 传入（禁止从 token 外推）
 → 高危动作（停用/销毁/配额清零）：9008 二次验证 + 9009 双人审批（12 篇矩阵）
 → 平台域双审计（12 篇 §7.3）→ 放行
```

非 platform 前缀携带跨租户参数 → 一律 9001（参数白名单外）；RLS 兜底保证即使漏判也 0 行可见（15 篇 T2 用例）。

### 2.2 租户生命周期状态机

`provisioning → active → suspended → archived → destroyed`（12 篇：停用/注销；销毁双人审批+延迟执行）。

| 状态 | 允许的操作 | 进入动作（entry） | 退出动作 |
|---|---|---|---|
| provisioning | 仅 platform:tenant:manage 的完成/中止 | 建表位（T0 行/T1 schema/T2 库）→ 配额初始化（tenant_quota 按 plan）→ **内置角色种子**（§2.5 六角色）→ 根部门创建 → 引导首个租户管理员（邀请链接） | 审核通过→active；失败→回滚清理 |
| active | 全部租户内业务 + admin:* | 计量/配额计数启用；feature_flag 下发 | →suspended / →archived |
| suspended（停用） | 仅 platform:* 与租户管理员只读登录页提示 | **全端 force.logout（reason=tenant_suspended）**；吊销全部 refresh；写路径全拒（2004）；WS 连接服务端关闭 | 恢复→active（重发登录）；→archived |
| archived（归档） | 仅 platform:* 与审计检索（admin:audit:read 只读） | **数据冻结**：写路径与登录全禁；对象存储置 WORM/合规保留桶（13 篇保留期）；连接数收敛 | →destroyed（延迟执行窗口后） |
| destroyed（终态） | 无 | 高危流：双人审批通过 → 延迟执行（默认 72h 可撤）→ 业务数据按保留期清除（审计链与锚点按 15 篇 3 年保留）→ 桶/schema/库回收 → tenant 行留墓碑（id/status/时间，供审计反查） | 无（不可逆） |

矩阵细节与页面见 D10（PAD-07 租户生命周期）。`tenant.status` 变更发布事件总线 `tenant.status.changed`（org→gateway(force.logout 扇出)/eco(停发)/audit）——**本篇新增 topic，回填 D02 §5**。

### 2.3 权限判定引擎

#### 2.3.1 中间件时序（展开 D02 §6 的 auth→tenant→perm 三段；所有服务端统一）

```
请求(Bearer JWT)
 │ S1 认证 auth      ─ 验签(ES256,jwks) → Claims；查吊销名单
 │ S2 租户 tenant    ─ tenant.status 校验 + SET app.tenant（RLS 生效）
 │ S3 会话 session   ─ user.status / force.logout 标记
 │ S4 RBAC perm      ─ Claims.scope ⊇ 所需权限点?
 │ S5 数据范围 scope ─ user_role.scope × 资源 owner 部门 path
 │ S6 资源 ACL       ─ resource_acl 逐层取最大 → 所需 perm 等级
 │ S7 审计标记       ─ audit-scope 中间件采样决策（D02 §6）
 ▼ handler
```

#### 2.3.2 步骤明细（输入/输出/缓存/失败码）

| 步 | 输入 | 输出 | 缓存 | 失败 → 错误码 |
|---|---|---|---|---|
| S1 认证 | Authorization 头 | Claims{sub,tenant,did,jti,scope,act?}；trace 注入 uid | jwks 本地缓存（kid 轮换，15 篇）；吊销名单 Redis `t:{tid}:obo:revoked:{jti}`、`auth:deny:jti:{jti}` | 验签失败/过期 → **1003**；已吊销 → **1004** |
| S2 租户 | Claims.tenant | app.tenant 会话变量；租户策略快照 | 租户策略 Redis `t:{tid}:policy`（policy.updated 失效，D02 §5） | tenant suspended/archived → **2004** |
| S3 会话 | Claims.sub | 有效用户上下文 | `auth:force-logout:{uid}`（TTL=token 余生） | user disabled/offboarded → **2005**；被强制下线 → **1004** |
| S4 RBAC | 路由声明的权限点 | pass/fail | scope 快照在 access token 内（15min）；`GET /me/permissions` 端侧缓存见 §7.3 | 无权限点 → **2001** |
| S5 数据范围 | user_role(scope_type, scope_dept_id) × 资源 owner 的 dept.path | pass/fail | 部门 path 缓存 `t:{tid}:dept:{id}`（TTL 300s；dept 变更失效） | 范围不足 → **2002** |
| S6 资源 ACL | resource_type+id × grant(user/dept/role/tenant) | 有效 perm（逐层取最大：显式>继承>默认） | `t:{tid}:acl:{uid}:{res}` TTL **60s**；授权变更主动失效（对 dept/role 授权按资源批量 SCAN 删除，13 篇 §5） | ACL 拒绝 → **2003** |
| S7 审计 | 路由策略（全量/采样/管理全量） | audit 事件（异步，事件总线 `audit.event`） | — | 落库失败进死信告警（D02 §5） |

高危操作（管理写、OBO 高敏动作、分享管理）**绕过 S6 缓存实时判定**（03 篇 §9：不一致窗口 ≤60s 的例外）。

#### 2.3.3 OBO 请求分支（03 篇 §6.3 展开）

Claims 含 `act` 声明时：

1. **按 sub（用户）鉴权**：S2~S6 完全相同，不因 Agent 放宽或收紧；
2. **Agent 限流**：额外过 `t:{tid}:rate:{uid}:agent`（默认 30 req/10s，租户可配，严于用户通道）→ 超限 **9003**；
3. **预授权清单校验**：租户策略开启 `agent.preauth_required` 且动作为高敏（删文档/发群消息/生态写操作，03 §6.3）→ 校验 Redis `t:{tid}:obo:allow:{agent_session_id}` 是否含该动作键（09 篇权限门控"批准/记忆"时写入，TTL=会话）；未列其中 → **8002**（工具未授权），响应携带 `details.need_consent=true`，Agent 据此向用户发起申请卡（09 篇）；
4. **审计双记录**：`subject=sub`、`actor="agent:"+agent_session_id`（03 §6.3 统一字段）。

OBO 签发（API-AU-15）校验：用户 token 有效 ∧ 申请 scope ⊆ 用户权限 → 否则 **1006**（不静默降级，03 §6.2）。

**自定义角色约束**：① 权限点树勾选**不得包含 platform:\***（前端置灰 + 服务端保存时二次校验 9001）；② 名称租户内唯一（UK(tenant_id,name)）；③ 数据范围四档（本人/本部门/本部门及以下/全租户），`platform_ops` 不可自定义复制。

**不搞角色继承，采用平铺 + 多角色并集**，理由：继承链的语义歧义（子角色收窄还是只增？范围如何覆盖？）与撤销追溯复杂度远超收益；并集模型判定 = 用户全部 user_role 权限一次并集（S4 为 O(1) 集合包含检查），范围"任一角色通过即通过"，行为可预测、审计可解释（与 03 §4.4"逐层取最大"同哲学）。

### 2.6 组织树与用户生命周期

#### 2.6.1 dept 物化路径（path）维护规则

- path 形如 `/{root_id}/{child_id}/{grandchild_id}/`（03 §3.1）；根部门 path=`/{root_id}/`。
- **创建**：path = 父.path + 新 id + `/`，同事务写入。
- **移动子树**（API-AU-20，事务性更新）：① **环检测**：`new_parent.path LIKE moved.path || '%'` 或 new_parent=自身 → **2007**；② 锁 moved 行（`SELECT … FOR UPDATE`）；③ 批量前缀替换：`UPDATE dept SET path = new_prefix || substring(path FROM length(old_prefix)+1) WHERE tenant_id=$t AND path LIKE old_prefix || '%'`；④ 同事务更新 member_count/leader 校验、发布 `org.dept.moved`（org.updated 推送 + 受影响用户 perm.changed，因数据范围基于 path）。
- 深度上限 15 层、单租户部门数上限 5 万（与 PAU-03 虚拟化目标一致，超限 9001）；**删除**：存在子部门或**直属成员**（user_dept 引用）→ **2006** 须先移空；逻辑删除（status=disabled）保留树完整性。

#### 2.6.2 用户生命周期状态机（`invited → active → disabled → offboarded`）

| 状态 | 含义 | 进入动作 | 允许转换 |
|---|---|---|---|
| invited | 已建户未激活（邀请链接/批量导入，12 篇） | 建 user 行（无口令，source=local/sso）；邀请链接 72h 有效可重发 | →active（激活设密/SSO 首登自动建户映射） |
| active | 在职可用 | 首登；发放默认角色（member） | →disabled |
| disabled | 停用（可恢复：长假/风控/离职流程中） | **全端 force.logout(reason=user_disabled)** + 吊销全部 refresh + OBO 全吊销；WS 关闭；其 pending 审批工单自动 expired（12 篇 §9） | →active（恢复重登）；→offboarded |
| offboarded | 离职办结（**终态**，行保留供审计，不物理删） | 离职交接向导（12 篇 §4.6）执行完成：所有权转移/群主转移/KB 空间处置 → 触发 `user.offboarded`（§2.6.3） | 无 |

批量导入/禁用/交接的**管理端操作流见 D10（PAD-04）**；本篇提供状态机与 API-AU-24。

#### 2.6.3 异动引擎（事件扇出表）

### 2.7 令牌与会话安全机制

#### 2.7.1 令牌与轮换链（03 §2.2 展开）

Access JWT（ES256，15min，仅内存不落盘）Claims：`sub/tenant/scope/did/jti/iat/exp`（OBO 追加 `act`）。Refresh（30d 滑动，系统钥匙串）**一次性轮换**：每次刷新将旧 token 置 `status=rotated` 并以 `rotated_from` 链接新行；同链根 `family_id` 串联。

refresh_token 状态机：`active --(正常刷新)--> rotated（终态，作废）`；`active/rotated --(吊销)--> revoked`；`rotated --(旧值重放被捕获)--> suspect（触发链级处置）`。

**被盗检测与处置流程**：

```
POST /auth/refresh 呈现 token_hash
 ├ status=active 且 did+指纹匹配 ──► 轮换：旧→rotated，签发新对（链+1）
 ├ status=active 但 did/指纹不匹配 ──► 吊销该 token(1004)，引导重新登录（疑似拷贝到别机）
 └ status=rotated/revoked（旧值重放）──► 疑似窃取：
      ① 整链吊销（family_id 全 revoked）+ 全设备 force.logout(reason=replay_suspect)
      ② notify 安全通知（系统通知+邮件/短信预留）③ 审计 auth.replay_suspect；下次登录按租略强制 MFA
```

设备绑定：did（客户端首装生成持久 UUID）+ 设备指纹（os/os_version/app_version/hostname 归一哈希，§7.1 device 表）；登录/刷新均校验。

#### 2.7.2 MFA 策略三档与判定时机

租户策略 `security.mfa_mode`：`off` / `optional`（用户自助开）/ `enforced`（全员强制）；`enforced_admin`（对持 admin:* 者强制，12 篇安全策略页配置）。判定时机：**登录第二因子**（口令/SSO/exchange 成功后返回 1002+mfa_ticket → PAU-02）、**锁屏解锁**（PAU-05，启用者）、**敏感操作二次验证**（12 篇 B 档，9008）、**改密/关闭 MFA**（必须验证一次）。TOTP（RFC 6238）±1 时间窗；备用码 10 枚一次性（展示一次，加密存）。

#### 2.7.3 登录防爆破

口令错 → **1001**（details.remaining_attempts）；连续 5 次锁 10min → **1007**（details.retry_after_sec，登录页倒计时，INT-AU-04）；计数键 `auth:loginfail:{tenant_slug}:{account}`（登录前无租户上下文，走全局 `auth:` 前缀例外，§2.1.2#2）。argon2id 存储（03 §2.1）。

#### 2.7.4 浏览器会话免密登录（一键登录）★新增机制

**流程（device-authorization 风格 + 深链回调）**：

```
桌面端 PAU-01 点「浏览器一键登录」
 ① POST /auth/browser-login/request {did, device_name, os, fingerprint} → {login_req_id, user_code(6位), expires_in:300}
 ② Rust sys_open_url 拉起系统默认浏览器：https://<门户>/login/desktop?req={login_req_id}
 ③ 浏览器确认页 PAU-07：无会话→先常规登录；有会话→展示发起设备信息（设备名/OS/IP/位置）
    + 6 位确认码核对 +「确认登录/取消」→ POST /auth/browser-login/confirm {login_req_id, user_code, decision}
 ④ 回传双通道：深链 bbc://auth/callback?code=…（首选，自定义 scheme 唤起桌面端）；
    轮询 POST /auth/browser-login/poll（3s 兜底：pending/authorized(+code)/denied/expired）
 ⑤ POST /auth/exchange {code, did}（一次性 code 60s、绑定发起 did）→ TokenPair（或 1002 需 MFA）→ 主窗
```

**安全设计**：login_req_id 一次性、5min 过期（Redis `auth:blogin:{req_id}`，登录前全局前缀例外）；**确认码核对防伪造桌面端**（用户比对桌面端大字显示的 6 位码与浏览器页展示一致才确认，不匹配 → **1012**）；code 绑定发起 did（异设备使用 → **1013**）；req 已用/过期 → **1010**；浏览器端拒绝 → **1011**。高安全租户策略 `security.browser_login_repwd=true` 时浏览器确认须重输口令；「7 天内该设备免确认」（`device.trusted` + `auth:blogin:trust:{did}:{uid}`）仅租户可选策略，**默认关闭**。限流：单设备发起 ≤5 次/min、单账号确认 ≤10 次/min（9003）。同一 login_req_id 幂等（重复 confirm 返回首次结果）。审计事件 `auth.browser_login`（req_id/did/结果）。服务器不可达门户时降级为口令/SSO 登录（不阻塞）。

## 10. 边界与异常

| 场景 | 处理 |
|---|---|
| SSO 服务不可用 | start 返回 9005 → SSO 按钮置灰+黄条；**本地口令兜底开关**（租户策略 `security.sso_fallback_password`，默认关：纯 SSO 租户提示联系管理员，03 §9 并存策略） |
| 一键登录门户不可达/浏览器未唤起 | 等 10s 未获深链也无 poll 变化→提示「未检测到浏览器动作」+重试/改口令；不阻塞其他登录方式 |
| 组织树超大（5 万节点） | 懒加载 depth≤3+虚拟化；整树导出/批量异动走管理端异步 admin_task（D10） |
| 离职竞态：进行中 Agent 会话 | force.logout → 宿主销毁 OBO+冻结 Runtime、本地会话锁定需重新激活（03 §4.5）；进行中调用以调用时刻校验为准（03 §9） |
| 离职竞态：进行中审批单 | 其 pending 工单自动 expired 回退，通知发起人（12 篇 §9）；交接向导可续跑（admin_task） |
| LDAP 同步冲突（手工改动被覆盖） | 租户配置 `ldap_conflict_policy`：`ldap_wins`（姓名/部门/工号以账源为准，头像/本地昵称保留）或 `local_wins`（冲突字段跳过并出报告）；冲突行写入 admin_task 报告（D10） |
| 跨时区设备时间 | 服务端时间为唯一权威（14 篇 §4.3）；TOTP ±1 窗且服务端计时；设备偏差>90s 时解锁/MFA 提示校时；登录历史展示本地化 |
| 被移出部门但为某文档 owner / 多部门用户 | owner 权限不随部门变，仅数据范围类权限收敛（03 §9）；多部门时任一命中即通过（并集），主部门仅展示用途 |
| 权限缓存不一致窗口 / 部门移动并发读 | 缓存窗口 ≤60s、高危操作实时判定（§2.3.2）；移动期行锁+旧 path 快照读（MVCC），org.updated 后前端对账 |
