## 1. 背景：需求与现状（2026-11-16 代码调查结论）

**需求**：公司同事在 Claude Code / zcode 中把 bbc agent 当子 agent 调用——递一句话、agent 在 bbc 内完整跑一轮对话（含知识检索/记忆/专家/工具）、答案回传、可续聊。**不是** /mcp/corp 工具原子面（服务端 D14 零会话约束下那是另一层），**不是**专家定义导出（借脑不借手，丢记忆/知识库上下文）。

**现状复点**：

- 壳内**零回环监听**（agent_bridge.rs 仅出站连网关）；深链走 OS scheme（lib.rs），无可复用 listener
- 往下整条链现成：`agent_start_session → user.message → 事件泵 → session.state`（agent_commands.rs 20+ 命令）；建会话缺省口径：`workspace=""（日常）、mode="ask"、model_policy="auto"`（tauri.ts:186）
- 轮收口信号=`session.state {state:"idle"}`（apply_session_event）；终答提取=`session.history` 回执最后一条 `kind:"assistant"`（envelope.rs:1155，seq 升序）
- 人工介入点已有事件：`permission.request` / `clarify.question`（审批/澄清卡在 App 内弹，人点后继续跑）
- 反向姊妹篇（bbc 调 claude/zcode，docs/17 bbrt-delegate）已于 2026-11-19 整域退役——本篇「被外部智能体调用」成为唯一方向（不再双向对偶）

## 2. 总体架构：一个内核，两张脸，三个客户端

```
同事的 Claude Code / zcode ──(MCP: tools/call bbc_agent_chat)──┐
bbc ask CLI               ──(A2A: message/send)──────────────► │ 桌面壳 127.0.0.1:8791
未来 A2A 原生平台         ──(A2A: 直连)───────────────────────► │ ┌────────────────┐
                                                                 │ │ MCP 脸 POST /mcp│ ← 方言翻译（批3）
                                                                 │ │ A2A 面 POST /   │ ← 协议正身（批1）
                                                                 │ └───────┬────────┘
                                                                 │  ExtHub 任务状态机
                                                                 │  + AgentHost 复用（零改动）
                                                                 ▼
                              bbrt 会话（会话列表可见、审批卡照弹、记忆/知识库/专家全复用）
```

- **监听器**：`tiny_http`（同步、极轻，匹配壳内 blocking 风格；不引 tokio/axum）。绑定 `127.0.0.1:8791`（env `BBC_EXT_AGENT_PORT` 可覆盖），状态文件 `{dataDir}/external-agent.json`（端口/版本/在线），token 文件 `{dataDir}/external-agent-token`（0600）
- **事件接线**：lib.rs 的 emit 闭包 fan-out——WebView `agent://event` 之外并行喂 `ExtHub.dispatch()`（normalize 后的 snake_case 事件，type/session_id 直取）
- **生命周期**：随 App 启动（setup 内拉起监听线程），App 关闭即面消失（需求前提就是「打开状态下」）

## 3. 任务生命周期映射（A2A task ↔ bbc 会话）

| A2A | bbc 侧 | 说明 |
|---|---|---|
| `task.id` | **bbc sessionId** | 续聊天然：`message/send` 带 `metadata.sessionId`（或 message.taskId）即续既有会话 |
| submitted→working | `user.message` 回执 running/queued | message/send **立即返回 working 态 task**（异步任务模式），调用方轮询 tasks/get |
| input-required | `permission.request` / `clarify.question` | 卡照弹在 bbc UI 里，人点后自动回 working→终态；调用方只见状态翻转 |
| completed | `session.state {state:"idle"}`（该轮收口） | 首次 tasks/get 触发 `session.history` 提取最后一条 assistant 原文=artifact（结果缓存） |
| failed | `runtime.state down` / `session.ended`（working 中） | 错误分类学一期从简（开放问题） |
| canceled | `tasks/cancel` → `session.interrupt` | 中断当前轮，会话保留可续 |

**A2A 协议口径**：JSON-RPC 2.0 over HTTP POST 单端点 `/`；agent card 服务于 `/.well-known/agent-card.json`（+ `/agent-card.json` 别名，card 无鉴权=可发现性）；文本 parts `[{kind:"text",text}]`，宽松解析（缺 kind 也收）。capabilities 声明 `streaming:false`（SSE 归 P1 开放问题，一期 tasks/get 轮询）。

## 4. MCP 脸（方言翻译，批3）

`POST /mcp` stateless streamable HTTP（JSON-RPC）：`initialize` / `notifications/initialized`（202 应答）/ `tools/list` / `tools/call`，无会话态。

| MCP | 翻译到 |
|---|---|
| `tools/list` | 单工具 `bbc_agent_chat(prompt: string, session_id?: string, timeout_secs?: int)` |
| `tools/call` | A2A `message/send` → 内联轮询 ExtHub 至终态（缺省 600s）→ 返回 `content:[{type:"text",text:答案或状态说明}]` |
| 长等待 | tool 阻塞直到终态/超时；答案含 `session_id` 供续聊 |

同事侧挂载：`claude mcp add --transport http bbc http://127.0.0.1:8791/mcp --header "Authorization: Bearer <token>"`；zcode 等价 MCP 配置。

## 5. 鉴权与防环

- **token**：48 字节随机 hex，0600 落 `{dataDir}/external-agent-token`；除 agent card 外全端点要求 `Authorization: Bearer`（401 兜底）；**撤销=重新生成**（批4 授权卡按钮，老 token 立即失效）
- **授权卡（批4）**：设置页「外部 Agent 接入」节——在线状态/端口、token 显示+复制+重新生成、接入指引文案（claude mcp add / bbc ask 示例）
- **防环（拍板 4，已随委派域退役失效）**：原设计 ExtHub 维护外部会话 id 集合，`agent_delegate_launch` 命令层命中即拒；该命令已于 2026-11-19 删除——外部会话本身仍由 ExtHub 维护（任务表 + 标题前缀兜底），供会话列表分类与外部面治理使用

## 7. 真机验收清单

1. App 打开 → `{dataDir}/external-agent.json` 生成、127.0.0.1:8791 监听、`curl /.well-known/agent-card.json` 通
2. `bbc ask "查一下XX"` → bbc 会话列表出现新会话、跑完 CLI 打印答案；`--session <id>` 追问第二轮上下文延续
3. 无 token/错 token → 401；agent card 例外（无鉴权可发现）
4. 知识检索实测：prompt 走 corp 工具（kb_query），结果按同事本人可见性过滤
5. 审批链：会话触发审批卡 → CLI 侧 task=input-required → App 内批准 → completed 且答案完整
6. Claude Code `claude mcp add` 挂载 → 会话内调 `bbc_agent_chat` 拿到答案；zcode 等价配置同验
7. ~~外部会话触发 delegate 被拒（防环）~~：委派域退役后该项自动满足（无委派入口），验收改为「外部会话正常收发、A2A/MCP 面不因委派移除受影响」
8. 重新生成 token 后旧 token 401；`tasks/cancel` → 当前轮中断
9. 关 App → 端口关闭、CLI 明确报「BaobaoChat 未运行」

## 9. 依赖与风险

- 新依赖 `tiny_http`（壳）/CLI 仅 serde_json+reqwest（既有依赖树）；**Cargo.lock 必随提交**
- 固定端口冲突：env 覆盖 + 状态文件动态发现兜底（CLI 读 json 拿真实端口）
- `REQ_TIMEOUT 15s` 只覆盖 REQ 回执（user.message 回执=running 确认非终态），无长阻塞风险；tasks/get 查 ExtHub 本地态零 RT 往返，答案提取首次触发一次 history REQ
- 壳关闭=面消失：需求前提即 App 打开，CLI 报错口径明示（验收 9）
