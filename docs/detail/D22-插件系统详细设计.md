## 0. 背景与拍板决策

目标：给 Agent 增加新能力时**安装插件即可**——一个包内可同时携带技能、工具、命令、子智能体、MCP 定义五类组件。调研对照了 deepseek-harness（进程内 Cordis JS 插件）、Claude Code/ZCode 插件（声明式包目录）、MCP（协议标准）三体系后定案。

**拍板决策（2026-11-12，用户裁决）**：

| # | 决策 | 结论 |
|---|---|---|
| 1 | 包格式 | **采 Claude Code 插件格式超集**：清单三目录名都认，`.bbw-plugin/plugin.json` 为主、回落 `.claude-plugin/`、`.zcode-plugin/`（自家发布用 bbw，生态白拿 claude/zcode） |
| 2 | 工具实现形态 | **一律 MCP**（包内嵌 stdio server 或指向 HTTP server）；不做进程内工具（Rust 宿主无 JS/wasm 运行时，v0.1 不引入） |
| 3 | SkillTab 处置 | **并入插件页**（技能=单组件插件；旧 `/eco/skills` API 保留兼容，SkillTab.tsx 删除——本就未挂路由，无迁移负担） |
| 4 | 同生态身份 | **HTTP-only 约定**：`${BBW_USER_TOKEN}` 仅注入 HTTP MCP 请求头（逐请求新值）；stdio server 只给 `${BBW_USER_ID}`（env 是 spawn 快照，token 轮换不进子进程） |
| 5 | hooks | 清单校验时读取合法性，**运行时不执行**；详情页标注「暂不支持」（阶段二随事件总线立项） |
| 6 | dsh 兼容 | **否决不做**（用户裁决终局）：dsh 插件核心是 Cordis 进程内 JS 闭包，Rust 宿主无法直跑；其 SKILL.md/模板文件可人工搬运 |
| 7 | 个人上传（方案 A，2026-11-13 拍板） | **个人可上传 → 个人区仅自己可见可装（draft 即自用沙盒）；管理员 publish 审核后进公共市场**。落地：0037 迁移 eco_plugin.owner_user_id（0=公共/>0=个人归属）、UploadPluginPrivate（policy 恒 optional、plugin_id 归属校验他人不可覆盖）、visibleTo（公共仅 published/个人对 owner 恒可见）、install/detail/download 归属校验、用户面 POST /api/v1/eco/plugins（multipart）、draft 安装版本回落最新版本行、插件页「上传插件」入口+个人/自用徽章。方案 B（全员直发进市场）否决——需先补签名链（OQ-2） |

**明确不做**（本篇边界外）：进程内插件 API、插件签名/供应链（阶段二）、`netAllow` 沙箱执行（v0.1 仅展示）、delegate 后端插件化（P1 另立项）。

## 1. 插件包格式

### 1.1 目录结构

```
deploy-helper/
├── .bbw-plugin/plugin.json    # 清单（识别顺序：.bbw-plugin → .claude-plugin → .zcode-plugin，取先命中）
├── skills/deploy/SKILL.md     # 技能（frontmatter: name/description[/triggers/allowedTools/risk]）
├── commands/release.md        # 命令（frontmatter: name/description；正文=提示词模板，$ARGUMENTS/$1 占位）
├── agents/release-verify.md   # 子智能体（frontmatter: name/description/tools/model）
├── .mcp.json                  # MCP server 定义（stdio 或 HTTP）
├── hooks/hooks.json           # 预留：校验合法、执行忽略
└── server.js                  # （可选）stdio MCP server 实现，路径经 ${PLUGIN_ROOT} 定位
```

### 1.2 plugin.json schema

Claude Code 兼容字段 + `bbw` 扩展块（扩展字段都在 bbw 块内，保证 claude/zcode 生态包零修改可装）：

```json
{
  "name": "deploy-helper",
  "version": "1.2.0",
  "description": "发布助手：发版流程技能 + 发布单查询/回滚工具 + 验收专家",
  "author": { "name": "平台组" },
  "skills": "./skills",
  "commands": "./commands",
  "agents": "./agents",
  "mcpServers": "./.mcp.json",
  "hooks": "./hooks/hooks.json",
  "bbw": {
    "risk": "medium",
    "category": "devops",
    "netAllow": ["*.company.internal"],
    "config": [
      { "key": "gitlab_token", "label": "GitLab Token", "type": "secret", "required": true }
    ]
  }
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | ✅ | 插件 id：小写字母数字与 `._-`，≤64（同 skill_id 规则）；**即目录命名空间** |
| `version` | ✅ | 语义化 x.y.z |
| `description` | ✅ | ≤200 字，市场检索语料 |
| `author` | — | 展示用 |
| `skills/commands/agents/mcpServers/hooks` | — | 组件目录显式声明；**缺省自动发现默认目录**（同名默认目录存在即生效） |
| `bbw.risk` | — | 插件级默认风险（low/medium/high）；工具级 `x-bbw-risk` 优先 |
| `bbw.category` | — | 市场分类 |
| `bbw.netAllow` | — | 网络声明，v0.1 仅安装确认页展示 |
| `bbw.config[]` | — | 用户配置项声明：`type: secret`（存钥匙串）/`string`（存本地 JSON） |

### 2.1 技能触发兼容（关键差异点）

现有 `SkillIndex` 是 `triggers` 关键词命中注入。Claude 格式 SKILL.md 只有 `description`（语义触发）。v0.1 兼容口径：

- 有 `triggers`：现行机制不变；
- 无 `triggers`：**默认 triggers = [name]**（kebab-case 英文名本身作触发词），同时该技能的 `name + description` 进入会话组装的「技能索引区」（每条一行、≤3 条上限共享），模型/用户提及即命中注入正文。

语义触发（模型看索引自判加载）登记阶段二（需 skill_load 按需注入机制，另行设计）。

## 3. 服务端市场（`server/internal/eco/` 扩展）

### 3.1 存储（迁移 `0036_eco_plugin.sql`）

app/skill 均注册式无包体；**插件带包体，v0.1 存 PG bytea**（单机部署零额外依赖，包限 10MB）：

```sql
plugin_pkg (
  id bigserial PK, tenant_id bigint, plugin_id text,        -- 同名唯一 (tenant_id, plugin_id)
  name text, description text, category text,
  policy int,                                               -- 1 force / 2 recommend / 3 optional（沿用 skill 三档）
  status text,                                              -- draft/published/delisted
  current_version text, created_by bigint, created_at bigint
)
plugin_version (
  id bigserial PK, pkg_id bigint FK, version text,          -- (pkg_id, version) 唯一
  notes text, manifest jsonb,                               -- 解析后的清单快照（组件统计/权限声明）
  package bytea,                                            -- zip 包体
  created_at bigint
)
plugin_install (
  id bigserial PK, tenant_id bigint, user_id bigint,
  plugin_id text, version text, installed_at bigint         -- (tenant_id, user_id, plugin_id) 唯一
)
```

repo 双实现（memory 兜底 + postgres）照 app/skill 先例。**注意本机迁移坑**：内嵌 Migrate 只到 23，24+ 须 psql 手工补（`0035` CASCADE 先例参照）。

### 3.2 API（照 `eco/api/handlers.go` 现有分组风格）

用户面（authed）：

| 路由 | 说明 |
|---|---|
| `GET /api/v1/eco/plugins/catalog?q=&category=&component=&cursor=` | 检索：q 命中 name/description；component 筛 `tool/skill/command/agent`；**含调用方安装态**（installed/version/hasUpdate）；force 置顶 |
| `GET /api/v1/eco/plugins/{plugin_id}` | 详情：清单、组件统计、版本列表、权限声明（netAllow/身份使用/config 声明） |
| `POST /api/v1/eco/plugins/{plugin_id}/install` | body `{version?}`（缺省 current_version）；记 install 态，返回 `{version, download_url}` |
| `GET /api/v1/eco/plugins/{plugin_id}/download?version=` | 返回 zip（Content-Type application/zip；登录态校验） |
| `DELETE /api/v1/eco/plugins/{plugin_id}/install` | 卸载记录 |
| `GET /api/v1/eco/plugins/mine` | 我的安装清单 |

管理面（adminOnly）：

| 路由 | 说明 |
|---|---|
| `POST /api/v1/admin/eco/plugins` | 发布：multipart 上传 zip → 服务端校验（§3.3）→ 入库（draft） |
| `GET /api/v1/admin/eco/plugins` | 列表 |
| `POST .../plugins/{plugin_id}/versions/{version}/publish` | 版本发布（draft→published + current_version 切换） |
| `PATCH .../plugins/{plugin_id}` | 改 policy/category（force 推发用） |
| `POST .../plugins/{plugin_id}/delist` | 下架 |

### 3.3 发布校验（服务端，安装前第一道）

1. zip ≤10MB；清单三目录名识别（§1.1）命中且 JSON 可解析；
2. `name/version` 规则校验（§1.2）；
3. 声明的组件目录存在且非空（显式声明优先，缺省扫默认目录后回填 manifest 快照）；
4. **路径穿越检查**：全部条目名无 `..`、无绝对路径、无符号链接条目（zip slip）；
5. `.mcp.json` 可解析、server 名合法（作 `mcp.{server}.*` 命名空间段）；
6. `hooks.json` 可解析（不执行）。

## 5. 生命周期

### 5.1 本地落盘布局

```
{dataDir}/eco/plugins/<plugin_id>/
├── plugin-state.json      # { "enabled": true, "activeVersion": "1.2.0" }
├── 1.2.0/                 # 版本目录（更新装新版，旧版保留一个供回滚）
└── 1.1.0/
```

bbrt 只认 `activeVersion` 指向的目录（skills 扫描与 `${PLUGIN_ROOT}` 替换都按它解析）。

### 5.2 四操作流程

| 操作 | 流程 |
|---|---|
| 安装 | install API 记态 → download zip → **本地校验**（同 §3.3 清单，客户端复跑防中间篡改）→ 解压落 `/<version>/` → 写 plugin-state → 详情页权限确认（**force 策略跳过确认**）→ 装配生效（§5.3）|
| 更新 | 新版本落新目录 → 切 activeVersion → 装配刷新；**失败自动回切旧版本目录**（旧版保留一个）|
| 禁用/启用 | 只改 `enabled`，不删文件；禁用=装配清单剔除（skills 移出扫描、MCP server 停止）|
| 卸载 | 停该插件 MCP 子进程 → 删目录（可选清配置，默认保留）→ 装配刷新 → 服务端记卸载 |

### 5.3 装配与动态下发（本篇关键协议变更）

现状：MCP 配置经 `BBW_RT_MCP_SERVERS` env 启动时一次性注入（`agent/crates/bbrt/src/main.rs:953`），`tools.reload` 只重扫 skills。**插件要求 MCP 装配可运行时变更**，协议扩展：

1. 宿主装配器（Tauri）：合并「系统级（corp 等 env 来源）+ 插件级（启用插件的 `.mcp.json`，`${PLUGIN_ROOT}` 替换为 activeVersion 绝对路径）」两源；
2. 宿主协议新增 `mcp.config` 下行消息（安装/更新/禁用/卸载/config 变更后推送全量 MCP 装配）——bbrt `McpClient` 支持重配：断开已移除 server、懒连新增 server（复用现有断连标灰+懒补连自愈机制，`bbrt-mcp/src/lib.rs:90`）；
3. `tools.reload {reason:plugin}` 照旧触发 skills/experts 重扫。

安装→生效全链不要求重启会话（正在执行的 turn 用旧装配跑完，下个 turn 用新装配）。

## 6. 身份与凭证注入

### 6.1 三变量族（替换发生在 `bbrt-mcp` 调用层，值推送式缓存，非装配时写死）

| 变量族 | 例子 | 值来源 | 注入位置 |
|---|---|---|---|
| 生态身份 | `${BBW_USER_TOKEN}` `${BBW_USER_ID}` `${BBW_USER_NAME}` | 当前登录用户 JWT/工号/姓名 | TOKEN：仅 HTTP MCP 逐请求 `Authorization: Bearer` + `_meta.bbwObo`（corp 网关 OBO 机制泛化，先例 `bbrt-mcp/src/call.rs:28`）；ID/NAME：HTTP 与 stdio env 均可 |
| 插件配置 | `${CONFIG:<key>}` | `bbw.config` 用户配置（secret 走钥匙串） | HTTP headers / stdio env |
| 安装路径 | `${PLUGIN_ROOT}` | activeVersion 目录绝对路径 | 装配时静态替换（唯一定期不变的变量） |

`.mcp.json` 示例（同生态系统与外部系统并存）：

```json
{
  "mcpServers": {
    "bbw-kb": { "url": "https://bbw.company.internal/mcp/kb",
                "headers": { "Authorization": "Bearer ${BBW_USER_TOKEN}" } },
    "gitlab": { "url": "https://gitlab.company.com/api/mcp",
                "headers": { "Private-Token": "${CONFIG:gitlab_token}" } },
    "deploy": { "command": "node", "args": ["${PLUGIN_ROOT}/server.js"],
                "env": { "BBW_USER_ID": "${BBW_USER_ID}" } }
  }
}
```

### 6.2 宿主协议新增两条推送

- `auth.push`：登录成功/token 刷新时宿主→bbrt 推 `{token, userId, userName}`；bbrt 缓存供 MCP 调用层取值（不落盘）；
- `config.push`：插件安装/配置修改/卸载时推 `{pluginId, config: {key: value}}`（宿主从钥匙串/JSON 汇总；bbrt 内存缓存）。

**为什么推送不拉取**：MCP 每次调用前向宿主 roundtrip 取值太重；推送式缓存代价是 token 失效窗口=推送延迟（秒级），可接受。stdio 局限（env 快照需重启子进程）按 §0 决策 4 规避：同生态服务一律 HTTP 形态。

### 6.3 安全联动

`.mcp.json` 出现 `${BBW_USER_TOKEN}` 的插件：安装确认页与详情页**常驻「将以你的身份调用」标识**；该插件被禁用/卸载即停注入。secret 值不写任何 bbrt/插件可读文件，仅调用瞬间进请求头/env。

## 7. 安全模型

1. **信任源**：企业市场=管理员审核发布（force/recommend/optional 三档管控沿用）；force 推发跳过用户确认；签名校验阶段二（专家 manifest 强校验先例可抄）；
2. **运行时无特权**：插件工具与内置工具同一九步门控、同一审批卡、同一三级授权记忆；风险级取 `x-bbw-risk` > 插件 `bbw.risk` > 默认 medium；
3. **双端包校验**：服务端发布校验 + 客户端解压前复跑（§3.3 清单，含 zip slip）；
4. **网络声明**：`netAllow` v0.1 安装确认页展示，沙箱执行阶段二；
5. **身份最小暴露**：§6.3。
