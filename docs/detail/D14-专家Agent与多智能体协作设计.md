## 1. 概念与目标

**专家 Agent（Expert Persona）**＝一个可复用的"角色定义包"：`人设提示 + 工具白名单 + 技能绑定 + MCP 服务绑定 + 模型偏好 + 权限上限声明`。编排层（08 篇主 Agent）可在一次任务里**按协作图（Team Graph）拉起多个专家**并行/串行工作。

三类执行体在本体系中的统一视图：

| 执行体 | 本质 | 工具集 | 出处 |
|---|---|---|---|
| 探查子 Agent | 进程内轻量上下文（现有，08 §4.5） | 只读子集 | 内置 |
| **专家 Agent（本篇）** | 进程内受限子会话 | **按定义装配**（内置+app.*+技能+MCP） | 公司库/个人库 |
| 外部编码后端 | 独立进程（Claude Code/zcode） | 其自身工具体系（经参数映射约束） | 17 篇 |

> **决策记录（用户裁决）**：① 子 Agent 一律**本地组装、本地运行**——定义包 =「agents.md（persona）＋ 技能 ＋ MCP ＋ 工具」四要素**人为组装**，公司库/个人库分发的只是**定义**，执行永远发生在用户自己的 Runtime（共用主 Agent 运行环境），**服务端不运行任何子 Agent**；② 子 Agent 无会话记录、无记忆——每次调用即一次性受限子会话（§3.2），"所有人调用同一个 Agent"指**同一份定义包**，而非同一运行实例；③ 调用语义对齐 A2A 任务模型（无状态任务提交 + 产物返回），但实现为 Runtime 内部协议（D11 §4），不引入网络协议与服务器沙箱；④ **外部 A2A 外呼**（跨系统/跨组织互操作，`a2a.call`）为二期预留、默认隐藏；⑤ **公司域能力统一经服务端 MCP 网关供给**（2026-11-07）——连接器与公司域 API（kb/doc/oa/im/file）包成 MCP server，Runtime 引入 MCP client 连接期发现工具（§6.1），公司域工具**不再硬编码进 Runtime 内置集**，新增服务/旧服务增能力零客户端与 Runtime 改动；⑥ **MCP 准入红线**——不支持用户身份逐请求传播的 MCP server 只能提供"全员同权限"能力，不得接入按人分权数据（§6.3）。

> 专家 Agent 是子 Agent 机制的**泛化**：从"只读探查工"扩展为"带独立工具集的受限执行体"。（原「外部编码后端则是重型专家特例（工具集=委派能力）」口径已随委派域退役 2026-11-19。）

**两级来源（用户核心诉求）**：

```
┌─ 公司库（组织共用）────────────────────────┐  ┌─ 个人库（私人自有）────────────────┐
│ 管理员/应用管理员经 eco 通道发布：            │  │ 用户自建，存个人空间（11篇）+本地：    │
│  签名 → 安全审查 → 审批 → 灰度(部门/角色)     │  │  声明式 YAML，无 native 代码          │
│  安装策略：强制/推荐/可选（同技能三档）        │  │  可私有 / 分享给部门·指定人（ACL）    │
│ 例：代码评审专家/测试专家/合同审查专家/OA专家  │  │ 例：我的周报助手/我的爬数专家          │
└──────────────────────────────────────────┘  └──────────────────────────────────────┘
```

## 2. 专家定义格式（Persona Manifest，声明式 YAML）

```yaml
id: corp.code-reviewer            # 公司级 corp./dept. 前缀；个人级 usr.{userId}. 前缀
type: local                       # 一期仅 local（本地受限子会话）；remote=外呼外部 A2A Agent（二期预留）
version: 1.2.0
display: 代码评审专家
icon: review.png
persona: |                         # 人设与输出契约（system prompt 增量）
  你是资深评审员。逐文件审查 diff，输出：阻断问题/建议/风险评级三段结构。
tools:                             # 工具白名单（只能引用运行时已注册工具的子集）
  builtin: [read_file, search_files, git_diff, run_command]   # 本地内置（编译期，仅文件/命令/git 类）
  apps:   [oa.lookup]              # 生态应用工具（经 MCP 网关供给，连接期发现注册，§6.1）
  mcp:    [kb.search]              # MCP 网关/外部 server 工具（连接期 list_tools 动态发现，§6.1）
skills: [corp.review-standards]    # 绑定的技能包（SKILL.md，10 篇格式）
knowledge:                         # 知识绑定（第七要素；装配时按空间 ACL 校验，无权限空间剔除并标灰）
  spaces: [kb.contract, kb.product]
constraints:
  max_steps: 40                    # 单次 Activation 步数上限
  max_context: 32k                 # 上下文预算
  write_policy: readonly           # readonly / checkpointed(经检查点可写) / none
  command_policy: whitelist_only   # 白名单命令（AGENTS.md 声明集）
model: { tier: strong }            # 模型档位偏好（D11 §模型路由）
source: company                    # company | personal
signature: <公司级才有：ed25519>
```

**关键约束（与 dsh 的"一切皆插件"分野）**：manifest 是**声明式**的——工具只能引用运行时已注册的清单（内置/已装生态应用/已装技能/MCP server），**不允许携带可执行代码**（脚本仅限技能包内 scripts/，走 10 篇技能沙箱规则）。个人专家的 `tools` 在装配时自动被租户策略 `agent_tool_policy` 过滤（声明了没权限的工具=装配时剔除并在详情页标灰）；`knowledge` 绑定同样按空间 ACL 过滤（专家知识视野 ≤ 用户本人，11 篇三级空间）；persona 内的权限表述仅为引导而非边界（§8-6）。

## 3. 协作图（Team Graph）

### 3.1 三种拓扑

```
① 会诊型（并行 fan-out，join 汇总）          ② 流水线型（串行）
      ┌─► [安全专家] ─┐                        [需求分析专家] ─► [编码专家] ─► [评审专家]
任务 ─┼─► [性能专家] ─┼─► 编排层汇总                                       (专家节点拓扑示例)
      └─► [测试专家] ─┘
③ 评审环（生成↔评审，≤N 轮）
   [编码专家] ⇄ [评审专家]（评审不通过→带意见返工，N=2 超限转人工）
```

### 3.2 执行语义（bbrt-session 扩展，D11 对齐）

| 规则 | 设计 |
|---|---|
| 专家=受限子会话 | 独立上下文窗口（不含主历史，仅任务简报+persona+绑定技能）；独立审计流（`actor=expert:{personaId}:{activationId}`） |
| 并行度 | 会诊型 ≤4 专家并行（探查子 Agent 另计 ≤3）；流水线天然串行 |
| 嵌套限制 | 协作图深度 ≤2（专家不得再拉协作图；探查可由专家自用） |
| 成员通信 | **经编排层黑板中转**（共享任务简报 + 产物写入工作区 `.bbc/team/{runId}/`），专家间不直接对话——避免上下文污染与权限混淆（与 dsh-agent-teams 直连通信的取舍：可审计性优先） |
| 写操作 | `write_policy=readonly` 的专家产出=结构化结论；`checkpointed` 的专家改动走主会话检查点+审批卡（复用 09 篇）；**任何专家不得越过主会话权限档位**（D13） |
| 失败 | 单专家失败不阻塞（编排层标注+补派或降级为探查）；两次失败转人工 |
| 生命周期 | TeamRun（图实例）→ NodeRun（专家 Activation）；全部终态后编排层汇总 → 主会话输出协作图摘要卡 |

### 3.3 谁来构图

1. **自动**：编排层按任务意图从专家库自动选角并生成 DAG（展示给用户，一键"开始执行"或调整）；快模型负责选角，规则：任务关键词 × 专家 manifest 的能力声明匹配。
2. **手动**：用户在专家库选 N 个专家 → 简易画布连线（拖拽拓扑，仅支持三种模板拓扑的参数化，不做自由画布）。
3. **模板**：管理员可发布"协作模板"（预置图+提示，随公司库分发）。

## 5. 分发与治理（复用 10 篇通道）

| 项 | 公司级专家 | 个人专家 |
|---|---|---|
| 发布 | eco 通道，`subject_type=agent`（eco_rollout 扩展枚举：app/skill/**agent**）；签名→审查→审批→灰度 | 无审批；保存即生效（仅本人） |
| 共享 | 灰度范围圈定 | 分享给部门/指定人（resource_acl，viewer 可用/fork 不可改） |
| 撤销 | app.revoked 同语义，在线即时 | 作者删除即失效（已运行中的 NodeRun 自然结束） |
| 策略 | 租户可禁用"个人专家"或限制其工具上限；可设公司专家强制装载 | 受 agent_tool_policy 自动过滤 |
| 审计 | 装载/使用计量（使用次数入用量看板，12 篇） | 本地审计+个人空间审计 |

**依赖打包安装（2026-11-07 补充）**：公司库安装专家时，将其引用的技能包（skills[]）**一并打包分发**（同签名链、同灰度范围），用户侧零配置；MCP 依赖走公司级网关配置（服务端代持连接凭证）；个人 MCP 依赖在详情页标注"需自行配置"。缺失依赖的专家：对应工具/知识空间装配时剔除并标灰（§2 关键约束），保证"点一下安装"对小白用户始终可用。

数据模型（服务端）：`agent_persona`（主档，source/company）、`agent_persona_version`（manifest+签名）；本地：`personal_agent`（镜像）、`team_run`、`node_run`（状态/步数/产物引用/审计关联）。

## 6. 公司域能力供给：MCP 网关与身份传播

### 6.1 供给架构（2026-11-07 裁决）

公司域能力（kb/doc/im/file/oa 与生态应用工具）统一由**服务端 MCP 网关**供给：服务端把各域 API 与连接器（10 篇 §1.2）包成 MCP server（远程 SSE/HTTP）暴露，Runtime 作为统一 MCP client（bbrt-mcp，D11 §2.10）连接，**连接期 list_tools 动态发现**工具并入注册表。Runtime 内置工具仅保留本地能力（文件/命令/git/检索，09 篇 §3.1 注记）。

| 注册表来源 | 注册时机 | 新增能力要动什么 |
|---|---|---|
| builtin（无前缀） | 编译期 | 仅本地能力，随 Runtime 发版 |
| `mcp.{server}.{tool}`（含生态 `app_short.*`） | **连接期（list_tools）** | **纯服务端动作**：挂新 server / 加 tool，Runtime 与客户端零改动 |
| `skill.{skill_short}.{tool}` | 安装期（技能包） | 走 eco 分发，Runtime 不动 |

解耦变更矩阵：新增服务=服务端挂新 server；旧服务加能力=server 加 tool（下次连接自动发现）；下线/吊销=断开 server 或策略禁用，装配时剔除标灰。MCP 工具与内置工具**走同一条执行管线**（D11 §6 九步：gate→审批→沙箱→脱敏），风险级以 server 清单声明、缺失默认"中"，租户策略可按 `mcp.{server}.*` 通配管控。

### 6.2 三层身份模型（连接 / 主体 / 归因分离）

```
① 连接身份：网关↔服务端互信凭证——可固定，服务端代持（10 篇 §5 路径 B 的 KMS 机制）
② 主体身份：sub=用户——逐请求传播，每次 tool call 携带 OBO（Runtime OboCache 注入）
③ 归因身份：act=agent:{session} | expert:{personaId}:{activationId}——仅审计，不影响权限
```

规则：**权限只看 ②，审计看 ③，连接可用性看 ①**。由此强制"专家权限 = 用户权限子集"：知识库专家检索按 sub 过滤空间（公司/部门/个人三级，服务端 RLS）；PPT 专家 `doc.create` 只能落 sub 的个人空间或其有 write 权限的空间；专家不可能因公司库分发而获得超出用户本人的视野。act 值域扩展复用 03 篇 §6.3 机制（双写 `subject=user / actor=…`）。

### 6.3 权限三防线与 MCP 准入红线

| 防线 | 时机 | 机制 |
|---|---|---|
| 一：装配过滤 | 专家 Activation 前 | manifest 声明 ∩ 租户策略 ∩ 用户已授权 → 超出部分剔除标灰 |
| 二：OBO scope 最小化 | 每次 tool call | 只申请 manifest 实际所用的 scope（`doc:write` 不带 `kb:read`），auth 域"scope 必须用户子集"校验兜底 |
| 三：服务端 RLS/ACL | 服务端 | 验签取 sub → 按用户过滤数据 → 审计双写（subject/actor） |

**MCP 准入红线（一票否决）**：不支持用户身份逐请求传播的 MCP server，只能提供"全员同权限"能力（如公共素材库），**不得接入按人分权的数据**（知识库/文档空间/个人数据）。公司 MCP 接入审查（§5）增加此项；OBO 生命周期上，专家 Activation 启动与审批恢复（checkpointed 等待后）前检查 `needs_renew` 并续签（D11 §10.1）。

### 6.4 个人 MCP 与二期反向暴露

| 类 | 设计 |
|---|---|
| 个人 MCP | stdio 本地进程/SSE 远程，配置存个人设置、**凭证入钥匙串**；身份天然=用户本人；可私有或分享定义，不进公司库（或标注"依赖个人配置"） |
| 二期：网关反向暴露 | 网关同时把公司域工具（kb_query/doc_read/oa.*）暴露给 Claude Code/zcode 等（stdio）——每次调用仍经编排层 OBO 转发+审计，凭证不出设备（呼应 17 篇开放问题 2、dsh-crew 反向调度）；先在白名单项目试点 |

## 7. 对 dsh 的采纳/不采纳清单（决策记录）

| dsh 能力 | 决策 | 理由 |
|---|---|---|
| SKILL.md 兼容与目录扫描 | ✅ 已有（10 篇），补充 `~/.agents/skills` 约定目录扫描（导入现有技能池） | 零成本接入存量生态 |
| SubAgent=可替换 Provider 的专家委派 | ✅ 采纳思想→专家 Agent（本篇） | 与我们子会话模型天然契合 |
| dsh-agent-teams 组队/成员通信 | ⚠️ 采纳组队与并行，**通信改黑板中转** | 审计与权限边界优先 |
| profile 分层装配 | ✅ 采纳→三档 profile：**公司（租户强制）/ 项目（AGENTS.md）/ 个人（用户库）**，装配顺序=公司∪个人∩策略过滤，项目级可关停某专家 | 等价于 dsh --profile 但带治理 |
| MCP server 化被外部调度 | ✅ 二期（§6） | 凭证与审计方案已想清楚 |
| 一切皆插件（native 模块动态装载） | ❌ 不采纳 | 企业审计不可接受；声明式清单+脚本技能覆盖主要场景 |
| 开放 npm 生态直接安装 | ❌ 不采纳（公司库替代；个人可"导入"但仅声明式内容+脚本走技能沙箱） | 供应链安全（15 篇） |

## 8. 安全要点汇总

1. 专家权限 ≤ 主会话档位（D13 生效算法同样作用于专家装配）；`run_command` 类工具在专家内仍走完整门控+沙箱。
2. 公司专家签名链同 10 篇；个人专家不出租户、不含可执行代码（YAML 校验：脚本仅允许引用已装技能包内的 scripts/）。
3. 协作图全部 NodeRun 事件入本地审计哈希链；OBO 公司域调用照常 `act=expert:{persona}` 双写。
4. 提示注入：专家产出与黑板产物均按不可信内容渲染（09 篇 §7.3）。
5. 资源：TeamRun 并发 ≤1/主会话；专家总步数 ≤120/图。
6. persona 内的权限表述（如"你只能查询自己权限内的知识库"）仅为**引导**——软约束可被提示注入绕过；硬边界=装配过滤（§6.3 第一层）+服务端 RLS（第三层）双层校验，本地拦不住的服务端兜底。
7. MCP 工具调用链遵守 §6.2 三层身份与 §6.3 准入红线；公司域调用的 OBO scope 按 manifest 最小化申请。

## 9. 边界与异常

| 场景 | 处理 |
|---|---|
| 专家绑定的 app/MCP 未安装或被吊销 | 装配时剔除+卡片标灰；运行中吊销→该专家降级只读继续或终止（编排层选择） |
| 两人协作同一工作区（主会话+TeamRun） | TeamRun 期间主会话修改类操作排队（同 17 篇工作区互斥的扩展） |
| 个人专家引用公司技能 | 允许（技能本身已过审）；反向禁止 |
| 模型档位不足（strong 被限流） | 按模型路由降档+专家卡提示 |

## 10. 开放问题
