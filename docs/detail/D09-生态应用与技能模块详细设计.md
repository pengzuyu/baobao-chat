## 1. 概述与范围

### 1.1 范围

将 10 篇的「清单化接入 → 签名分发 → 灰度 → 客户端安装 → 工具热加载」落为页面/交互/接口/模型级设计：

| 端 | 页面 | 归属 |
|---|---|---|
| 管理端（D10 管理 shell 内容区）PEC-01~06 / 用户端 PEC-07~09 | 9 页 | `features/admin/` 应用管理部分 / `features/eco/` |

不含：Agent Runtime 注册表合并与注入算法（D11）、工具风险门控矩阵（09 篇 §4.1）、审批中心页面壳与工单列表（D10 PAD-13）、KMS 内部实现（15 篇 §3.3）。

### 1.2 术语对齐（沿用 10 篇 §1.1，不新造概念）

应用／技能包／工具／AppManifest／连接器／KMS 引用（authRef）／灰度（eco_rollout）／签名链（根密钥→发布证书→ed25519）／三档策略（force/recommend/optional）；UI 文案统一「应用 / 技能包 / 工具」。

### 1.3 权限点（与 03/10 篇一致）

| 权限点 | 来源 | 控制内容 |
|---|---|---|
| admin:app:publish | 03 篇 | 应用登记/元数据/版本/连接器/灰度/审查提交/发布/回滚/下架 |
| admin:app:review | 10 篇 §6.1 | 版本审批（一级/二级审批人均须持有，且 ≠ 发起人、互异） |
| admin:skill:publish | 10 篇 §6.1 | 技能包 CRUD/版本/三档策略/回滚 |
| agent:app:install | 03 篇 | 用户端自装 optional 应用/技能（PEC-07 安装按钮与 download-ticket） |

### 1.4 确认档位（引用 12 篇 §4.1 矩阵）

- 应用**发布/下架**＝C 档双人审批（发起=应用管理员，审批=租户管理员）；下架按钮为危险级红色确认（D01 §8）。本篇决策：**版本回滚视为与发布同级，同样 C 档**（12 篇未单列回滚，记入 §10-3）。
- 技能三档策略变更、技能版本发布：常规审计；技能包含高危脚本时发布走 C 档（对齐 10 篇 §7.2 第 7 项）。

## 3. 页面详细设计

### 3.0 管理端承载说明

PEC-01~06 渲染于 D10 管理 shell（左模块树「生态应用与技能」节点；二级列表栏=应用列表/技能包列表/审查队列三 tab，12 篇 §3.4）；以下线框只画内容区。

### 3.1 PEC-01 应用登记向导（四步）

```
┌─ 应用登记 · ② 上传清单与图标（第 2/4 步）────────────────────────┐
│ ①基本信息 ─ ②清单与图标 ─ ③连接器 ─ ④权限声明核对                 │
│ ┌─ AppManifest.yaml ────────────────────────────────────────┐ │
│ │ [选择文件] AppManifest.yaml ✓4.2KB     [重新上传] [查看原文] │ │
│ │ 静态校验: ✓schema  ✓semver  ✓签名结构  ✓包扫描(病毒/密钥)    │ │
│ └───────────────────────────────────────────────────────────┘ │
│ [icon] 256×256 PNG（>48KB 自动压缩 webp）  包 1.0MB sha256:9f2a… │
│ ✗ 示例失败: 签名结构不完整(8004) → 阻断「下一步」并给出修正指引    │
│                                       [◀ 上一步(保留状态)] [下一步▶]│
└────────────────────────────────────────────────────────────────┘
```

| 区块 | 内容 | 组件/数据 |
|---|---|---|
| 步骤条 | 四步指示，已完成可点击回退 | `Steps`（AntD） |
| 步骤①表单 | app_id/名称/描述/供应商/发布者 | `Input`×5；app_id 即时校验 |
| 步骤②上传 | manifest+图标+包文件 | `Upload`；07 篇通道拿 file_id |
| 步骤③表单 | 连接器配置（见 3.1.1） | `ConnectorForm` |
| 步骤④核对 | 权限声明核对表 | 只读表+用途说明输入 |
| 底部操作 | 上一步/下一步/提交 | 状态存 `store/wizard` |

步骤③连接器表单（`ConnectorForm`）：baseUrl（保存时服务端校验内网白名单）；authRef＝下拉已有 `kms://` 引用或「新增凭证」write-only 子表单（提交后仅回显 authRef，值永不回传）；timeoutMs 1,000–60,000 默认 8,000；requestsPerMinute 1–600 默认 60；executor=client 的应用可跳过。步骤④核对表：列＝权限项/值/用途说明（必填 20–200 字），行＝每个 oboScopes、maxToolRisk、每个 tools[].risk（>maxToolRisk 预检红字阻断）、minRuntime（低于客户端最低版本黄条警告，不阻断）。

每步校验与失败分支见 INT-ECO-01~04。

### 4.2 关键交互逐项

**4.2.1 向导四步（INT-ECO-01~04）**

| 步 | 校验（客户端→服务端） | 失败分支 | 回退语义 |
|---|---|---|---|
| ① | app_id 正则 `^[a-z0-9]+(\.[a-z0-9-]+){1,}$`；名称 1–40 字；防抖 500ms GET /apps/{appId} 返回 9002=可用 | 重复→内联红字+建议后缀；网络失败→可下一步（本地暂存，提交时再校验） | 步骤数据全存 feature store，回退/刷新不丢 |
| ② | 图标 256×256；manifest 上传后调 manifest-check：schema/semver/签名结构/包扫描逐项回显 | 8004→签名区块红条阻断；扫描阳性→同阻断；9006→格式指引 | 重传文件覆盖即可 |

**4.2.2 发布流泳道（INT-ECO-05，操作级）**

```
应用管理员        审批人(一级/二级)       租户管理员          app-registry           客户端
 │1 上传新版本(draft)│                     │                   │                     │
 │2 PEC-04 勾选清单→POST review ─────────────────────────────►│                     │
 │3 发起审批 POST /admin/approvals(op=app.publish,选审批人)──►│ 站内+WS 审批通知     │
 │                  │4 一级 approve ─────────────────────────►│ status: review      │
 │                  │5 (高危)二级审批(≠一级≠发起) ────────────►│ status: approved    │
 │6 PUT rollout(范围+百分比) ─────────────────────────────────►│                     │
 │7 POST publish(approval_id) ───────────────────────────────►│ 版本落库+包传 MinIO  │
 │                  │                     │                   │8 WS app.updated ───►│
 │                  │                     │                   │                     │9 安装管线→tools.reload→工具可用+toast
```

任一审批拒绝（9010）→ 版本回 draft，PEC-02 状态条红色提示原因；审批 24h 未决过期 → 发起人收到过期通知可重发（对齐 D10 审批状态机）。

**4.2.3 版本回滚（INT-ECO-06）**：入口 PEC-02/03「回滚」→ 选择目标（仅历史 published）→ 确认弹窗（危险级红色钮）列影响提示：「当前 v1.4.0 已安装 3,210 端；回滚到 v1.3.0 后全部端将收到降级同步（app.updated action=downgrade），进行中的工具调用按调用时刻校验放行完成」→ 需 C 档审批（POST /admin/approvals op=app.rollback）→ 执行 POST /rollback → current_version 指回旧版 + 推送。

**4.2.4 应用下架（INT-ECO-07）**：PEC-06 危险区红色按钮 → 危险级确认（列出：工具 N 个将停用、捆绑技能 M 个同步移除）→ C 档审批 → POST /delist → 服务端置 delisted 并向**全体在线端**推 `app.revoked`。**用户侧即时表现**：宿主即刻 tools.reload 移除该 app.* 工具 → 技能索引移除捆绑 SKILL.md → toast（error 样式 6s）「"公司OA审批"已被管理员下架，相关工具已停用」→ 进行中调用返回 8003；离线端缓存时效 ≤10min（10 篇 §4.4）。

**4.2.5 灰度调整（INT-ECO-08）**：滑杆/按钮（暂停/提至50%/全量）→ PUT rollout → 服务端按稳定哈希（`hash(uid)%100 < canary_percent`，同一用户不抖动）重算命中集 → **新增命中**在线端收 app.updated（action=install/upgrade）即时拉取（推送到达≤10s；WS 断线由重连补拉兜底）；**移除命中**（如调出部门）收 app.revoked(reason=rollout_excluded)；离线端在下次启动登录 catalog 时生效。页面保存后 toast 注明时延口径。

**4.2.6 技能安装三态的用户感知差异（INT-ECO-09/10/11）**

| 档 | 触发 | 感知差异 |
|---|---|---|
| optional（市场） | 点「安装」→ 权限说明强制展开+确认（「以你的身份使用 …」）→ 管线可见（进度浮层可取消） | 唯一需要用户显式同意权限的场景；需 agent:app:install |
| recommend（引导页） | 首入 /agent 弹层，勾选+一键安装 | 已默认勾选；确认文案弱化（一键）；可跳过；安装队列后台进行，完成后 toast |
| force（登录） | 登录同步 catalog 命中即自动执行 | **无感**：不弹任何确认；安装失败静默重试（≤3 次退避），仍失败仅通知中心一条「技能安装失败，联系管理员」；不可停用/卸载（INT-ECO-14） |

**4.2.7 更新流（INT-ECO-12）**：WS `app.updated`（或重连补拉）→ 与本地 current 比对得 action=upgrade/downgrade → **后台静默下载**（不打断会话；下载进度仅进 PEC-08 队列条）→ sha256 摘要比对 → ed25519 链验签（根公钥内置→证书→签名，§6.2）→ 解包至 `{version}.new` → 原子 rename 生效 → 宿主向 Runtime 发 `tools.reload{reason}` 热加载 → toast（info 3s）「应用已更新：公司OA审批 1.4.0，新工具即时可用」。downgrade（回滚）同管线，toast 文案区分「已回退到 1.3.0」。

**4.2.8 验签失败（INT-ECO-13）**：verifying 阶段任一失败（8004 签名 / 8045 下载或校验失败 / 摘要不符）→ 删除 `.new` 保留旧版本继续可用 → 安装任务置 failed → 用户端 toast error 6s「"X"更新校验失败，已保留当前版本（8004）」+「查看详情」→ POST /apps/state 上报（管理端看板「失败 N（8004×k）」即时可见）→ 不自动重试验签类失败（防重放攻击面）。

**4.2.9 force 拦截（INT-ECO-14）**：PEC-08 中 force 包的启停/卸载按钮锁定态；点击 toast info 4s「该技能由管理员策略安装（强制），不可停用/卸载」。服务端 state 上报同样拒绝（8006）。

**4.2.10 技能策略与回滚（INT-ECO-15）**：三档单选→保存即 PUT policy（常规审计）→ force 变更对下次登录生效并在看板提示；技能回滚复用 INT-ECO-06 语义（含高危脚本时 C 档）。

**4.2.11 注册表冲突/超限（INT-ECO-16）**：发布静态预检（命名重复/单应用>40/总数>200）阻断发布并提示改名；运行期 8044 → 管理端安装统计页黄条告警「该应用部分工具未装载（命名冲突/超限）」。

### 4.3 状态机

**4.3.1 应用版本状态机**（`eco_app_version.status`；delisted 为 `eco_app.status` 投影）

```
draft ─submit_review→ review ─approve(L1,无高危)→ approved ─publish(C档)→ published
  ▲                     │─approve(L1)→(高危待L2)review                        │
  └───reject(9010)──────┘─approve(L2,高危)→ approved     published ─rollback(C档)→ rolled_back
                                                        rolled_back ─publish(再审批)→ published
任一非 draft 态 ←─ delist（app 级，C 档）→ eco_app.status=delisted（版本态冻结，展示投影 delisted）
```

| 当前 | 事件 | 下一 | 守卫 |
|---|---|---|---|
| draft | submit_review | review | 清单七项全勾（PEC-04） |
| review | approve | review | 仅一级完成且 maxToolRisk=high（待二级） |
| review | approve | approved | 无高危（一级即成）或二级完成；审批人持 admin:app:review，≠发起人，二级≠一级 |
| review | reject | draft | 任一审批人拒绝（9010） |
| approved | publish | published | 携带 24h 内有效 approval_id（9009/9008） |
| published | rollback | rolled_back | 目标为历史 published；C 档 |
| rolled_back | publish | published | 重新走审批 |

**4.3.2 安装任务状态机**（客户端 Rust 层；UI 镜像 `['eco','install-queue']`）

| 当前 | 事件 | 下一 | 说明 |
|---|---|---|---|
| pending | 调度 | downloading | 队列**串行**（同时 1 个）；GET download-ticket→预签名下载，断点续传 |
| downloading | 分片完成 | downloading | 进度回推 `eco://install-progress` |
| downloading | 下载完 | verifying | sha256 摘要比对 |
| verifying | 链校验通过 | installing | 根公钥→证书→ed25519；解包至 `.new` |
| verifying | 失败 | failed | 8004/8045；删临时保留旧版（INT-ECO-13），不上报重试 |
| installing | rename 成功 | done | 原子 rename→tools.reload→toast→POST /apps/state |
| installing | 失败 | failed | 8043；删 `.new` 保留旧版，自动重试≤3 次（退避 1/5/15min） |
| downloading/pending | cancel | canceled | 仅手动任务（optional/recommend）可取消；force 不可 |
| done/failed/canceled | — | 终态 | failed 可手动重试→downloading |

### 4.4 客户端同步时序（登录全量 + 推送增量）

```
登录成功 ──► GET /apps/catalog?installed={id:ver,…}（apps+skills 合并差异）
   ├─ action=install/upgrade/downgrade ──► 入安装队列（force/recommend 已装/应用升级 自动执行）
   ├─ action=revoke ──► 移除+tools.reload+toast（INT-ECO-07 同表现）
   └─ 无差异/optional 未装 ──► 跳过（optional 仅市场角标「新」）；POST /apps/state 上报本机安装态
运行中 ──► WS app.updated{subject_type,subject_id,version,action} ──► INT-ECO-12 更新流
        ─► WS app.revoked{subject_type,subject_id,reason} ──► 即时移除（在线语义）
WSS 重连成功 ──► 补一次 catalog 全量校验（防推送丢失，10 篇 §4.3「联网后补一次」）
每次工具调用前 ──► 本地撤销时间戳检查：>10min 且可联网→在线刷新再放行（8046 高危拒绝/低危放行记录）
```

### 5.2 管理端接口详解（字段级）

**API-ECO-00 manifest-check**（请求：manifest 全文 yaml/text + package sha256/size）
响应 data：`{items:[{key:'schema'|'semver'|'signature'|'scan'|'icon', ok:bool, detail:string}], parsed:{app_id,version,tools_count,skills_count,max_tool_risk,min_runtime}}`。错误：9001（yaml 解析）、9003。清单内出现明文凭证模式命中→scan.ok=false 并 detail 提示。

**API-ECO-01 POST /apps**　请求：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| app_id | string | Y | 逆序域名，租户内唯一 |
| display | {name,description,vendor,color,icon_file_id} | Y | name 1–40 字 |
| publisher | string | Y | 发布密钥证书主体 |

响应 data：`{app_id,status:'draft',created_at}`。错误：9001（格式/app_id 重复→details.reason=duplicate，见 §10-2）、2001、9003。

**API-ECO-05 POST /versions**　请求：`{version, manifest(jsonb), package_file_id, package_sha256(64hex), min_runtime}`；服务端复验签名链并落 signature。响应：`{version_id,version,status:'draft',signature_check:'valid'|'invalid',created_at}`。错误：8004（签名校验失败）、9001（semver 非法/版本已存在→details.reason=duplicate）、8041（捆绑技能结构非法）。**signature_check=invalid 时记录但仍为 draft，禁止进入 review**。

**API-ECO-07/08 connectors + secret**　POST/PUT 请求：`{label,type:'http',base_url,auth_ref,timeout_ms(1000–60000,def 8000),rate_limit:{requests_per_minute(1–600,def 60)}}`。secret 请求：`{secret_value}`（**write-only**，服务端写 KMS 后仅回 `{auth_ref:'kms://…'}`，任何接口不回显值）。错误：8006（base_url 不在内网白名单）、9001、9005（KMS 不可用）。

**API-ECO-09/10 rollout + stats**　PUT 请求：`{subject_type:'app',version,scope_type:'all'|'dept'|'role'|'allowlist',scope_targets:[dept_id/role_id/uid…],canary_percent(0–100),status:'active'|'paused'}`；响应：`{rollout_id,effective_hint:{online:'≤10s',offline:'下次登录'}}`。stats 响应：

```json
{ "subject_id":"com.company.oa", "version":"1.4.0",
  "online_total":5100, "installed":3210, "failed":12,
  "by_dept":[{"dept_id":7,"dept_name":"研发中心","online":1468,"installed":1204,"pct":82}],
  "recent_errors":[{"code":8004,"count":3},{"code":"timeout","count":9}] }
```

错误：9001（百分比/目标非法）、9002（版本不存在）。

**API-ECO-11/12/13 review / approve / publish**　review 请求：`{checklist:[{item:1..7,checked,note}],summary?}`（七项须全 checked=true，自动预检失败项不可提交）。approve 请求：`{decision:'approve'|'reject',note,level:1|2}`；服务端校验审批人权限/互异/≠发起人，高危且 level=2 缺失时保持 review。publish 请求：`{approval_id}`（24h 内有效；缺失/过期→9009/9007）；响应：`{version,status:'published',pushed:true,published_at}`。错误：9008（需二次验证票据）、9009、9010、8004。

**API-ECO-14/15 rollback / delist**　rollback：`{target_version,reason,approval_id}`（C 档）→ `{current_version:target,pushed:true}`；delist：`{reason,approval_id}` → `{status:'delisted',revoked_push:true}`；错误：9002（目标非 published）/9009/8003（重复下架）。

**API-ECO-16~20 skills**　POST /skills：`{skill_id,name,description,risk,icon_file_id,install_policy}`；POST versions：`{version,package_file_id,package_sha256,min_runtime,skill_md_preview}`（解析 frontmatter：triggers/allowedTools/oboScopes，失败 8041）；publish 同型（risk=high 时 C 档）；PUT policy：`{install_policy}`；rollback：`{target_version,reason}`。错误同应用域+8041。

**API-ECO-21 GET /apps/catalog**　query：`installed={subject_id}:{version},…`（apps 与 skills 合并返回）。响应：

**API-ECO-25 POST /apps/{appId}/tools/{tool}**（Agent 经 Runtime 以 OBO 调用）

```json
// 请求（Header: Authorization: Bearer <OBO token>）
{ "call_id":"c-991", "args": { "status": "pending" } }
// 响应 data
{ "result": { "todos": [ {"id":"T-1","title":"报销单 R-88 待审批"} ], "total": 1 },
```

## 9. 边界与异常

| 场景 | 处理 |
|---|---|
| 离线首登（无缓存） | 仅内置工具；PEC-08 显示空态+「联网后同步」；联网补 catalog |
| 安装中断（断电/杀进程） | `.new`/`.part` 残留→下次启动清理重试；原子 rename 保证不半装（10 篇 §7.4） |
| 多设备 | 安装为设备级（user_app_state 含 device_id）；force 包每台设备各自安装 |
| 用户调离灰度部门 | rollout 重算→下次校验不命中→app.revoked(rollout_excluded)，缓存 ≤10min |
| 撤销时正在执行的调用 | 以调用时刻校验为准放行完成，后续调用 8003（与 03 篇 §9 权限窗口一致） |
| minRuntime 不满足 | catalog 标记 blocked（8040）→跳过安装+通知中心提示升级客户端 |
| 注册表超限/命名冲突 | 超出部分拒绝装载+管理端告警（8044）；发布静态预检尽量前置拦截 |
