## 0. 背景与拍板决策

背景：2026-11-12 十轮设计讨论。起点=「内置知识库太重（纸面 RAG 一件没落地）」，终点=**轻量博客**：公司内部一上手就有知识可检索、可分享，榜单让优秀文章和作者被看见（**攀比=明确的产品目标**）；重型能力外包给插件生态。中途三次裁剪：博客化 → 成员制空间 → **两维度终稿**（成员制也砍）。

**拍板决策（2026-11-12，用户裁决，勿重提）**：

| # | 决策 | 结论 |
|---|---|---|
| 1 | 定位 | 内置=**轻量博客**（feed+阅读页+榜单）；重型 RAG=RAGFlow 等走 D22 插件（工具一律 MCP），不进内置 |
| 2 | 维度 | **只有两个维度**：公司知识库（公共，全员可看可投，全租户唯一）+ 我的文章（个人，仅本人，AI 入库默认落点，不进榜单）；**「空间」产品概念彻底消失**——无创建/管理/授权动作；多空间/成员制/隔离**后置**（未来想好再做，本篇登记防丢） |
| 3 | 页面形态 | 纯阅读+检索+榜单，**无写/编辑/删除 UI**；写入只留服务端 API 给未来 AI（OBO）；编辑/删除仅作者（created_by）——API 随 AI 写入批次落地 |
| 4 | 目录 | 保留=「专栏」：公共维度一棵共享树（全员可建目录）+ 个人维度每人一棵；文章挂目录**可空=维度根**（先保存后整理） |
| 5 | 保存/投稿分离 | 保存（高频无脑）默认落我的文章、零选择；投稿（低频显式）=移动到公司知识库，**单向升级不并存**（后置 AI 动作）；跨维度不做多挂载——归属判断（内容面向谁）+标签（P1）解决发现 |
| 6 | 组织解耦 | 部门不再有空间（不自动建/不挂靠/不查祖先链）；组织语义由内容与作者信息呈现，不绑存储结构 |
| 7 | 浏览量 | **一人一天一篇计 1**（kb_doc_view 三元组主键去重，ON CONFLICT DO NOTHING）；**作者本人不计**（防刷榜） |
| 8 | 榜单 | **只收公共维度文章**（公平口径：个人/未公开内容不参与攀比）；三列=最新 Top10 / 最热 Top10（窗口 7d·30d·总榜）/ 作者榜 Top10（文章数+总浏览）；首页另含个人概览卡（文章数/本月新增/总浏览/7 日新增/**全公司作者排名**） |
| 9 | 检索 | **三态降级**：未配嵌入=纯关键词 ILIKE（零依赖可用）→ 配嵌入=向量+关键词 RRF → 再配 rerank=RRF top30 重排取 topK；嵌入/rerank 复用 ai_provider+ai_route_rule（**tier embed/rerank 独立路由，可与 LLM 不同来源**；上游全部 HTTP 接口调用，服务器进程不跑模型） |
| 10 | 嵌入切换 | **epoch 渐进重建**：切模型=epoch+1+后台按文档重嵌；过渡期向量路只命中当前代、关键词路全量兜底（RRF 天然融合，零停机零错配）；跨维度=清空向量+ALTER 列+索引重建（管理端确认）；**rerank 是查询时组件，切换零成本** |
| 11 | 图片 | v0.1 图片本体不入向量，只索引 markdown alt+上下文段落文本；P1=VLM 生成图片描述注入分块（复用 chat 多模态通道）；CLIP 类双索引**不上** |
| 12 | 授权 | ACL grants 三件套（ListGrants/AddGrant/RemoveGrant+resource_acl 投影）**废弃**——两维度下无授权场景；隔离需求回归时随成员制后置项另立 |

**明确不做/后置（登记防重提）**：多空间/成员制/邀请制/空间广场（未来想好再做）；文章编辑/删除 API 与 UI、投稿移动、Agent 会话「保存到知识库」入口（随 AI 写入批次）；VLM 图片 caption（P1）；标签（P1，跨主题发现）；热门搜索词（P1）；概览卡排名升降 rankDelta（P1，需日快照）；异步摄入 job 表/状态机（同步摄入毫秒级，内网量级不需要）；zhparser FTS/LibreOffice 解析/bge-reranker 自托管/敏感标记/水印/kb_query_log 审计（重型项全冻结-插件化）；CLIP 图文双索引。

## 2. 两维度模型

### 2.1 维度定义

| | 公司知识库 | 我的文章 |
|---|---|---|
| 内部 space_type | company（每租户 1 行，0037 种子，唯一索引兜底） | personal（每人 1 行，首次访问惰性创建——现状保留） |
| 可见 | 全员（可检索/可浏览/进榜单） | 仅本人 |
| 可投稿 | 全员（IngestDoc API） | 仅本人 |
| 目录 | 一棵共享专栏树（全员可建目录，同父同名 7014） | 每人一棵 |
| 配额 | 20GB（现状） | 5GB/人（现状） |
| 榜单 | 三列榜单+作者榜唯一数据源 | 不进榜单；概览卡统计含 |
| 定位 | 公开分享、攀比主场 | 草稿/私有沉淀，AI 入库默认落点 |

**内部实现注记（非产品概念）**：kb_space 表退化为纯内部维度行——公共维度每租户 1 行（0037 迁移种子，EnsureCompanySpace 幂等同构个人惰性）、个人维度每人 1 行（惰性）。quota 与检索过滤继续按这两行记账；用户不可见、不可建、不可管理。前端任何页面不出现「空间」字样，左栏=固定两入口「公司知识库 / 我的文章」。

### 2.2 权限判定（收口后全量）

```
canRead(space)  = space.type=company → true
                | space.type=personal → space.owner=user
canWrite(space) = canRead 同式（公共全员可投/个人仅本人）
文章编辑/删除   = 仅 created_by=作者（API 后置随 AI 批次，本篇只锁语义）
```
删件：ACLPerm/ACLGrant/ACLListGrants/ACLRevoke/UserDeptIDsOf/UserDeptChainOf 六闭包、deptChainOf、resolveDeptBinding、canRead/canWrite 的 dept 分支。检索/浏览/详情全部经 getSpaceFor→canRead，一处收口全线生效。

### 2.3 保存/投稿分离

```
保存（高频·零选择）：任何来源（IM 收藏/未来 AI 产出）→ 默认落我的文章（目录可空=根）
投稿（低频·显式）  ：我的文章文章 → 移动到公司知识库（单向升级，后置 AI 动作，不留双份）
```
文章唯一归属（一篇一维度一目录）——榜单/浏览量/作者榜口径全部依赖「条目唯一」。

## 3. 数据模型（迁移 0037）

```sql
-- 浏览量（榜单/概览唯一数据源）
ALTER TABLE kb_doc ADD COLUMN view_count BIGINT NOT NULL DEFAULT 0;
CREATE TABLE kb_doc_view (
  tenant_id  BIGINT NOT NULL, doc_id BIGINT NOT NULL,
  user_id    BIGINT NOT NULL, view_date DATE NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  PRIMARY KEY (doc_id, user_id, view_date));            -- 日去重：一人一天一篇计 1
CREATE INDEX idx_kb_doc_view_agg ON kb_doc_view (tenant_id, doc_id, view_date);

-- epoch 重建
ALTER TABLE kb_chunk ADD COLUMN embed_epoch INT NOT NULL DEFAULT 1;
CREATE TABLE kb_settings (                                -- 单行表
  id INT PRIMARY KEY DEFAULT 1 CHECK (id=1),
  embed_epoch INT NOT NULL DEFAULT 1,
  embed_model TEXT NOT NULL DEFAULT '',
  embed_dims  INT NOT NULL DEFAULT 1024,
  rebuild_status TEXT NOT NULL DEFAULT 'idle',           -- idle|running
  rebuild_done INT NOT NULL DEFAULT 0, rebuild_total INT NOT NULL DEFAULT 0,
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now());

-- 维度收口（DO 块）：
--   ① 每租户缺公共维度行则种子（space_type='company'，quota=20GB）
--   ② 存量 dept 空间的 node/doc/chunk 并入该租户公共维度（space_id 改挂）
--   ③ 删除 dept 空间行；dept_id 列废弃不删
CREATE UNIQUE INDEX uq_kb_space_company ON kb_space (tenant_id) WHERE space_type='company';
```

## 5. 检索链路

### 5.1 三态降级（部署配置决定，代码同一套）
```
态一 未配嵌入路由：B 路 ILIKE 关键词直出（Degraded=["vector"]，现状行为）
态二 配 bbw-embed：A 路向量(余弦)+B 路 ILIKE → RRF(k=60) 融合直出（现状默认）
态三 再配 bbw-rerank：RRF 候选取 30 → rerank(query×30) → 重排取 topK；
     rerank 失败/未装配 → Degraded+=["reranker"]，RRF 序直出（不阻塞检索）
```
管理端零新开发：复用 ai_provider CRUD+probe+routes（admin:policy:manage）；部署清单加一条「配好 bbw-embed 路由」。

### 5.2 rerank 通道与 aigw 两缺口（前置）
| # | 改动 | 说明 |
|---|---|---|
| 1 | OpenAICompatProvider.Embed 真实调用 | 现状恒报错（只有 mock 可用）：POST {base}/embeddings（OpenAI 协议） |
| 2 | registry 放开 embed/rerank 档表驱动 | 现状 PutRoutes 拒 embed tier、Reload 只装 fast/strong——管理后台配了嵌入供应商也不生效；白名单加两档 |
| 3 | rerank 通道 | AliasRerank="bbw-rerank"+Provider.Rerank（OpenAICompat=Cohere 风格 POST {base}/rerank；Mock=词面重叠确定性打分）+HandleRerank（抄 HandleEmbeddings：auth→oboGate→decode→limiter→Route→Invoice Scene"rerank"）+main 注册 POST /v1/rerank |
| 4 | kb 消费 | Options.RerankFn+GatewayRerankFn（embed_gateway.go 同款 HTTP 自调，dev token 通道）；Query() RRF 后插 rerank 阶段 |

### 5.3 epoch 渐进重建
```
切换模型（管理端 POST /api/v1/admin/kb/embedding/rebuild {model, dims}）：
  ① 样本校验：实时嵌入一条探测文本，维度≠dims → 7018
  ② rebuild_status=running 时拒绝 → 7017
  ③ epoch+1 写 kb_settings；dims 变化 → 清空 kb_chunk.embedding + 动态 ALTER 列类型 + HNSW 索引重建（管理端确认弹窗前置）
  ④ 后台 goroutine 按 doc 遍历：读 content → runPipeline 重切+重嵌（直调 Router 绕 HTTP 限流，计量照记）→ IngestCommit 带 epoch
  ⑤ 进度 done/total 实时更新，完成 status=idle；中断可重触发（幂等续跑）
过渡期检索：向量路 WHERE embed_epoch=当前代（只命中已重建）；关键词路全量兜底——RRF 融合天然增量，零停机零错配
```
量级依据：内网万级 chunk≈160 次批量嵌入（64/批），分钟级完成；不需要 Redis Stream/job 框架，单行状态表+goroutine 足够。

## 11. 补记：正文媒体存储与访问（2026-11-12 讨论拍板，随批次 N 实施）

**缺口**：正文内嵌图片/视频/附件的本体走 file 域（D06/D25=MinIO，正文只存 file_id 引用），
但文件票据放行=「owner 或会话成员」（file/service canAccess）——公开文章的读者对作者
上传的媒体取票即 403，正文图全裂。

**拍板（勿重提）：挂门法（引用表）——权限不落在文件行上，跟引用走**。否掉「文件行打标
source=kb_article」标记法两死穴：①同一行多处引用时权限被最大上下文放大（私人原件被动公开）；
②文章移动/删除需联动改标记，漏一处即泄漏。

| 层 | 设计 |
|---|---|
| 数据 | `file_ref(file_id, ctx_type, ctx_id, created_by, created_at)`；ctx_type ∈ kb_article（本批）/ message（终态）。file 行只描述物理内容（sha/owner），不承载访问语义 |
| 放行 | canAccess = owner OR EXISTS(请求者**可见**的引用上下文)。可见性判定按 ctx_type 分发闭包：kb_article→文章维度（company 全员 / personal 仅本人，§3 两维度口径）——file 域零业务知识 |
| 正文引用 | markdown 内嵌 `bbwfile://{file_id}`；阅读页渲染时现场换 120s 票据（D25 IssueClientTicket，variant=240 气泡/origin 点开）——正文不嵌死一次性 URL |
| 删除 | 三层：编辑删图/撤回/删文章=静默删对应引用（其他门不受影响）；「我的文件」删本体=引用计数提示「正被 N 篇文章/M 条消息使用」确认后裂；引用全零+无 owner=清理任务真回收（归 D06 已登记项） |
| 记账 | 物理字节≠账单：账跟引用走（file_ref.created_by 备将来配额记账）；个人配额 v0.1 不做（D06 登记）；sha 去重=多处引用全公司一份字节 |
| 检索 | 不变：图片本体不入向量只索 alt+上下文（§2 既有口径） |

**最小落地切法**：批次 N 只挂 kb_article 上下文（file_ref 随迁移 0037 一并建；canAccess 加
第三判据+文章可见性闭包注入；N4 阅读页落 bbwfile:// 渲染换票）。IM 侧 conv_id 旧径**不动**
（行为零变化）；message 迁 file_ref（顺治 v0.1「转发第二个会话 conv_id 被覆盖」旧简化）=
终态另立登记。EXECUTION-PLAN 批次 N 已加 N8 行。
