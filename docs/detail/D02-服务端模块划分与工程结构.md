## 1. 仓库与顶层结构

Go monorepo（与客户端仓库分离，`server/`）：

```
server/
├─ cmd/
│  ├─ bbw-server/        # 模块化单体：内嵌 auth/org/message/file/doc/kb/eco/admin/audit/notify/aigw(内嵌模式)
│  ├─ bbw-gateway/       # WSS/REST 接入层（独立部署，水平扩展）
│  └─ bbw-media-ctl/     # mediasoup 控制面（API server，与 media worker 同机/同组）
├─ internal/
│  ├─ auth/ org/ message/ file/ doc/ kb/ eco/ admin/ audit/ notify/ aigw/
│  ├─ gateway/            # 连接管理、信封路由、推送扇出
│  ├─ platform/           # 公共基础设施：pg/redis/s3/kms/eventbus/middleware/i18n/errors
│  └─ version/
├─ migrations/            # golang-migrate，按域分目录（§7）
├─ deploy/                # compose / helm（16 篇）
└─ test/ contract/ e2e/   # 契约 golden JSON、RLS 强制测试、集成
```

## 2. 逻辑模块与进程映射（对应 02 篇 §3 服务清单）

| 模块 | 职责一句话 | bbw-server | bbw-gateway | 独立进程 |
|---|---|---|---|---|
| gateway | WSS 连接/信封/推送扇出/在线状态 | — | ✅ | 可与 bbw-server 同机 |
| auth | 登录/令牌/OBO/设备 | ✅ | 依赖 | |
| org | 租户/组织树/用户 | ✅ | 依赖 | |
| message | 会话/消息/seq/检索 | ✅ | 依赖 | |
| file | 分片/秒传/配额/缩略图 | ✅ | 依赖 | worker 可拆 |
| doc | 文档元数据/WOPI/版本 | ✅ | 依赖 | 转换 worker 可拆 |
| kb | 空间/摄入/检索 | ✅ | 依赖 | 摄入 worker 可拆 |
| eco | 应用/技能注册分发/连接器 | ✅ | 依赖 | |
| admin | 管理聚合 API/审批/异步任务 | ✅ | 依赖 | |
| audit | 审计事件/哈希链/检索 | ✅ | 依赖 | 锚点 job |
| notify | 通知中心/公告 | ✅ | 依赖 | |
| aigw | 模型代理/计量/脱敏 | ✅（也可独立） | — | Agent 直连它而非 gateway（14 篇 §3.3） |

拆分原则：**编译期一个 binary，部署期可按模块拆进程**（`--enable=message,file,kb` 启动参数）；拆分后模块间调用从进程内接口切换为 gRPC（接口定义不变，§4）。

## 3. 模块内部标准分层

```
internal/<module>/
├─ api/        # 对外接口定义（Go interface）+ DTO + 校验
├─ service/    # 业务逻辑（只依赖本模块 repo 与其他模块的 api）
├─ repo/       # 数据访问（sqlc 生成 + 手写事务）；唯一允许写 SQL 的层
├─ events/     # 本模块发布/订阅的领域事件声明
└─ module.go   # 依赖注入装配（构造函数注入，禁止全局单例）
```

**示例：auth 模块 api 层接口全集**（其他模块按此风格在各自模块篇定义）：

```go
type AuthService interface {
    Login(ctx, LoginReq) (*TokenPair, error)
    ExchangeSSO(ctx, provider string, code string) (*TokenPair, error)
    VerifyMFA(ctx, userID string, code string) error
    Refresh(ctx, refreshToken string, did string) (*TokenPair, error) // 轮换
    Logout(ctx, userID, did string, all bool) error
    IssueOBO(ctx, actorUserID string, agentSessionID string, scopes []string) (string, error)
    ListDevices(ctx, userID string) ([]Device, error)
    RevokeDevice(ctx, adminClaim Claims, userID, did string) error
    PublicKeys(ctx) ([]JWK, error) // /.well-known/jwks.json
}
```

## 4. 依赖规则（CI 以 import-lint 强制）

```
gateway ──► 各模块 api（转发/推送时调用）
各模块 service ──► auth api（令牌校验仅 gateway/middleware 做，模块只读 Claims）
               ──► audit events（写审计走事件总线，异步）
               ──► notify events
kb ──► aigw api（嵌入/重排）；doc ──► file api（对象引用）；eco ──► auth（OBO 校验）

禁止：
✗ 模块 A import 模块 B 的 service/repo（只能 import B 的 api）
✗ 任何模块 import gateway
✗ repo 层 import service 层
✗ 绕过 repo 直接使用 pg 句柄
```

模块间**同步调用**只允许出现在图中实线；其余需求一律走**事件总线**（§5）。

## 5. 进程内事件总线（未来替换为 NATS）

```go
type EventBus interface {
    Publish(ctx context.Context, topic string, evt any) error   // 至少一次投递
    Subscribe(topic string, handler Handler)                    // 模块装配期注册
}
```

| topic | 发布者 | 订阅者 | 用途 |
|---|---|---|---|
| msg.created | message | gateway(推送扇出)·notify·audit | 新消息 |
| msg.recalled / conv.updated | message | gateway·audit | 撤回/会话变更 |
| file.scan.completed | file | gateway·message | 扫描结果更新卡片 |
| doc.version.created | doc | gateway·kb(重摄入) | 版本事件 |
| kb.doc.ready | kb | gateway | 摄入完成推送 |
| app.version.published / app.revoked | eco | gateway·audit | 分发/撤销 |
| audit.event | 全部 | audit(落库+哈希链) | 审计 |
| policy.updated | admin | gateway | agent 策略/租户策略推送 |
| user.offboarded | admin | org·doc·kb·eco·mail | 离职联动（交接+邮箱停用，22 篇） |
| user.updated / user.dept_changed | org | gateway（org.updated / perm.changed 推送）、message（名片缓存失效） | 用户信息/异动（D12 异动引擎） |
| tenant.status.changed | admin | gateway（force.logout 广播）、各域（状态检查） | 租户停用/恢复 |

投递语义：至少一次 + 幂等消费（事件带 `event_id`，订阅方去重）；audit 事件落库失败进死信并告警（不允许静默丢失，15 篇）。

## 6. HTTP/WS 中间件链（bbw-gateway 固定顺序）

```
trace(id生成) → recovery → access-log → rate-limit(租户/用户/Agent 三档)
 → auth(Bearer 校验, 拒 1003/1004) → tenant(注入 app.tenant + RLS 会话变量)
 → perm(RBAC 权限点判定, 拒 2001) → audit-scope(标记是否落审计)
 → handler → 响应包{code,data,trace_id}（14 篇 §5.2）
```

WS 生命周期：`/ws/connect` 升级 → 同鉴权链 → 注册连接（Redis `t:{tid}:online:{uid}`）→ 订阅该用户的推送 topic（Redis pub/sub）→ 心跳（30s ping/pong）→ 断开清理（宽限 60s 内重连保留 in-flight ack）。

## 7. 数据访问规范

| 项 | 规范 |
|---|---|
| 迁移 | golang-migrate；`migrations/<域>/NNN_desc.up.sql`；表归属唯一域（13 篇表清单为准），跨域引用只按 ID 不建外键 |
| SQL | sqlc 生成类型安全查询；事务边界=service 层方法；跨库操作禁用分布式事务，用事件+幂等补偿 |
| RLS | 连接池按请求设置 `SET app.tenant`；repo 层测试强制带租户断言（15 篇 RLS 测试基类） |
| 读写分离 | 只读查询走副本（`repo.ReadOnly(ctx)`）；写必须主库 |
| 大对象 | 一律走 MinIO（S3 预签名），DB 只存 ID/摘要（13 篇 §6） |

## 8. 配置与特性开关

- 配置分层：`默认值 < 环境变量 < 配置文件 < 租户策略(admin_policy)`；热更仅租户策略层（事件 policy.updated）。
- feature_flag（16 篇表）按租户读取，客户端经登录响应携带下发。

## 9. 测试策略

| 层 | 工具与门槛 |
|---|---|
| 单元 | service 层 ≥80% 覆盖（auth/message/file/kb/eco/audit 核心域强制） |
| 契约 | golden JSON：每个 REST/WS 事件 payload 固化 `test/contract/`，前端 TS 类型与 Go DTO 同源生成，PR 双端校验 |
| RLS | 每张业务表的跨租户访问用例（15 篇），CI 阻塞 |
| 集成 | docker-compose 起全量依赖（pg/redis/minio/onlyoffice mock），关键链路：登录同步/发消息/上传/编辑/委派审计 |

## 10. 构建与发布

单二进制内嵌迁移与 admin 权限点字典；发布顺序与灰度按 16 篇（audit/notify→域服务→auth→gateway 最后；协议兼容窗口 ≥6 个月）。

## 11. 开放问题

1. gateway 拆分后推送扇出的 Redis pub/sub 是否直接换 NATS（2 万用户压测定，02 篇开放问题 1）；
2. eco 连接器转发（10 篇 §6.3）是否独立部署面（连接器故障不拖累 eco 主服务）；
3. aigw 独立部署的时机（模型流量与业务流量隔离）。
