## 1. 概述与范围

本文是 05 篇（音视频通话概要）的详细设计：页面区块级线框、交互事件级定义、rtc.* WS 事件 payload 字段级规范、REST 全参数、DDL 级数据模型、四档断点与六态逐页适配、features/rtc 文件级模块划分。

| 项 | 范围 |
|---|---|
| 覆盖页面 | PRTC-01 全屏通话窗 / PRTC-02 PiP 浮窗 / PRTC-03 来电通知 / PRTC-04 设备设置 / PRTC-05 通话中邀请面板 / PRTC-06 通话历史页 |
| 覆盖能力 | 1v1 与群通话全生命周期（主叫/被叫双视图状态机）、屏幕共享、布局管理、弱网降级、媒体节点迁移、通话卡片、质量上报 |
| 不在本文 | 预约会议与录制纪要（阶段四，`rtc:meeting:schedule` / `rtc:record:start` 仅保留权限点登记）；PSTN/直播；消息卡片渲染框架本身（D03） |
| 窗口体系 | 通话全屏窗/PiP 沿用 D01 §3；路由沿用 D01 §4.2（/rtc、/rtc/history、/rtc/settings） |

**术语沿用 05 篇**：call_session（逻辑房间）、Router / WebRtcTransport / Producer / Consumer（mediasoup 对象）、simulcast 三层（f=1080p30 / m=720p15 / l=180p8）、P2P 直连、SFU 转发、TURN relay 兜底、回铃音、多端响铃（answered_elsewhere）、单设备单活动通话。不引入新概念。

## 3. 页面详细设计

### 3.1 PRTC-01 通话全屏窗

**布局三态**（layoutStore.mode：`auto` 自动跟随 / `grid` 九宫格 / `speaker` 演讲者 / `focus` 1v1 大图）：

```
状态A: 1v1 大图（两人或手动固定）
┌──────────────────────────────────────────────────────────────┐
│ ①状态栏: ●通话中 12:34 · P2P/SFU ｜ ②弱网指示 ●良 ｜ [⇱布局▾][⚙][_最小化] │
│ ┌──────────────────────────────────────────────────────────┐ │
│ │            ③ 主画面（对方视频/共享内容，镜像关）              │ │
│ │            右下角 ④ 画中画小窗（自己，可拖到四角）            │ │
│ └──────────────────────────────────────────────────────────┘ │
│ ⑤控制条: [🎤静音][📹摄像头][🖥共享屏幕][⚙][📞挂断(红)]          │
└──────────────────────────────────────────────────────────────┘

状态B: 九宫格（3–16 人，2×2…4×4 自适应 + 翻页）
┌──────────────────────────────────────────────────────────────┐
│ ① …同上                                                     │
│ ┌────────┐┌────────┐┌────────┐┌────────┐                    │
│ │⑥参与者瓦片││⑥       ││⑥       ││⑥ +9 翻页│  ← 无视频者显示头像  │
│ └────────┘└────────┘└────────┘└────────┘                    │
│ ⑤控制条: [🎤][📹][🖥][👥成员(5/12)+邀请][⇱][⚙][_][📞]          │
└──────────────────────────────────────────────────────────────┘

状态C: 演讲者（>2 人默认，含共享时强制）
┌──────────────────────────────────────────────────────────────┐
│ ┌────────────────────────────────────────────┐ ┌⑦胶片条─────┐ │
│ │      ③ 演讲者大画面（自动跟随音量/手动📌固定）  │ │▏瓦片(180p) │ │
│ │      共享画面出现时替换为共享内容（1440p f层）   │ │▏…横向滚动  │ │
│ └────────────────────────────────────────────┘ └────────────┘ │
│ ⑤控制条 …                                                   │
└──────────────────────────────────────────────────────────────┘
```

| 区块 | 内容与行为 |
|---|---|
| ①状态栏 | 呼吸点+状态文案（见 §4.2 状态表）+ 计时（服务端 connected_at 起算，本地每秒刷新）+ 当前模式徽标（P2P/SFU） |
| ②弱网指示器 | 三档色点（良/中/差），点开浮层显示 RTT/丢包/码率实时值（statsCollector 5s 窗口） |
| ③主画面 | 焦点视频流；共享存在时共享优先占位；双击切换全屏/布局 |
| ④画中画小窗 | 自己画面 176×99，可拖至四角吸附，拖出=切回九宫格 |
| ⑤控制条 | 见 3.1.2 组件；挂断为红色主按钮，直径 48px |
| ⑥参与者瓦片 | 见 3.1.1 组件 |
| ⑦胶片条 | 180p 低层订阅；横向滚动；当前发言者瓦片高亮；点击=📌固定到主画面 |

**布局自动切换规则**（layoutStore）：

| 条件 | 目标布局 | 可被用户覆盖 |
|---|---|---|
| 2 人 | focus（1v1 大图） | 可切 grid |
| 3–16 人无共享 | speaker（>4 人）或 grid（≤4 人） | 可手动锁定 |
| 任一参与者开始共享 | 强制 speaker，共享内容占主画面 | 停止共享后回到上次布局 |
| 发言者变化（音量>阈值 800ms） | speaker 模式主画面自动跟随 | 已📌固定则不跟随，固定标识常显 |

#### 3.1.1 参与者瓦片（ParticipantTile）

| 元素 | 说明 |
|---|---|
| 视频/头像 | 有 cam 流显视频（grid 取 m 层）；无则头像（48px）+ 姓名 |
| 音频波形动效 | 说话时瓦片边框主色呼吸 + 底部 4 条能量柱（AnalyserNode 采样，静音轨道不订阅） |
| 静音标 🔇 | mic 关闭常显右下角 |
| 弱网标 ⚠ | 该成员下行质量差（loss>10%）时左下角黄色角标 |
| 发言高亮 | 当前最大音量者边框 2px primary |
| 名字+设备徽标 | 多端加入者显示 "手机/桌面" 徽标 |
| hover 操作 | 🎌固定到主画面 / 🔇远程静音提示（仅通知，不强制） |
| 自己的瓦片 | 镜像开启；"你"标签 |

#### 3.1.2 控制条（ControlBar）

| 按钮 | 图标态 | 行为 |
|---|---|---|
| 静音 🎤/🔇 | 开=🎤 闭=🔇(红斜杠) | 即时 track.enabled 切换（§4 INT-RTC-11），不发信令（SFU 侧静音轨道不消费） |
| 摄像头 📹 | 同上 | 即时开关；关闭后瓦片转头像 |
| 共享屏幕 🖥 | 激活=主色填充 | 打开选择器（3.1.3）；激活中再点=停止 |
| 成员 👥 | 徽标 (5/12) | 打开成员列表面板（含被邀请振铃中/已拒绝状态分组）+ [+] 邀请入口 |
| 布局 ⇱ | 下拉 | auto/grid/speaker/focus 四选；focus 仅 1v1 可选 |
| 设置 ⚙ | — | 打开 PRTC-04 抽屉态 |
| 最小化 _ | — | 切 PiP（INT-RTC-09） |
| 挂断 📞 | 红底白图标 | connected 态：单击弹确认气泡"结束通话？[挂断][取消]"（防误触）；未接通态（dialing/ringing/connecting）单击直接挂断 |

#### 3.1.3 屏幕共享选择器（ScreenSharePicker）

| 分组 | 内容 |
|---|---|
| 整个屏幕 | 每块显示器缩略预览（含多屏） |
| 窗口 | 应用窗口缩略列表（按最近使用排序） |
| 标签页 | 仅浏览器内共享场景（WebView 内页面，阶段一隐藏，预留） |
| 底部 | ☑ 同时共享系统声音（平台支持时）· [取消] [开始共享] |

选择"整个屏幕"时提示共享隐私风险横幅（"共享中请勿展示敏感信息"）。仅 1 人可共享：已有他人共享时按钮置灰并提示"张三正在共享"。

**数据绑定**：视频流 ← RtcEngine consumer 订阅（§5.3 订阅规则）；成员/状态 ← callStore（rtc.state 事件驱动）；质量 ← statsCollector。不落 TanStack Query（通话运行态为端内瞬态）。

**六态表**（通话窗是过程视图，六态语义适配如下）：

| 态 | 触发 | 表现与允许操作 |
|---|---|---|
| loading | connecting 态 | 呼叫中状态环（3.1.4）+ 连接中对端头像；可取消 |
| empty | — | 不适用（必有对端/成员） |
| error | 设备失败 5008 / ICE 失败 5005 | 错误横幅+文案+「重试/以音频继续」；错误码映射 D01 §7 |
| offline | WSS 断开（媒体面未断） | 顶部横幅"信令连接中…"（媒体照常，控制信令排队） |
| forbidden | 5011 非成员 / 5012 策略禁用 / rtc.state{removed} | 提示+自动退出通话，无申请入口 |
| degraded | 弱网档位=中/差 | 弱网横幅（3.1.5）+ 自动降级动作；可手动恢复视频 |

### 3.2 PRTC-02 PiP 浮窗

```
┌────────────────────────┐   默认 320×180，always-on-top；
│     对方/共享画面        │   悬停 300ms 展开控制：
│ 12:34 ●良   (点击=还原)  │   [🎤][📞][⤢还原] 三钮浮层
└────────────────────────┘   未悬停时仅画面+计时
```

| 项 | 规则 |
|---|---|
| 内容 | 优先级：共享内容 > 对方（focus 逻辑同 PRTC-01）> 自己 |
| 拖拽 | 全窗可拖；松手时若距屏幕边缘 <32px → 吸附该边缘（留 4px 视觉边）；位置持久化（rtc_pip_state） |
| 置顶 | Tauri always_on_top；不抢主窗焦点（D01 §3） |
| 还原 | 点击非控件区 / ⤢ 按钮 / 主窗"通话中"横幅点"回到通话" |
| 消息通知 | PiP 态系统通知照常（不因通话抑制，勿扰规则走 D01 §8） |
| 六态 | 与 PRTC-01 同源（共享 store）；仅显示 degraded 色点，不展开横幅 |

### 3.3 PRTC-03 来电通知（双形态）

```
形态一：应用内来电窗（主窗前台时）           形态二：系统横幅（主窗后台/最小化）
┌ 来电 ────────────────────┐        ┌────────────────────────────┐
│      ┌────┐              │        │ [头像] 张三 · 视频通话       │
│      │头像 │  李四         │        │        产品研发群 · 3人在通话 │
│      └────┘  视频通话      │        │ [拒接]  [接听]              │
│   产品研发群 · 已有3人     │        └────────────────────────────┘
│ [💬短信回复(预留·禁用)]     │        点击横幅本体=聚焦应用并转形态一
│   [拒接]      [接听]      │        （未处理且仍在振铃时）
└────────────────────────┘
```

| 元素 | 说明 |
|---|---|
| 头像/主叫 | 发起人头像 72px + 姓名 + 通话类型图标；群通话附"群名 · 已有 N 人" |
| 接听 | 绿色 56px；call_type=video 时长按切换"以语音接听"（子菜单） |
| 拒接 | 红色 56px → rtc.reject{reason:declined} |
| 忙线短信回复 | **预留按钮**：disabled + tooltip"即将上线"；不发明新协议，后续复用 msg.send |
| 多端联动 | 任一端处理（接听/拒接/主叫取消）→ 本端收 rtc.state{answered_elsewhere / canceled} → 窗/横幅自动收起 |
| 超时 | 振铃 45s 服务端 no_answer → 自动收起，转未接来电通知 |
| 形态规则 | 主窗聚焦→形态一；后台/托盘→形态二（设置-通知可固定一种）；形态二经系统通知 action 按钮直接接听/拒接 |

**六态**：来电为瞬态推送视图，无 loading/empty/forbidden；error=主叫已取消或会话不存在（5010，自动收起）；degraded 不适用。

| 区块 | 说明 |
|---|---|

## 4. 交互详细设计

### 4.1 INT-RTC 交互事件表

### 4.2 通话全生命周期状态机（callStore 单一状态源，双视图）

```
主叫视图:  idle → dialing → ringing → connecting → connected ⇄ reconnecting → ended
被叫视图:  idle → ringing → accepting → connecting → connected ⇄ reconnecting → ended
迁移触发（沿 05 §4.2/4.3，超时: 振铃45s / connecting 10s / reconnecting 10s / 通话4h租户可配）
```

**各状态可操作集**（未列出=禁用）：

| 状态 | 进入条件 | UI 表现 | 可操作集 |
|---|---|---|---|
| idle | 无通话 | — | 发起通话（INT-RTC-01/02） |
| dialing（主叫） | invite 已发未获振铃回执 | 状态环"正在等待…"+回铃音 | 取消(04)、切换 Mic/Cam 预置、最小化 |
| ringing（主叫） | 收到对端振铃回执 | 状态环"对方振铃中…" | 同 dialing |
| ringing（被叫） | rtc.ringing | PRTC-03 通知+铃声 | 接听(05)、拒接(06)、静音铃声（仅本地）、以语音接听 |
| accepting（被叫） | 已发 accept | "正在接通…" | 取消（=reject 兜底，竞态以服务端为准） |
| connecting | accept/升级 SFU 后 ICE/DTLS 进行中 | 状态环+对端头像 | 挂断、最小化；Mic/Cam 可预切换（生效于 connected） |
| connected | 媒体建立 | 全功能界面+计时 | 静音/摄像头/共享/布局/邀请/成员/设置/PiP/挂断(确认) |
| reconnecting | 断流>1s（ICE restart/迁移） | 弱网横幅"正在重连…(Ns/10s)" | 静音/挂断；其余只读；恢复自动回 connected |
| ended | bye/超时/对端离开/迁移失败 | 结束页 3s（时长+原因）→ 关窗；落卡片 | 回拨、关闭 |

**迁移补充表**：

| from → to | 触发 | 附注 |
|---|---|---|
| dialing/ringing → ended | 45s no_answer / cancel / reject / busy | 原因分别落卡片文案：未接听/已取消/对方已拒绝/对方忙线 |
| connecting → ended(failed) | 10s ICE 未成（5005） | 提示"连接失败 [重试][反馈]"，重试=重新 invite |
| connected → reconnecting | RTP 断流>1s / rtc.call.moved | ICE restart 或新节点重建；≤10s |
| reconnecting → ended | 10s 未恢复 | network_lost；群卡片标"网络中断退出" |
| connected → ended | bye/对端全部离开/4h 到点（先 60s 倒计时提示）/removed | 服务端 ended_at 为计时权威 |
| P2P → SFU（connected 内） | P2P 劣化或 3s 未成 | 双活 ≤2s 切换，徽标 P2P→SFU；单向不回退 |

## 5. 接口详细设计

### 5.1 WS 事件（rtc.*，信封沿 14 篇 §2.2）

**rtc.call.invite（c→s，请求）** —— 幂等键 call_id（14 篇 §5.3）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| call_id | string | ✅ | 客户端生成（UUID），重试不换 |
| conv_id | string | ✅ | 关联会话（卡片落此会话） |
| call_type | int | ✅ | 1 音频 2 视频 |
| invitees | string[] | ✅ | 首批被叫 uid；群内发起=全部成员（由服务端展开）或指定子集 |
| media | object | ✅ | {audio:true, video:true} |
| offer | string | — | 1v1 直附 SDP offer（省一轮 RTT） |

```json
{ "v":1, "id":"c-1001", "type":"rtc.call.invite", "ts":1760000000000,
  "payload":{ "call_id":"ca-9f2a", "conv_id":"cv-77", "call_type":2,
    "invitees":["u-201","u-202"], "media":{"audio":true,"video":true},
    "offer":"v=0..." } }
// ack
{ "v":1, "id":"s-8801", "ack":"c-1001", "type":"rtc.call.invite.ack", "code":0,
  "payload":{ "call_id":"ca-9f2a", "part_total":2 } }
```

**rtc.accept（c→s）**：`{call_id✅, answer(SDP，群/SFU 场景可空) —, did✅}`；ack 返回 `{room?{router_id, transports:[…join 凭证]}}`。
**rtc.reject（c→s）**：`{call_id✅, reason✅(declined\|timeout_local\|replace)}`。
**rtc.call.cancel（c→s，本篇沿用 05 新增）**：`{call_id✅}`（仅振铃阶段）。
**rtc.call.busy（c→s，自动）**：`{call_id✅, did✅}`（本端已有活动通话时引擎自动发）。
**rtc.bye（c→s）**：`{call_id✅, reason✅(normal\|replace\|network_lost\|…)}`。
**rtc.signal（c→s/s→c，双向转发不落库）**：

| 字段 | 类型 | 说明 |
|---|---|---|
| call_id | string | 归属通话 |
| to | string | 目标端 did（服务端转发填入；1v1 P2P 为对端 did） |
| kind | string | sdp / candidate / restart / join_room / migrate |
| data | object | kind=sdp→{sdp, type}; candidate→{candidate, sdpMid, sdpMLineIndex}; join_room/migrate→{transport_id, dtlsParameters, rtpCapabilities…} |

**rtc.ringing（s→c 推送）**

| 字段 | 类型 | 说明 |
|---|---|---|
| call_id / conv_id | string | — |
| call_type | int | 1/2 |
| initiator | object | {uid, name, avatar} |
| group | object | 群通话：{conv_name, ongoing:true, member_count, elapsed_s} |
| members | array | 已在通话成员 [{uid,name}]（群） |
| offer | string | 1v1 附带 |
| ring_id | string | 本次振铃标识（多端一致，用于 45s 对齐） |

**rtc.state（s→c 推送，判别联合）**：公共字段 `{call_id✅, kind✅, ts✅}` +：

| kind | 附加字段 | 说明 |
|---|---|---|
| member_joined | {user:{uid,name}, did, media:{mic,cam,screen}} | 成员（或同用户新设备）加入 |
| member_left | {uid, did, reason(normal\|network\|replace\|removed)} | 离开 |
| media_changed | {uid, did, media:{mic,cam,screen}} | 静音/摄像头/共享变化广播 |
| answered_elsewhere | {did} | 他端已接听，本端停响 |
| canceled | — | 主叫取消 |
| no_answer | {ring_id} | 45s 超时（主叫 ended；被叫转未接通知） |
| removed | {reason} | 被移出会话，强制退出 |
| stats | {member_count, elapsed_s} | 进行中卡片实时态（≤5s 一推，仅群通话未加入者收） |
| mode_changed | {mode(p2p\|sfu)} | 1v1 升级 SFU 通知（对端校准徽标） |
| ended | {duration, end_reason, card_msg_id} | 终态（含 card_msg_id 供 D03 落卡片） |

**rtc.call.moved（s→c 推送，05 新增沿用）**：`{call_id✅, new_node{id,url}✅, room_token✅, deadline_ms=3000, fallback:"p2p" —}`。

### 5.3 mediasoup 房间概念（接口背景，非客户端直连 API）

call_session=逻辑房间 → 每节点每通话 1 Router → 每参与者 WebRtcTransport（上行 1+下行 1）→ Producer（audio：Opus 不分层；video：simulcast×3；screen：单层 1440p）/ Consumer 按订阅分发。客户端经 rtc.signal(kind=join_room) 用 rtpCapabilities 协商 consumer；Transport 凭证由 accept/加入 ack 发放，迁移时 room_token 复用免重邀。

**simulcast 订阅规则（布局驱动）**：

| 消费场景 | 订阅层 |
|---|---|
| 演讲者主画面 / 共享 | f（1080p30；共享 1440p） |
| 九宫格前排（≤8） | m（720p15） |
| 九宫格后排/胶片条/后台参与者 | l（180p8，仅音频+小流） |
| 弱网档位=中/差 | 端侧请求 preferredLayer 降档；层切换 <500ms 无黑帧 |

上行恒三层同发（带宽不足端侧先降高层帧率/分辨率）；拥塞牺牲顺序按 05 §5.3，音频最后。

## 6. 模型设计

### 6.1 服务端 PG（迁移目录 migrations/rtc/；RLS 同全局约定）

```sql
CREATE TABLE call_session (
  id             BIGINT PRIMARY KEY,                  -- 雪花 call_id
  tenant_id      BIGINT      NOT NULL,
  conv_id        BIGINT      NOT NULL,
  call_type      SMALLINT    NOT NULL,                -- 1 audio 2 video
  mode           SMALLINT    NOT NULL DEFAULT 1,      -- 1 p2p 2 sfu（终态，迁移记 history）
  room_id        TEXT,                                -- media-svc Router 标识
  media_node_id  TEXT,                                -- 当前媒体节点（迁移时更新）
  initiator_id   BIGINT      NOT NULL,
  status         SMALLINT    NOT NULL DEFAULT 1,      -- 1 ringing 2 ongoing 3 ended 4 missed 5 canceled
  ring_at        TIMESTAMPTZ NOT NULL DEFAULT now(),
  connected_at   TIMESTAMPTZ,
  ended_at       TIMESTAMPTZ,
  duration       INT         NOT NULL DEFAULT 0,      -- 秒 connected→ended
  end_reason     TEXT,                                -- normal/no_answer/canceled/rejected/busy/
                                                     -- failed/network_lost/node_moved_final/timeout
  max_member_count INT       NOT NULL DEFAULT 0,
  card_msg_id    BIGINT                               -- 通话卡片消息回链（04 篇）
);
CREATE INDEX idx_call_conv   ON call_session (tenant_id, conv_id, ring_at DESC);
CREATE INDEX idx_call_tenant ON call_session (tenant_id, ring_at DESC);

CREATE TABLE call_member (
  id           BIGINT PRIMARY KEY,
  call_id      BIGINT      NOT NULL REFERENCES call_session(id),
  tenant_id    BIGINT      NOT NULL,
  user_id      BIGINT      NOT NULL,
  device_id    TEXT        NOT NULL,                  -- 每人每设备一行
  state        SMALLINT    NOT NULL DEFAULT 1,        -- 1 invited 2 ringing 3 joined 4 left 5 rejected 6 busy 7 missed
  joined_at    TIMESTAMPTZ,
  left_at      TIMESTAMPTZ,
  media_flags  SMALLINT    NOT NULL DEFAULT 0,        -- bit0 mic bit1 cam bit2 screen
  quality      JSONB                                -- {avg_rtt_ms,avg_loss,avg_bitrate_kbps,downgrade_events}
);
CREATE UNIQUE INDEX uq_member_dev ON call_member (call_id, device_id);
CREATE INDEX idx_member_call ON call_member (call_id, state);
CREATE INDEX idx_member_user ON call_member (tenant_id, user_id, joined_at DESC);
```

## 9. 边界与异常

| 场景 | 处理 |
|---|---|
| 设备被占用（5008） | 提示"摄像头/麦克风被占用"→可先以音频加入；deviceManager 热插拔自动恢复 |
| 17 位视频/65 音频（5002） | 被邀端提示"视频席位已满"自动音频加入；纯音频满员拒绝并 toast |
| 主叫取消 vs 拒接竞态 | 以服务端状态机为准（accept 后到达的 cancel 不生效，回 bye） |
| 被移出会话（removed） | rtc.state{removed} → 自动退出+提示；后续 invite 对其不达（成员失效） |
| 4h 上限 | 提前 60s 双端倒计时横幅"通话即将到时结束"，到点服务端 ended(timeout) |
| 群无人 30s | 服务端自动 ended；卡片时长以最后成员 left_at 结算 |
| WSS 断开但媒体在 | 信令进 offline 横幅；ICE/媒体自愈不受影响；重连后补拉 rtc.state 终态 |
| 多端替换 | 旧端收 bye(reason=replace) → toast"已在其他设备接听" |
| 未知 rtc.* 事件/字段 | 前向兼容：忽略+埋点上报（14 篇 §8） |

## 10. 开放问题

1. 端侧 `media_flags` 与服务端广播的最终一致性窗口（本地切换即时、广播 ≤1s）在弱网下卡片标记可能短暂回跳，是否需要乐观锁版本号。
2. `rtc.state{stats}` 推送频率（现定 ≤5s）对万人租户网关扇出压力需压测（16 篇联调）。
3. 群通话全空自动结束的 end_reason 归一化（normal vs 新增 all_left）——涉及 04 篇卡片文案，需与 D03 对齐后回填 05 篇枚举。
4. 来电"挂断并接听"跨通话切换的信令竞态（bye 未 ack 即 accept）是否需要服务端原子支持。
5. PiP 是否跟随系统原生画中画 API（macOS 15 PiP 窗口）以获得更优体验，需评估 Tauri 支持。
6. 通话记录"删除我的一段记录"（05 开放问题 4）客户端入口是否提供，待 12/15 篇合规结论。
