# D21 · 自动更新与官网发布链详细设计

> 状态：2026-11-12 实施落地（批次 K；J1-J4 编码完成，真机验收待做）。
> 对应概要篇：[16-部署运维与非功能设计](../16-部署运维与非功能设计.md) §4/§5（本篇为其落地形态，差异处以本篇为准）。
> 关联篇：[15-安全设计](../15-安全设计.md) §3.1（证书口径）、[D01](D01-客户端总体详细设计.md)（关于页）。

## 0. 背景与决策

需求三件套：① 三平台桌面应用自动检查→下载→更新；② 官网（功能介绍 + 未来规划 + 各平台安装包下载）；③ 打包方式支持环境变量指定后台服务地址、应用自带。

**拍板决策（2026-11-12，用户裁决）**：

| 决策 | 结论 | 备注 |
|---|---|---|
| 传输协议 | **v0.1 统一 http（内网明文）**，https 以后再加 | 免 CA 生成/分发/续期全套；bbrt 手写 HTTP 客户端免 TLS 改造（原 P0 阻断项直接消失） |
| 平台签名 | 不买证书（macOS 临时签名 + Windows 无 Authenticode） | 安装包完整性由 Tauri updater minisign 签名保证，与平台代码签名无关 |
| macOS 架构 | x86_64 + aarch64 双出 | updater 清单分 `darwin-x86_64`/`darwin-aarch64` 两键 |
| 构建执行 | 三台对应系统机手动跑发布脚本 | CI 矩阵为二期 |
| 官网托管 | 同域名根路径（复用 nginx-lb，http://域名/） | 下载直链与 /update/ 同源 |

**为什么不是「应用忽略证书校验」**（设计澄清，2026-11-12）：webview 主流量（登录/API/WS）走系统信任库无法豁免，机器装 CA 躲不掉；既然统一 http 后此问题整体消失，bbrt 随包 pin CA / updater dangerous 开关均**不做**，登记为转 https 阶段事项（§7）。

## 1. 打包注入链：单变量 BBW_PUBLIC_URL

发布出包唯一开关 `BBW_PUBLIC_URL`（如 `http://bbw.example.internal`，不带路径），三条链路一次注入：

| 链路 | 注入点 | 机制 |
|---|---|---|
| 前端 REST/WS | `VITE_API_BASE=$BBW_PUBLIC_URL/api/v1` | build-desktop 写临时 `client/.env.production`（gitignored，构建完清理；WS 由 `resolveWsBase()` 推导 ws://，零改动） |
| 壳→bbrt 网关 | `BBW_DEFAULT_GATEWAY`（编译期） | `build.rs` 读 env 注入（仿 BBW_TARGET_TRIPLE 先例）；`agent_bridge.rs` 缺省链：进程 env `BBW_RT_GATEWAY` > `option_env!("BBW_DEFAULT_GATEWAY")` > `127.0.0.1:8090`（本地联调语义不变） |
| updater 端点 | `endpoints=[$BBW_PUBLIC_URL/update/latest.json]` | 临时 `tauri.release.conf.json` 经 `tauri build --config` 合并——真实域名不进仓库 |

**macOS ATS**：WKWebView 对非 localhost 明文请求默认拦截（dev 走 localhost 豁免掩盖）——`client/src-tauri/Info.plist` 放开 NSAppTransportSecurity（Tauri v2 自动合并同目录 plist），转 https 后删文件即可。

**Windows 产物收敛**：`tauri.windows.conf.json` 平台覆盖 `bundle.targets=["nsis"]`（updater 只认 NSIS；MSI 弃出）。

**版本管理**：`scripts/release/set-version.sh <ver> [--tag]` 一把改齐四处版本（client/package.json、tauri.conf.json、壳 Cargo.toml、agent workspace Cargo.toml）+ Cargo.lock 离线随动 + git tag。

**产物布局**（按 updater 平台键分目录，防双 mac 架构 `.app.tar.gz` 同名撞名）：

```
out/release/v<ver>/
├── darwin-x86_64/    BaobaoWork.app.tar.gz(+.sig) · *.dmg
├── darwin-aarch64/   同上
├── linux-x86_64/     *.AppImage(+.sig) · *.deb
├── windows-x86_64/   *-setup.exe(+.sig)
├── latest.json       Tauri updater 标准清单（gen-manifest 生成）
├── release-info.json 官网数据源（gen-manifest 生成）
└── RELEASE-NOTES.md  更新说明（可选，gen-manifest 自动拾取）
```

## 2. 自动更新链路

**启用条件**：`tauri.conf.json plugins.updater.pubkey` 非空（壳 `lib.rs` 条件注册——空则禁用并打启动提示）。首次启用步骤：

```bash
cd client && npm run tauri signer generate -- -w ~/.tauri/bbw-updater.key   # 口令自设
# 私钥+口令用户保管不入库；把生成的 pubkey 填入 tauri.conf.json plugins.updater.pubkey
```

出包机环境变量：`TAURI_SIGNING_PRIVATE_KEY`（内容或路径）+ `TAURI_SIGNING_PASSWORD`；缺失时 build-desktop 拒绝（`BBW_ALLOW_UNSIGNED=1` 可出无签名试包，仅本地试装不可发布）。

**客户端流程**（J2 落地）：

- 静默检查：App 挂载 3s 后首查 + 每 6h 复查（16 篇 §4.2 口径）；发现新版 → 系统通知（复用 notification 插件）+ 关于页状态；版本去重防重复弹；下载中/待装不再打扰。
- 手动入口：设置 · 关于（AboutPage UpdateCard）：检查更新 → 下载（进度条，total 未知走不定态）→ 重启并安装（`install()` + plugin-process `relaunch()`）。
- 降级矩阵：非 Tauri 宿主（浏览器 dev/mock）与插件未注册（pubkey 空）→ 报错/静默不炸；Linux deb/rpm（非 AppImage）`install()` 失败 → 错误 + 官网下载引导（Tauri 限制：仅 AppImage 支持应用内自更新）。

**降级攻击缓解**：出包覆盖配置开 `requireSignedVersion: true`——minisign 可信注释携带版本且受签名保护，配 http 明文 manifest 下「伪造 version 字段 + 旧版合法签名包」的降级攻击被拒（插件 2.14+ 支持；我们的发布从零起签，无存量兼容问题）。

**传输安全口径**：`dangerousInsecureTransportProtocol: true`（http 端点放行）随 BBW_PUBLIC_URL scheme 自动判定；`dangerous_accept_invalid_certs` 不开（转 https 后亦按正常校验）。

## 3. 服务器侧（deploy/compose）

**nginx-lb 路由表**（80 主入口全明文 + 443 保留）：

| 路径 | 80（http） | 443（https 保留） | 后端 |
|---|---|---|---|
| /healthz | ✓ | — | nginx 本地 |
| /api/ | ✓ | ✓（既有） | app×2（ip_hash） |
| /ws/ | ✓（升级头） | ✓（既有） | app×2 |
| /v1/ | ✓ | ✓ | app×2——aigw OpenAI 兼容（bbrt 生产链路；SSE 关缓冲 + 300s 读超时） |
| /mcp/ | ✓ | ✓ | app×2——MCP 网关（POST /mcp/corp） |
| /update/ | ✓ | ✓（既有） | update-src |
| / | ✓（官网） | ✓ | website |

> /v1/、/mcp/ 此前无路由——生产包 bbrt 走 `BBW_PUBLIC_URL` 网关必 404（服务端 main.go 根路径早有挂载，纯接入层缺口）；本批收口。helm ingress 同步补 path（chart 不含官网/更新源，登记 TODO）。

**update-src 转正**：bind 卷 `deploy/compose/volumes/updates/`（rsync 可写；原具名卷 + 内联占位 manifest 退役）；内联 nginx conf：`=latest.json`/`=release-info.json` no-store（每发即变），`/releases/` immutable 长缓存（按版本不可变），`/update-ok` 健康探测与发布物解耦。

**website 服务**（新）：nginx-alpine + bind 卷 `volumes/website/`；未发布时根路径 try_files 回落占位提示；`/website-ok` 健康探测。

**服务器侧 URL 布局**（发布产物）：

```
http://<域名>/update/latest.json                      ← updater 清单（no-store）
http://<域名>/update/release-info.json                ← 官网数据源（no-store）
http://<域名>/update/releases/v<ver>/<platform>/<file> ← 安装包（immutable）
http://<域名>/                                          ← 官网
```

## 4. 官网（website/，新顶层工程）

- Vite + React + TS 纯静态单页（无 antd 手写样式，中文）：Hero / 功能特性（九卡，源=docs/00 现状口径）/ 路线图（近期·中期·远期；**不含已裁决关闭项**：移动端/外网接入/音视频会议）/ 下载区 / 页脚。
- 下载区**运行时 fetch `/update/release-info.json`**（同源）——发新版官网自动跟进，无需重建站；失败回落「暂未发布」占位。
- 平台卡片：按平台聚合（mac 双架构/Linux/Windows），粗粒度 UA 识别高亮「推荐」；过滤 `.app.tar.gz`（updater 专用中间产物不外露）；macOS 首装右键打开指引、Windows 无 Agent 功能说明、deb 手动升级说明随卡展示。
- 门禁：Makefile `verify-website` / `verify-quick` + `.workflow/verify.yml` website-gate（tsc + vite build）。

## 5. 发布操作手册

**首次启用**（一次性）：

1. 出签名密钥（§2）→ pubkey 填 `tauri.conf.json` → 提交。
2. 部署机：拉最新 compose（website/update-src/nginx 路由生效）→ `mkdir -p volumes/updates volumes/website`。
3. 官网首发：`BBW_DEPLOY_HOST=... BBW_DEPLOY_ROOT=... bash scripts/release/publish-website.sh`。

**例行发版**（三平台机各跑后汇总）：

```bash
bash scripts/release/set-version.sh 0.2.0          # 四处版本 + git tag
# macOS 机：
BBW_PUBLIC_URL=http://<域名> TAURI_SIGNING_PRIVATE_KEY=... TAURI_SIGNING_PASSWORD=... \
  bash scripts/release/build-desktop.sh             # 默认双架构
# Linux 机 / Windows 机：同上（ps1）
# 任一汇集机：
BBW_PUBLIC_URL=http://<域名> node scripts/release/gen-manifest.mjs --notes "更新说明"
BBW_DEPLOY_HOST=... BBW_DEPLOY_ROOT=... BBW_PUBLIC_URL=http://<域名> \
  bash scripts/release/publish.sh                   # 齐套校验→rsync→回读验证
```

**脚本清单**（scripts/release/）：`set-version.sh` · `build-desktop.sh`（mac/Linux） · `build-desktop.ps1`（Win） · `gen-manifest.mjs` · `publish.sh` · `publish-website.sh`。

## 6. 风险登记

| 风险 | 口径 |
|---|---|
| 内网明文传输（令牌/IM/manifest） | 用户拍板简单优先；安装包完整性 minisign 兜底；requireSignedVersion 拒降级攻击 |
| macOS 无 Developer ID | 首装右键打开（官网指引）；应用内更新下载不触发隔离属性，不受影响 |
| Windows SmartScreen「未知发布者」 | 内部分发可接受；Windows 包无 bbrt（既有决策），官网下载区注明 |
| Linux deb 无自更新 | AppImage 全自动；deb 引导官网 |
| updater native-tls / 证书兼容 | 转阶段问题——v0.1 http 下不存在 |
| 80 端口暴露面 | 仅官网静态 + 安装包 + 更新清单，无敏感数据 |

## 7. 未来转 https（三步走，纯增量零返工）

1. bbrt 补 TLS（`bbrt-aigw`/`bbrt-mcp` 手写传输层引 rustls，机器装 CA 或随包 pin CA——docs/15 §3.1 口径）；
2. 服务端证书与机器信任分发（CA 一次安装：钥匙串/certutil/update-ca-certificates）；
3. `BBW_PUBLIC_URL` 换 https 重新出包（客户端 Info.plist ATS 例外删除；nginx 443 块与路由已就绪）。

## 8. 验收清单（真机走查，登记 EXECUTION-PLAN 批次 K）

1. 出 v0.1.0 包装机（macOS 双架构：Intel 与 M 机器各一）；
2. 服务器 publish 一个 v0.1.1（可低配：手动放包验证 manifest 链路）；
3. 启动静默提示 + 关于页手动检查 → 下载进度 → 重启升级 → 版本变化；
4. Windows NSIS passive 升级、Linux AppImage 升级与 deb 引导文案；
5. 生产包 bbrt 走 `http://<域名>/v1` 网关跑通 IM agent 卡（审批/提问真机联动）；
6. `http://<域名>/` 官网可访问、下载区随发布自动更新版本号与直链。
