> 状态：2026-11-19 拍板即实施（当日编码）。
> 定位：**记忆形态的状态扩展**——不新增存储/协议/UI，进度就是一条普通项目记忆条目。兑现 [D23](D23-Agent记忆系统升级详细设计.md) 拍板 #10 预留的「状态类扩展位」（补采集话术+写入规则，零 schema 迁移）。
> 上游：[D15](D15-Agent记忆双轨与日报详细设计.md)（知识记忆文件族/W1-W3 写入路径）、[D19](D19-Agent项目与日常对话及记忆分级详细设计.md)（项目分区/作用域路由）、[D23](D23-Agent记忆系统升级详细设计.md)（公共层预算/状态类延后）。

## 0. 背景与拍板（2026-11-19，用户裁决，勿重提）

现有两层记忆都是**事实库**（公共层 USER.md=用户习惯/风格/要求；项目 MEMORY.md=可泛化知识/教训），不存「进行态」——跨会话新开会话时 agent 不知道上次做到哪、下一步、未完成项和本任务的坑（ZCode 用项目记忆充当工作台账补的就是这块，实测其代价=170KB 死文件/25.6KB 索引/2.7KB 索引行，即 D23 背景三条退化）。

| # | 决策 | 结论 |
|---|---|---|
| 1 | 承载形态 | **一条普通项目记忆条目**（`MemoryType::Status`），复用 `KnowledgeStore::save`（同题更新/原子写/脱敏/索引）；不建 ledger 目录/progress.json/新 Store/新协议/新 UI |
| 2 | 粒度 | **完全扁平五段**：待办/已做/阻塞/决策/坑；无目标字段、无线程、无 thread_id、无任务选择；多任务并行=条目自带任务名前缀（如 `11-19 D35：批0-4 已推 697707c`） |
| 3 | 写入触发 | **仅会话结束自动**（W3 一次调用双产出）；不做 progress_update 工具，`memory_save` 显式拒绝 type=status |
| 4 | 可见性 | **仅注入模型**（`[记忆]` 块第三段 `[项目进度]`）；无 UI/事件新增（复用 memory.saved 回执） |
| 5 | 内容 | 台账**含本任务决策与坑**；W3 提示词划界——progress=本任务进行态，memories=可泛化持久事实，同一内容不双写 |
| 6 | 大小 | **项目记忆与状态条目不限大小**——D15 的 4KB 上限废除（2026-11-19 拍板，以后有需要再加）；标题/钩子 40 字保留（护索引路由）；注入侧 assemble 预算截断兜底 |
| 7 | 弃案存档 | 每项目多份按任务线+thread_id 选线程（两版）已否决——过度设计，勿重提 |

## 1. 数据形态

每个项目分区一条，与普通记忆同构：

```
{dataDir}/agent/memory/projects/<scope_key>/项目进度台账.md
（索引行进 MEMORY.md；frontmatter type=status；created_at 同题更新保留）
```

正文五段（渲染段序=注入优先级：待办驱动续作放最前，尾部截断先丢「坑」）：

```markdown
## 待办
- [ ] D35：真机八项验收
## 已做
- 11-19 D35：批0-4 已推 697707c，程序侧全绿
## 阻塞
- …
## 决策
- D37：台账仅会话结束自动写
## 坑
- 改日历要重算 workday next_run
```

- 空段整段省略；段内条目**新→旧**（合并插段首，尾部最旧）。
- 索引钩子：`hook_of` 跳过 Markdown 标题行取首个正文行（D37 微调，防钩子变 `## 已做`）。

## 2. 合并语义（`bbrt-memory/src/status.rs`，纯函数层）

W3 产出 `StatusDelta{done[], todo[], blockers[], decisions[], pitfalls[]}` → `merge_status_body`：

1. **加法合并**：归一化（去空白+小写）去重插段首；**不删既有条目、不裁剪**（拍板 #6）。
2. **todo→done 对账**：新 done 与既有 todo 归一化相等 → 从待办移除计 completed；新 todo 已在 done → 跳过（已完成不复活）。
3. **脱敏**：单条命中密钥特征（`find_secret`）整条丢弃计 redacted（防整篇 save 被拒）。
4. **拒绝覆盖**：现有条目非 status 类型（用户手写同题记忆），或正文非五段格式 → 不合并不写盘（宁可不动，不可误删）。
5. **跳过**：去重后零新增零完成 → 不空转重写（frontmatter updated_at 不动）。
6. **并发**：`MemoryEngine.status_lock`（`Arc<Mutex<()>>`，**跨 clone 共享**——与 GlobalStore「克隆=新锁」不同）串行「读-合并-写」；多会话同时结束各自 delta 条目级合并不丢更新。

## 3. 写入路径（仅 W3，`loop_runner.rs`）

- 项目会话 W3 输出改**对象 payload**，一次 bbc-fast 调用双产出：
  ```json
  {"memories":[{"title","type","body"}],
   "progress":{"done":[],"todo":[],"blockers":[],"decisions":[],"pitfalls":[]}}
  ```
- 日常会话保持旧数组格式（无项目进度）。
- 解析兼容：剥围栏后**外层 `{` 开头才走对象解析**（防旧数组被劫持——数组元素里的 `{}` 不能当外层对象）；对象解析失败回退数组；memories 中 `type=status` 一律丢弃（台账唯一写入方=progress→merge_status，防绕过合并护栏）。
- 转录改造：`transcript_of` **首条用户消息永远保留** + 尾部 8K（任务目标/需求原话在首条，是进度条目的任务归属依据）。
- 失败静默：模型不可用/输出不可解析 → 不写，台账保持原状（与 W3 记忆同语义）。
- WAL：`status.merge {"added","completed","redacted"}`；回执复用 `memory.saved`（type=status，会话流显示「更新记忆：项目进度台账」）。

## 4. 注入与预算

- `MemoryEngine::recall_scoped` 三段：`[用户记忆]` + `[项目记忆·<key>]` + `[项目进度]`（status 条目正文全文）；日常会话仅用户段；无台账时输出与旧口径逐字节一致。
- probe 子 agent 经 `probe_system` 继承（recall_scoped 同源）。
- 预算不变：仍走 `memory_index` 10%（默认 128K 窗口≈11,520 token）；台账无上限，常态远小于预算，极端增长由 assemble `fit_block` 尾部截断兜底（段序保证先丢「坑」）。
- W3 去重参考拆开喂：记忆走 `recall_memory_scoped`（头 60 行）+ 台账走 `status_body`（头 40 行）——避免 60 行截断把台账切掉。

## 5. 边界与护栏

| 面 | 约束 |
|---|---|
| 工具面 | `memory_save` 拒绝 type=status（8002，文案说明自动维护）；工具 schema 不暴露 status |
| 作用域 | status 仅项目分区；日常会话（ws=None）引擎层报 `StatusRequiresProject`，不回落公共层 |
| 协议 | `memory.saved` 的 memoryType 为字符串，status 直接透传，零协议改动；client `MemoryType` 联合类型加 `'status'`（回执 reducer 只看 title，零 UI 改动） |
| 迁移 | D15 旧文件族迁移映射 status→不灌 journal（legacy 不可能出现，防御分支） |

## 6. 已知取舍（watch-point，登记防丢）

- **不限大小的代价**：台账/项目记忆无上限，增长治理交使用纪律 + 注入截断兜底；若真机发现常态超预算挤占 USER.md/项目索引，再加容量上限或蒸馏（届时拍板）。
- **仅会话结束触发**：长会话中段里程碑可能漏（W3 只看首条+尾部 8K）；崩溃/直接关 App 不走 `SessionEnd` 则不落盘。若漏记成为常态，加轻量检查点（关键事件/每 N 轮调同一个 merge，不改存储形态）。
- 台账定位是**摘要**不是全量日志：要 ZCode 式 170KB 活文档请另立项。

## 7. 验收清单（真机）

1. 项目会话干一轮活后点「结束会话」→ `projects/<key>/项目进度台账.md` 生成、MEMORY.md 有索引行、会话流出现「更新记忆：项目进度台账」回执；
2. 新开会话问「上次做到哪了」→ 模型基于 `[项目进度]` 直接答（无需跑 git log）；
3. 待办完成后新会话结束 → 待办条目消失、已做段新增（todo→done 对账）；
4. 两个项目会话先后结束 → 条目合并且无覆盖；同名手写记忆不被台账覆盖；
5. 日常会话结束 → 无分区目录产生；
6. `memory_save(type=status)` → 8002 拒绝；密钥内容条目不落盘。
