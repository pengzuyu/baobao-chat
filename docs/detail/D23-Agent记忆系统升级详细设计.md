## 0. 背景与拍板决策

背景：2026-11-12 九轮设计讨论。参照系=ZCode 记忆机制实测（常载索引仅占全库 2.3%、三通道入上下文）+ 本机实测三退化教训（①状态类只追加不蒸馏→90K 不可整读死文件；②索引行被塞成第二正文→双重记账；③多会话无锁并发写）。核心认知：**记忆系统本质是检索系统，写入只是半题；防退化靠结构约束不靠纪律**。

**拍板决策（2026-11-12，用户裁决，勿重提）**：

| # | 决策 | 结论 |
|---|---|---|
| 1 | 层级 | **两层=公共+项目**；会话层不做平级存储层（生命周期无解+三层写入路由成本高+会话内上下文本就承载） |
| 2 | 公共层归属 | **单用户本地**（非组织共享）；**不做 tenant/user 身份键**——人轴外包 OS 账号（同 ZCode 口径：记忆=本机痕迹，归属者=机器）；P2 同步到来时一次性迁移（老根整体 mv 进 u-{uid}/ 一层） |
| 3 | 预算 | 硬顶 **3000 字**、常态目标 **≤2400**（留余量使压实低频）；单条 ≤80 字、一条一事实一句一线 |
| 4 | 机制 | **日志+压实两段式**：journal 追加永远可写，超硬顶才压实。漏斗=规则（去重/同义合并/过期剔除）→**仅软条目进 LLM**（禁止/授权硬条目不进 LLM 输入、程序拼回=结构性保护）→校验（超限/格式坏=保留旧视图，宁旧勿错） |
| 5 | 一致性 | **view 是缓存、journal 是真相**：不一致只可能「视图旧了」不可能「多出 journal 没有的内容」；每次写入重投影 + bbrt 启动 reconcile 兜底 |
| 6 | provenance | **只进 journal 不进视图**（视图带元数据≈吃预算 20% 且压实合并后来源语义模糊）；日期进视图仅当本身是内容（目标类 deadline） |
| 7 | 并发 | **单写者**：bbrt 本就是唯一碰记忆目录的进程（D15 既有事实），进程内一把 `Mutex` 串行全部记忆操作，零分布式锁 |
| 8 | 类型 | 公共层**十类硬枚举**（§3.1）；硬度轴=禁止/授权硬（压实不可删、只能显式解除）·目标时敏（压实优先复核、过期即清）·其余软（新盖旧） |
| 9 | 更正 | **forget+write 两确定性操作、零 LLM**（条目粒度非字符串替换——防同名误伤）；forget 返回移除清单回显，误删可重写；软类自然演变直接 write 新条目、压实时新盖旧 |
| 10 | 状态类 | **延后不做**（非否决）：类型=文本前缀标记，后加零 schema 迁移，本篇只留扩展位；v1 项目层只收知识类 |
| 11 | 命名 | 压实视图=`USER.md`（内容名：全是关于用户的事实）；项目索引=`MEMORY.md`（对齐 ZCode 惯例）；记忆 journal 保留机制名 |
| 12 | 召回分档 | P0=视图/索引常载+`memory_read` 主动拉；P1=FTS5 自动召回+设置页编辑+蒸馏纪律；P2=embedding+服务端按用户同步 |

**落地修订（与讨论蓝图两处差异，D23 定稿口径，用户可否决）**：

| # | 蓝图原案 | D23 落地 | 理由 |
|---|---|---|---|
| A | 日常会话写项目记忆→工具报错拒绝 | **保留 D19 回落用户级** | IM embedded 日常会话是主场景（「日常=默认工作区」既定口径），拒绝会丢主场景教训（8020 工具教训即来自此类会话）；回落条目落 USER.md 带 `[教训]` 类型标记，压实可甄别去留 |
| B | 项目层无容量上限（蓝图未提） | **两层 LRU 一并废除**（global 随换制自然废；project 200 条上限废除） | 否决/拍板类被 LRU 静默淘汰=将来重提已否决方案的事故源；增长治理改蒸馏纪律（§4.3）；单条 ≤4KB 保留 |

## 2. 目标存储布局

```
{dataDir}/agent/memory/                  ← 根沿用（dataDir 即 ~/.baobaochat，天然在 workspace 沙箱外）
├── global/                              ← 公共层（原用户级平铺文件族迁入改制）
│   ├── journal.jsonl                    ← 记忆写入日志（真相；永不注入上下文）
│   └── USER.md                          ← 压实视图（缓存；每次重投影整体重渲染）
├── projects/<scope_key>/                ← 项目层（D19 既有，零迁移）
│   ├── MEMORY.md                        ← 索引：一行一记忆（标题+≤40 字钩子）
│   └── <slug>.md                        ← 单条：frontmatter+正文（一文件一事）
└── archive/                             ← 迁移归档（一次性）
```

- **一次性迁移（bbrt 启动执行，幂等）**：既有用户级 slug.md 文件族逐条转 `{op:"add"}` 灌入 journal（四类→十类映射见 §3.1），重投影生成首个 USER.md，旧文件移 `archive/`；项目分区零迁移。
- `BBW_MEMORY_ROOT` env 覆盖记忆根——测试/联调隔离（防 :8090 测试期 agent 脏记忆污染日常 USER.md；与 BBW_RT_DEFAULT_WORKSPACE 同族模式）。
- P2 同步到来时：老根整体 mv 进 `u-{uid}/` 一层即完成按用户切分（拍板 #2），非重构。

## 3. 公共层（global）设计

### 3.1 十类清单与采集话术（写入门禁=工具描述携带的自问句）

| # | 类型 | 定义 | 采集话术（agent 写前自问） | 硬度 |
|---|---|---|---|---|
| 1 | 画像 | 「我是谁」的稳定事实 | 换个项目还成立、且说的是这个人吗？ | 软 |
| 2 | 偏好 | 内容与流程的取舍 | 用户对「先做什么、做到什么程度」给口径了吗？ | 软 |
| 3 | 风格 | 呈现形式 | 用户对「长什么样」给口径了吗？ | 软 |
| 4 | 习惯 | 周期性行为 | 这是会重复发生的节奏吗？ | 软 |
| 5 | 禁止 | 硬否定约束 | 用户说「不要/别/不允许」了吗？ | **硬** |
| 6 | 授权 | 硬肯定许可 | 用户给了「可以直接做」的许可吗？ | **硬** |
| 7 | 人际 | 对具体他人的协作事实 | 这是关于某个人的协作口径吗？ | 软 |
| 8 | 术语 | 私有词汇表 | 这是用户侧简称/黑话吗？ | 软 |
| 9 | 目标 | 阶段性方向 | 用户说了近期要达成什么吗？ | **时敏** |
| 10 | 教训 | 泛化的失败规律 | 这个坑换个项目还会踩吗？ | 软 |

- 统一写入判据（先于类型）：**换个项目还成立吗？明天还成立吗？任一否→不进公共层**（进项目层或不记）。
- 迁移映射：user→画像；feedback→教训；reference→术语；project→**不迁 global**（按 D19 本应落项目分区；历史误落用户级者，迁移时逐条过判据，不成立随 archive 归档、不灌 journal）。
- USER.md 渲染：一行一条 `[类型] 内容`（≤80 字）；文件头标注「自动生成，修改请走设置页」；日期仅目标类随内容出现（deadline 是内容）。

### 3.2 journal 与 USER.md

```
journal.jsonl 一行一 op：
{"op":"add"|"remove"|"edit","type":"偏好","text":"…","ts":"…","session":"sess-…"}

不变量：
① USER.md = f(journal)——纯派生物，永不直改（设置页编辑也转 op 过来）；
② journal 只追加永不删行（remove=tombstone，重放时剔除被标记条目）；
③ 全部写入路径（W1/W2/W3/设置页）收敛为 append(journal)+reproject() 两步。
```

**命名注记**：本 journal（`memory/global/journal.jsonl`，记忆写入日志）与 D15 被动轨活动日志（`agent/journal/YYYY-MM-DD.jsonl`，行为流水供日报聚合）是**两个东西**——目录隔离、语义不同，D23 不动后者。

### 3.3 重投影与压实漏斗（每次写入触发）

```
reproject():
  entries = 重放 journal
    → 应用 remove/edit（tombstone 剔除/替换）
    → 去重（同 type+归一化文本相等合并，保最新）
    → 目标类剔除已过期 deadline
  if render(entries) ≤ 3000 字:
      USER.md = render(entries)               ← 常规路径，零 LLM
      原子写（temp+rename）
  else:
      硬 = 禁止/授权条目（程序保留，不进 LLM 输入）
      软 = 其余条目 → bbw-fast 压缩（目标 ≤2400 字）
      candidate = render(硬) + render(压缩后软)
      校验：总长 ≤3000 且格式合法 → 原子写
            否则保留旧 USER.md（宁旧勿错；journal 无损，下次再试）
```

- **全量重渲染而非局部更新**：派生物无「局部更新」概念；temp+rename 原子性保证注入方永见完整文件；成本 O(视图 ≤3000 字)，与 journal 历史长度无关。
- **目标 2400 非贴顶 3000**：压实后留 600 字余量，后续十余次常规写入走免 LLM 规则路径——压实是低频事件不是每写必压。
- 压实失败/provider 不可用：跳过本次，视图临时超限无害，journal 无损。

### 3.4 一致性与自愈

不一致只可能「视图旧了」（崩溃在 append 与重投影之间/压实校验失败），**不可能「视图多出 journal 没有的内容」**（视图只有 journal 一个来源）。自愈双保险：每次写入重投影；**bbrt 启动 reconcile**——重放+规则渲染，≤3000 则确定性重建覆盖一切漂移；超限保留现视图（最近一次成功压实产物，启动不跑 LLM）。

### 3.5 更正与解除

```
用户更正（例：「我不叫小红，叫小明」）：
  ① memory_forget(type=画像, contains="小红")
       journal 追加 {op:"remove",…}；重投影剔除；
       返回「已移除 1 条：[画像] …」
       ← 移除清单回显=防同名误伤（同事小红在人际类，type 限定天然避开；
         同类多条命中时全部移除并逐条回显，agent 看得见、误删可重写）
  ② memory_save(type=画像, text="用户叫小明") → 立即生效
全程零 LLM、两次确定性操作、journal 留完整更正审计（何时/哪个会话/删什么加什么）。

软类自然演变（偏好变了，非更正）：直接 write 新条目，压实时新盖旧合并。
项目层更正：同 slug 整体改写（memory_save 既有「同题更新」语义天然覆盖）。
```

### 3.6 写入路径接驳（三条既有路径全改灌 journal）

| 路径 | 改造 |
|---|---|
| W1 `memory_save` | type 参数改**双枚举**：global 十类 / 项目 project·feedback·reference（分区路由不动）；global 写入=append+reproject；**日常会话 project 类回落 global**（落地修订 A：以 `[教训]` 类落 USER.md） |
| W2 heuristic | 「记住…」候选与连续同错教训，先过统一判据门禁再灌 journal——**自动路径判据不过则丢弃**（自动写不能污染预算） |
| W3 会话收尾提炼 | bbw-fast 候选逐条过判据+十类归类后灌 journal；提炼与压实共用 fast 档调用设施 |

## 4. 项目层（projects）设计

### 4.1 沿用（D19 零迁移）

文件族制（MEMORY.md+slug.md）、scope_key=<目录名-哈希>、类型路由（project/feedback/reference 随会话工作目录，项目会话写）、frontmatter（name/title/type/created/updated/session/links）、单条 ≤4KB、同题更新不重复、召回 ≤50 全量/>50 Top-K。

### 4.2 修订

- **索引行限长数据模型化**：钩子 ≤40 字超长硬拒（现状 title ≤40 已有，把索引行同口径封死——ZCode 索引膨胀教训：索引行是路由信息不是正文）；
- frontmatter 增 `last_used`（memory_read 触碰时更新）——为 P1 蒸馏提供依据；
- **取消 200 条 LRU**（拍板 B）：知识类静默淘汰=否决被遗忘的事故源；增长治理交给蒸馏纪律。

### 4.3 生命周期纪律（P1，随设置页编辑一起落）

任务收口触发蒸馏：durable（机制/不变量/否决）并入常驻、过程细节删除。状态类届时作为任务作用域类型加入——拍板 #10 扩展位兑现方式=补一条采集话术+一条压实规则，零 schema 迁移。

## 5. 工具面与协议

| 工具 | 参数 | 行为 |
|---|---|---|
| `memory_save`（既有，扩） | title,type,body,links? | global 十类→journal+重投影；项目三类→分区文件（同题更新语义不变）；单条 >80 字（global）结构化报错 |
| `memory_forget`（新） | type,contains | global 条目 tombstone+重投影；返回移除清单（0/1/N 条三态回显） |
| `memory_read`（新） | slug | 读项目分区单条正文；**路径解析限定记忆目录内**（防被当通用文件读工具）；touch last_used |

协议增量（D11 §4 表追加）：`memory.forgot`（RT→宿主 UNT：type/contains/removed[]——UI 同步删除）。memory.saved 沿用（type/scope 已带）；memory.list/delete 沿用，list 增 global 段（返回 USER.md 解析条目）。

## 7. 安全与边界

| 面 | 约束 |
|---|---|
| 沙箱 | 记忆根在 dataDir（workspace 沙箱外），8020 词法+内核双拦覆盖——agent 文件工具不可达，改记忆唯 memory_save/forget 门禁一条路 |

| 脱敏 | masking 沿用（journal/USER.md/分区文件写前打码；密钥特征拒写） |
| 本地性 | 零网络行为；P2 前不上服务端；审计仅 metadata 沿用 |
| 用户可见可编辑 | 记忆页 P0 加 USER.md 只读视图+global 条目删除（走 op 通道）；P1 编辑——**安全阀**：错误记忆毒化全部后续会话，唯一纠错途径是用户本人 |
| 联调隔离 | `BBW_MEMORY_ROOT` 覆盖记忆根 |
