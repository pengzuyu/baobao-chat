## 3. 机制设计

### 3.1 `brand/` 目录（部署方唯一改动面）

```
brand/
  README.md        # 白标指南：五步换牌手册（§7 验收即其走查脚本）
  brand.json       # 唯一品牌配置源
  assets/
    logo.svg       # UI 内 logo（登录页/侧栏/关于页 + favicon 源）
    icon.png       # 1024×1024 OS 图标源图（tauri icon 唯一入口）
```

### 3.2 brand.json schema

```json
{
  "name": "BaobaoChat",
  "page_title": "BaobaoChat · 企业协作工作台",
  "tagline": "让协作更简单 · 企业协作工作台",
  "copyright": "© 2026 BaobaoChat",
  "device_name": "BaobaoChat Desktop",
  "identity": {
    "identifier": "com.baobaochat.client",
    "deep_link_scheme": "bbc"
  },
  "updater_pubkey": ""
}
```

- `name` → productName/窗口标题/UI 全部显示名；`page_title` → index.html `<title>`（独立字段保默认零 diff）；`tagline` → 登录页副题/关于页标语；`device_name` → 登录上报。
- **identity 与 updater_pubkey = 高级覆盖区**：gen.mjs 检测偏离默认值时打红字警告（改 identifier=数据目录迁移全员登出；改 scheme=服务端 `BBC_DEEP_LINK_SCHEME` 必须同步）。

### 3.3 生成物与流向（gen.mjs）

| 生成物（全部 committed，头注释 `AUTO-GENERATED`） | 来源 | 消费方 |
|---|---|---|
| `client/src/shared/brand.ts`（APP_NAME/PAGE_TITLE/TAGLINE/COPYRIGHT/DEVICE_NAME） | brand 区 | 前端 11 触点（§4） |
| `client/src-tauri/src/brand.rs`（`pub const APP_NAME/SCHEME`） | brand+identity | `lib.rs:85` 深链 register 消灭硬编码 |
| `tauri.conf.json` 原地 patch：productName、windows[0].title、deep-link schemes、updater.pubkey | brand+identity | tauri build / NSIS 快捷方式名自动跟进 |
| `client/public/logo.svg` ← `assets/logo.svg` 复制 | assets | Logo.tsx/favicon |
| `client/index.html` `<title>` 正则重写（幂等） | page_title | webview 文档标题 |

图标全套（`src-tauri/icons/` icns/ico/png + android/ios）仅 `make brand` 全量时经 `npx tauri icon brand/assets/icon.png` 重生成——输出可能非字节等价，上游只在换图标时跑，日常 `make brand-conf` 不触图标。**默认值跑 `make brand-conf` 必须全仓零 diff**（幂等验收基线）。

### 3.4 一致性门禁

`gen.mjs --check`：重算期望输出与现存生成物比对，不一致 exit 1；挂 `build-desktop.sh`/`build-desktop.ps1` 前置——防"改了 brand.json 忘跑生成器"带着旧品牌出包。
