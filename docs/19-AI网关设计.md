## 1. 概述

### 1.1 定位

ai-gateway（Go 服务）是 BaobaoChat **全部模型流量的唯一出入口**：任何调用大模型、嵌入模型、重排模型的流量——无论来自 Agent Runtime、客户端聊天内嵌、知识库摄入管线还是专家 Agent——都必须经 ai-gateway 转发，**禁止任何服务与客户端直连模型上游**。

```
一句话职责：把"模型怎么选、密钥怎么放、用量怎么算、内容怎么防"收敛到一个模型无关的服务里，
           其余模块只需要面对 OpenAI 兼容接口与四个档位别名。
```

### 1.2 设计原则

| # | 原则 | 含义 | 违反后果（为什么必须收敛） |
|---|---|---|---|
| 1 | **模型无关** | 对内只暴露 OpenAI 兼容接口 + 档位别名（§3.3）；供应商差异（GLM/Qwen/DeepSeek/vLLM）全部由适配层吸收 | 调用方耦合具体模型 API，换模型全端发版 |
| 2 | **密钥不出网关** | 模型 API Key 只存网关侧 PG（KMS 引用 `kms://…`，对齐 10 篇 connector 凭证规范）；客户端与 Agent Runtime 不持有任何模型密钥 | 密钥散落终端，泄漏不可审计、不可轮换 |
| 3 | **全量计量** | 每次调用按 租户/用户/会话/场景 计量 token 与请求数（§6.7），无"免费旁路" | 成本分摊与配额失去数据源 |
| 4 | **统一入口** | Agent 聊天、聊天内嵌、KB 嵌入/重排、D14 专家、委派编码全部走网关 | 熔断/脱敏/审计出现盲区 |
| 5 | **明确不做 KV 缓存** | 不做 prompt/response 语义缓存（命中复用）；仅保留路由表、限流计数等控制面缓存 | 语义缓存引入"跨用户内容串用"风险，且与全量计量口径冲突 |
| 6 | **网关不做事，只做面** | 不做提示词组装、不做工具执行（08 篇 Runtime 职责）；不做检索（11 篇 kb 职责） | 职责膨胀导致单点变更频率过高 |

### 1.3 范围

| 项 | 说明 |
|---|---|
| 本期范围 | chat/completions（SSE 流式 + 非流式）、embeddings、rerank；路由/熔断/降级；计量与配额联动；脱敏与敏感词；出站白名单；管理配置页 |
| 不在本期 | 多模态（图片/语音输入）接口、按 token 成本直接计费出账、语义缓存（明确不做）、模型微调托管（开放问题 §9） |

## 2. 角色与场景

### 2.1 调用方一览

| 调用方 | 通道 | 凭证 | 计量场景 scene | 说明 |
|---|---|---|---|---|
| Agent Runtime（08 篇） | HTTPS+SSE，OBO token（含 act） | 用户 token 降权 | chat / delegate / expert | 主流量；委派编码后端（17 篇）与专家 Agent（D14）同走此通道，靠请求头区分场景 |
| 聊天内嵌（客户端 UI） | HTTPS，用户 access token | 用户本人 | chat | 客户端内轻量场景：消息翻译、摘要、润色（04/06 篇按钮触发） |
| KB 摄入管线（11 篇） | HTTPS，内部服务 token | 服务身份 svc:kb | embed / rerank | 摄入 worker 批量嵌入；检索时查询嵌入 + 重排 |
| 管理台（D10 PAD-09） | REST /api/v1/admin/ai | 管理员 | — | 路由配置、健康面板、用量查询；不产生模型流量 |

### 2.2 典型场景

```
S1 Agent 编码会话：用户在 Agent 视图下任务 → Runtime 组上下文 → POST /v1/chat/completions
   (model=bbc-strong, stream) → 网关路由到供应商 A → SSE 逐帧回传 → 计量(user, session, scene=chat)
S2 强模型故障降级：S1 中供应商 A 熔断 → 网关按降级链自动切 bbc-strong 备选 → 全部失败返回 8051
   → Runtime 暂停会话报 8011（08 篇既有语义，用户一键重试）
S3 知识库夜间摄入：kb 摄入 worker 批量 64 条/批 POST /v1/embeddings (model=bbc-embed)
   → 计量(tenant, svc:kb, scene=embed) → 配额不足返回 8005 → 摄入任务挂起不丢（11 篇 7008）
S4 专家 Agent 组队：D14 协作图中多个专家并行调用 → 各自带 X-BBC-Agent-Session
   → 网关按会话维度聚合计量（scene=expert），供专家成本核算
S5 管理员切流：新模型到货 → 管理台新增路由版本 v3（bbc-strong→供应商 B，灰度 10%）
   → 激活 → 观察 1h 健康面板 → 比例逐步 100%
```

### 3.2 档位模型（路由的最小语义）

| 档位别名 | 用途 | 典型上游 | 质量要求 | 延迟预算（首 token） |
|---|---|---|---|---|
| `bbc-fast` | Agent 轻步骤、分类、路由判断、聊天内嵌摘要/翻译 | 小参数模型 / vLLM 私有部署 | 中 | P95 ≤ 1.5s |
| `bbc-strong` | Agent 主推理、编码任务、专家 Agent | GLM/Qwen/DeepSeek 旗舰 | 高 | P95 ≤ 4s |
| `bbc-embed` | KB 嵌入（摄入批量 + 查询单条） | bge-m3 推理服务 | 冻结模型（01 篇） | 批量 P95 ≤ 2s |
| `bbc-rerank` | KB 重排（query × top50 chunk） | bge-reranker 推理服务 | 冻结模型 | P95 ≤ 300ms（11 篇 §9.5 联测） |

规则：

- 调用方 `model` 字段**只允许档位别名**；传具体模型名一律 9001（防止调用方绕过路由与计量口径）。
- 档位语义稳定，路由表换供应商对调用方透明（08 篇"会话内选快/强模型"即选档位）。

### 3.3 版本化路由表

路由表（ai_route_rule）是档位 → 供应商候选序列的**版本化配置**：

```
路由表 v7（当前生效）
┌─ 档位 ─────┬─ 候选序列（按优先级，含灰度权重）────────────┬─ 备注 ────────────┐
│ bbc-strong │ A:供应商GLM-旗舰 60% │ B:Qwen-旗舰 30%      │ C 为降级目标       │
│            │ C:DeepSeek-旗舰 10%（灰度）                 │                   │
│ bbc-fast   │ A:vLLM-local-32b 90% │ B:GLM-轻量 10%      │ 私有优先控成本     │
│ bbc-embed  │ bge-m3-svc（单实例，无降级，故障即排队）      │ 11 篇 §7.2        │
│ bbc-rerank │ bge-reranker-svc（同上）                    │ 故障时 KB 跳过重排 │
└────────────┴──────────────────────────────────────────────┴───────────────────┘
```

| 机制 | 设计 |
|---|---|
| 版本化 | 每次修改生成新 version，可回滚（一键回上一版）；激活即生效，副本 5s 内收敛（Redis 版本号广播） |
| 租户级覆盖 | 租户策略可覆盖默认表（如高合规租户**只允许私有 vLLM**，公有 API 档位整体禁用）；覆盖条目带 `scope=tenant:{tid}` |
| 灰度切流 | 候选带权重，按 request_id 哈希稳定分流（同一会话尽量同供应商，减少风格跳变） |
| 配置审批 | 修改走 12 篇二次验证 A 档（口令重验）；切换"仅私有化"等合规敏感项走 C 档双人审批 |

## 4. 核心流程

### 4.1 请求主流程

```
① 接入: TLS 终结 → 鉴权(JWT: 用户/OBO[act]/服务token) → 出口判定(aud=ai-gateway)
② 限流: 令牌桶(租户×场景维度) 超限→8050；幂等键(Idempotency-Key)24h 去重→重放返回原结果
③ 解析: model 别名→档位；无路由条目→8052
④ 安全面: 脱敏(租户档位) → 敏感词(命中打标,不拦截,元数据记录) → 注入检测(可选,§7.5)
⑤ 路由: 版本化路由表(含租户覆盖) → 候选序列过滤(健康状态) → 哈希灰度选主
⑥ 适配: 协议转换 → 出站(白名单校验) → 超时控制(首token/总时长双阈值)
⑦ 流式回传: SSE 逐帧透传；结束时附 usage 终帧(prompt/completion tokens)
⑧ 计量: 开票(request_id, 维度, tokens, 延迟, 结果) → 内存聚合 → 分钟刷盘 → 小时表
```

### 4.2 健康探测与自动摘除

| 机制 | 参数（默认，可配） | 动作 |
|---|---|---|
| 主动探测 | 每 30s 对每供应商发 1 token 探测请求（embed 档发单条短文本） | 探测失败计 1 次失败 |
| 被动统计 | 滑动窗口 2min：错误率 > 50% **或** P95 延迟 > 档位预算 × 3 | 计入熔断判定 |
| 熔断打开 | 连续失败 ≥ 5 或窗口错误率达标 | 该供应商从候选摘除（现有流不切断，新请求不再路由） |
| 半开探测 | 熔断 60s 后放 1 个探测流量 | 成功 → 恢复（初始权重减半爬升）；失败 → 继续熔断（指数退避上限 10min） |
| 状态可见 | 健康面板实时展示（3.4） | 8051 错误体携带 `provider_status` 供排障 |

### 4.3 超时与重试矩阵

| 档位 | 首 token 超时 | 总时长上限 | 网关内重试 | 幂等性 |
|---|---|---|---|---|
| chat（流式） | 10s | 300s | 首 token 前可换供应商重试 1 次；**已出 token 后不重试不换路** | 重试换供应商会双计费，计量按 request_id 去重（§4.5） |
| chat（非流式） | — | 120s | 5xx/超时换下一候选，最多 2 次 | 同上 |
| embed | — | 30s/批 | 指数退避 3 次（同供应商） | 批次幂等（input 哈希） |
| rerank | — | 10s | 1 次 | 幂等 |

### 4.4 降级链

```
chat 类（fast/strong）:
  主候选 → 次候选 → … → 全部不可用:
    ├─ 强模型场景: strong→fast 降档重发（请求头 X-BBC-Downgraded: true 标记，08 篇切档上报 model.switched）
    └─ fast 也不可用: 进入排队（网关侧短队列 ≤ 30s 等半开恢复）→ 超时 8051
embed/rerank 类:
  唯一候选不可用 → 不降级（模型不可替换，语义不一致）:
    ├─ embed: 返回 8051 → KB 摄入队列挂起不丢（11 篇 7008），检索降级纯 FTS
    └─ rerank: 返回 8051 → KB 检索跳过重排（RRF 序直出，11 篇 §4.3）
```

### 4.5 SSE 中断与断流重试语义（对齐 08 篇 / 14 篇 §5.3）

| 关注点 | 语义 |
|---|---|
| 调用方断流重试 | Runtime 侧行为冻结在 08 篇：SSE 断流 → 幂等重试 ≤ 2 次；429/5xx → 指数退避 3 次 → 强降快 → 8011。网关保证：**同一 Idempotency-Key 的重试在 24h 内不重复计量**（首算后命中即复用票据） |
| 生成不可续传 | 流式生成中断后**不支持从断点续传**（生成式无幂等续传语义），调用方整体重发；网关在响应头回 `X-BBC-Request-Id` 供双方对账 |
| 服务端主动断 | 总时长超限/客户端 60s 未消费缓冲 → 网关关闭流并完成计量（已生成 token 照计），客户端收到非正常结束可按断流重试 |
| 计量一致性 | 以网关开票为唯一口径（供应商账单对账用，08 篇 Runtime 本地记录仅对账参考） |

### 4.6 配额检查与预警

```
请求前: 查租户/用户月度配额(Redis 计数, 小时表对账) → 超限即拒 8005(不进路由)
请求后: 开票累加 → 达 80%/95% 阈值 → 发 ai.quota.warning(14 篇已登记, 归属 12 篇)
        → 推送责任管理员; 用户个人配额触达时同时推用户本人
数据源: ai_usage_hourly 为 12 篇"用量与配额"页唯一 AI 数据源(T+1min 刷新窗口)
```

## 5. 数据模型

> **回填提示：本节 3 张新表（ai_provider / ai_route_rule / ai_usage_hourly）必须登记入 [13-数据模型与存储设计](13-数据模型与存储设计.md) §3（新增 §3.9 AI 网关域）。**

### 5.1 ai_provider（供应商登记）

| 列 | 类型要点 | 说明 |
|---|---|---|
| id, tenant_id | 雪花；tenant_id=NULL 表示平台级登记 | 平台统一登记，租户仅做覆盖引用 |
| name / kind | 如 `glm-flagship`；kind=openai_compatible / vllm / bge_embed / bge_reranker | kind 决定适配器 |
| endpoints jsonb | `[{url, weight}]`，出站白名单以此为准 | 域名或 IP:端口，TLS 必须 |
| api_key_ref | `kms://ai/{provider_id}/key`（KMS 引用，明文永不落库，对齐 10 篇 §6.3） | 轮换只换 KMS 版本 |
| health | status(green/yellow/red) + 熔断状态机字段(open_at/half_open_at/连续失败数) + 最近探测延迟 | 面板与路由共用 |
| quota | 日请求数/token 上限（供应商侧配额保护，超出即摘除） | 与平台租户配额区分 |
| pricing jsonb | 输入/输出 token 单价（成本分摊口径 §6.7） | 管理台维护 |
| status / created_at / updated_at | enabled/disabled | 停用=不参与路由 |

### 5.2 ai_route_rule（版本化路由表）

| 列 | 类型要点 | 说明 |
|---|---|---|
| id, tenant_id | tenant_id=NULL=默认表；租户覆盖时非空 | 三种形态：默认/租户覆盖条目/草稿 |
| version | int，同一 scope 内单调 | 激活靠 status=active 唯一约束（部分唯一索引） |
| tier | fast/strong/embed/rerank | 档位 |
| candidates jsonb | `[{provider_id, weight, priority}]` | 候选序列 + 灰度权重 |
| overrides jsonb | 超时/重试参数覆盖、`private_only` 布尔（合规租户仅私有） | 租户级差异 |
| status | draft/active/archived | 激活/回滚=状态迁移 |
| created_by / approved_by / created_at | 修改走二次验证（12 篇），审批人留痕 | 审计回链 |

### 5.3 ai_usage_hourly（计量聚合，按月分区）

| 列 | 类型要点 | 说明 |
|---|---|---|
| id, tenant_id | 非空 | 计量必属租户 |
| hour_bucket | timestamptz 截断小时 | UK(tenant_id, hour_bucket, user_id, session_id, scene, tier, provider_id) |
| user_id | 用户；服务调用存服务身份（svc:kb） | 个人配额与成本分摊维度 |
| session_id | Agent 会话（X-BBC-Agent-Session）；非会话调用为空 | 会话聚合（专家/委派成本核算） |
| scene | chat/embed/rerank/delegate/expert | 场景维度 |
| tier / provider_id | 档位与实际命中的供应商 | 路由效果分析 |
| requests / prompt_tokens / completion_tokens / total_tokens | bigint 累加 | 供配额与报表 |
| errors / degraded_count | 降级发生次数 | 质量观测 |
| latency_ms_p50/p95 | 小时内分位近似（t-digest） | SLO 观测 |
| est_cost | numeric，按 provider.pricing 计算 | 成本分摊报表口径 |

Redis key（登记 13 篇 §5 规范）：`t:{tid}:ai:quota:{subject}:{ym}`（配额计数，月 TTL）、`t:{tid}:ai:rl:{scene}:{uid}`（限流桶）、`ai:route:version`（路由版本号广播，5s 收敛）、`ai:cb:{provider_id}`（熔断状态，副本共享）。

## 6. 接口设计

### 6.1 鉴权模型

| 凭证 | 形态 | 计量归属 | 判定 |
|---|---|---|---|
| 用户 access token | `Authorization: Bearer <JWT>`（aud 含 ai-gateway） | user + scene=chat | 03 篇签发，聊天内嵌等 |
| Agent OBO token | 同头 + token 含 `act`（agent 会话）+ `X-BBC-Agent-Session` 头 | user + session + scene（chat/delegate/expert 由 `X-BBC-Scene` 头声明） | OBO scope 必须含模型调用；超出 1006（03 篇） |
| 内部服务 token | `Authorization: Bearer <svc JWT>`（sub=svc:kb，scope=embed,rerank） | tenant + svc:kb + scene=embed/rerank | 签发/轮换/审计/撤销约定见 **03 篇 §2.4**（OQ-C31 定稿）；传输层叠内网 mTLS；仅限内网调用；**不允许发起 chat** |

公共请求头：`Idempotency-Key`（14 篇 §5.1）、`X-BBC-Scene`、`X-BBC-Agent-Session`、`X-BBC-Kb-Space`（服务 token 携带，计量细分到空间，可空）。

### 6.2 POST /v1/chat/completions（OpenAI 兼容，SSE）

| 项 | 设计 |
|---|---|
| 请求体 | OpenAI Chat Completions 兼容（messages/tools/temperature/stream…）；`model` 仅档位别名（bbc-fast/bbc-strong） |
| 流式响应 | `text/event-stream`，chunk 帧格式与 OpenAI 一致（08 篇 Runtime 直接消费）；结束帧后附 `X-BBC-Usage` 终帧（`{request_id, prompt_tokens, completion_tokens, provider, tier, degraded}`）再 `[DONE]` |
| 非流式 | 标准 JSON 响应，网关注入 `usage` 与 `x-bbc-request-id` 头 |
| 错误 | 网关侧错误以 OpenAI 风格错误体返回但 `code` 字段填本篇错误码（§6.6），`trace_id` 保留（14 篇 §5.2 约定） |
| 降级标记 | 响应头 `X-BBC-Downgraded: true`（strong→fast 时） |

### 6.3 POST /v1/embeddings（OpenAI 兼容）

| 项 | 设计 |
|---|---|
| 请求 | `{model:"bbc-embed", input: string[]|string, ...}`；批量上限 64 条 / 512KB |
| 响应 | `{data:[{embedding: float[1024], index}], usage, x-bbc-request-id}`，维度固定 1024（01 篇冻结） |
| 调用方 | 服务 token（KB 管线）为主；用户 token 仅未来客户端本地检索等场景预留（需租户策略开启） |

### 6.4 POST /v1/rerank（内部扩展，非 OpenAI 标准）

| 项 | 设计 |
|---|---|
| 请求 | `{model:"bbc-rerank", query, documents:[{id, text}], top_n}`；documents ≤ 50、单条 ≤ 8KB（对齐 KB topN） |
| 响应 | `{results:[{index, id, score}], usage, x-bbc-request-id}` |
| 调用方 | 服务 token（kb-svc 检索路径）；不对用户 token 开放 |

### 6.5 管理 REST（`/api/v1/admin/ai`，挂 D10；遵 14 篇 §5）

| API | 说明 | 权限点 |
|---|---|---|
| GET/POST /admin/ai/providers · PATCH /providers/{id} | 供应商登记/健康查看/停启用；密钥仅接受 KMS 引用写入，改密钥走二次验证 | admin:policy:manage |
| GET /admin/ai/routes?version= · POST /admin/ai/routes · POST /routes/{v}/activate | 路由表草稿/激活/回滚（激活=A 档验证） | admin:policy:manage |
| GET /admin/ai/routes/health | 供应商健康面板数据 | admin:policy:manage |
| GET /admin/ai/usage?group_by=tenant/user/scene&from=&to= | 用量查询（12 篇用量页数据源） | admin:usage:read |
| GET /admin/ai/audit?… | 网关审计检索（路由变更/密钥轮换） | admin:audit:read |

**v0.1 落地子集（0023 迁移，2026-11-09）**——上表的多供应商务实版，协议形态有调整处：
- 表驱动装配：`ai_provider`（+`owner_user_id` NULL=公司级/本人 BYOK、`models` 清单）+ `ai_route_rule`（fast/strong 各一条 active；candidates 扩展 `{provider_id, model, priority}`，主备降级=逐候选）替代环境变量单上游；env/mock 装配保留为兜底（内存模式/E2E 不变）。
- 密钥：`api_key_ref` = `kms:v1:<b64>`（AES-256-GCM，主密钥 `BBC_KMS_MASTER_KEY` 注入，openssl rand -base64 32 生成）——"KMS 引用"原则的嵌入式落地；接口仅回 `****末4` 掩码；二次验证/密钥轮换审计留阶段二。
- REST 实际形态：`GET/POST/PATCH/DELETE /api/v1/admin/ai/providers`（DELETE 软语义=硬删但被 active 路由引用时拒绝）+ `POST .../probe`（探活兼拉取上游 /models）+ `GET/PUT /api/v1/admin/ai/routes`（PUT=旧 active 归档+新 version 落地）；健康面板/用量/审计查询复用 D10 既有页，未做网关独立端点。
- model 字段扩展（§3.2 之外的 v0.1 新形态）：`p:<provider_id>:<model>` 直达引用——公司级供应商任意员工可用其清单内模型；个人 BYOK 仅 owner（8054）；清单外 8055；用户默认选择存 `users.settings.ai_default`（mode=org/provider），客户端解析，网关无状态。
- 用户侧 REST：`/api/v1/me/ai/providers`（BYOK CRUD+probe，≤5 个/人）、`/api/v1/ai/providers/shared`（公司级只读下拉源）、`/api/v1/me/settings`（通用个人设置，PATCH 浅合并）。
- 降级判定：候选选定依据=「首帧产出或错误」（StreamChat 异步，连接失败在首帧前暴露方可换候选；全尽回 503+8051）；per-candidate TTFB 超时/熔断状态机仍留阶段二。

### 6.6 错误码（8xxx 段扩充，**需登记入 [14-协议](14-通信协议设计.md) §7**）

| code | 含义 | 触发 |
|---|---|---|
| 8005 | 模型配额超限（**沿用 14 篇既有**，本篇明确语义=租户/用户月度 token 配额耗尽） | §4.6 请求前检查 |
| 8050 | 网关限流（入口令牌桶超限，非供应商侧限流） | §4.1-②，附 `Retry-After` |
| 8051 | 供应商不可用（全部候选熔断/排队超时/供应商报 5xx 透传判定） | §4.2/§4.4，错误体含 `provider_status` |
| 8052 | 路由档位未配置（别名不存在或租户覆盖后该档位无可用候选） | §4.1-③ |
| 8053 | 引用的供应商不存在或已停用（`p:<provider_id>:<model>` 直达引用解析失败；跨租户引用同判不存在，防探测） | §3.2 引用扩展（0023 表驱动多供应商） |
| 8054 | 越权引用（非公司级供应商且 owner ≠ 当前用户——BYOK 边界） | §3.2 引用扩展 |
| 8055 | 模型不在该供应商 models 清单内（清单为管理端/用户录入的可用模型） | §3.2 引用扩展 |

与既有码的边界：8011（ai-gateway 连续失败）是 **Runtime 侧聚合后暴露给用户**的会话暂停语义（08 篇），8051 是**网关单次请求**的同步错误；Runtime 收到 8051 重试耗尽后升级为 8011。9003 通用限流不用于模型通道（模型通道固定 8050，便于客户端差异化文案）。

### 6.7 计量与配额口径

| 项 | 口径 |
|---|---|
| 计量维度 | 租户 / 用户（或服务身份）/ 会话 / 场景（chat·embed·rerank·delegate·expert）/ 档位 / 供应商 |
| 聚合粒度 | 请求开票（内存）→ 分钟刷盘 → 小时聚合入 ai_usage_hourly；原始逐请求明细**不落库**（只进元数据日志流 §7.3） |
| 配额 | 月度 token 配额（租户级 + 可选用户级），存 12 篇 tenant_quota（limits），计数 Redis、对账小时表；超限 8005 |
| 预警 | 80%/95% 双阈值发 `ai.quota.warning`（14 篇已登记、12 篇归属），payload 含 quota_key/used/limit/pct/subject |
| 成本分摊 | est_cost = tokens × provider.pricing，按租户/部门（user→dept 映射）/场景三口径出报表；**内部成本分摊口径，不等于供应商账单**（公有 API 折扣/包月差异在管理台人工校准） |
| 报表入口 | 12 篇"用量与配额"页 AI 用量区块（按部门、按用户 TOP 榜）；网关不自带报表 UI |

### 6.8 WS 事件

本篇**不新增** WS 事件：配额预警复用 `ai.quota.warning`（14 篇 §3.2 已登记，归属 12 篇）；管理台健康面板轮询 REST。

## 7. 边界与安全

### 7.1 内容脱敏档位（租户策略）

| 档位 | 行为 | 适用 |
|---|---|---|
| `off` | 不脱敏直出（默认） | 全私有化部署、内网 vLLM |
| `regex` | 出站前正则脱敏（身份证/手机号/邮箱/自定义模式表，租户可维护）；**流式响应不回扫**（只脱 prompt 出站方向） | 混合云 + 公有 API 租户 |
| `strict` | regex + 命中即拒绝（返回 8006 策略禁止） | 高合规租户 |

注意：正则脱敏有漏检可能，档位说明写入租户管理文档（15 篇数据分级联动）；脱敏仅作用于**出公有 API**的流量，私有部署档位默认 off。

### 7.2 敏感词

复用 04 篇 `sensitive_word` 租户词库：prompt 命中**打标不拦截**（拦截决策归 09 篇 Agent 门控与租户 Agent 策略），命中记录进元数据日志并计入审计事件，供治理复核（对齐 11 篇清洗打标口径）。

### 7.3 日志策略（默认不存正文）

| 项 | 设计 |
|---|---|
| 默认 | 日志只存元数据：request_id/trace_id/租户/用户/会话/场景/档位/供应商/token 数/延迟/结果码/脱敏与敏感词命中标志；**不存 prompt 与 completion 正文** |
| 采样 | 租户策略可开启正文采样（默认 0%，上限 1%）；采样正文加密（KMS 数据密钥）落 MinIO `t/{tid}/ai-sampled/`，保留 7 天，仅审计合规员可解密查看 |
| 例外 | 8051/8052/熔断切换等**控制面事件**全量记录（不含正文）；审计事件入 15 篇哈希链 |

### 7.4 供应商出站白名单

- 网关出站目标仅限 ai_provider.endpoints 登记项（域名级，DNS 解析后校验 IP 防绕过）；新增供应商=新增白名单，走管理审批。
- 出站强制 TLS ≥ 1.2（15 篇 §3.2）；私有 vLLM/推理服务限内网网段。
- 与 09 篇 8025（Agent 本地出站白名单）是两套独立防线：网关白名单管服务端模型出站。

### 7.5 提示注入检测接入点（15 篇联动）

- 网关作为**统一检测挂载点**（单点覆盖全部 chat 流量）：租户策略开启后对 prompt 做规则/小模型检测（15 篇开放问题 2 的落地位置）。
- 命中**不拦截**（避免误杀），在响应头与计量开票打标：`X-BBC-Injection-Flag: low|high`；Runtime 依据该标记走 09 篇不可信触发强制人工确认路径；high 级同时写审计事件。

### 7.6 高可用与容量边界

| 项 | 设计 |
|---|---|
| 无状态多副本 | 副本不持久状态（路由表/熔断态在 Redis），K8s HPA 按 QPS 扩容；单副本故障客户端重连即可 |
| 供应商熔断 | §4.2 状态机；熔断是"摘除候选"不是"拒绝服务"（除非全候选熔断） |
| 网关整体故障 | 02 篇 §7 失败域既定：Agent 不可用但 IM 等基础功能不受影响；KB 摄入队列挂起不丢 |
| 容量基线 | 峰值 chat 200 req/s、embed 批 50 req/s 起步；16 篇压测后细化（GPU 推理服务容量是真正瓶颈，01 篇 §8 开放问题 3） |
| 明确不做 | KV/prompt 缓存（§1.2-5）、请求正文入库、跨供应商自动 failover 的 embed（模型语义不可替换） |

## 9. 开放问题

1. **多模态模型接入预留**：图片/语音输入（消息内嵌图片理解、会议纪要音转文）走 /v1/chat/completions 扩展 content 数组还是独立 /v1/multimodal？档位是否增设 `bbc-vision`？待阶段四产品需求明确。
2. **按 token 成本计费联动**：est_cost 目前仅内部报表口径；若租户间（多子公司）需要"实质结算"，需与 12 篇 tenant_quota/套餐（9011）打通出账周期、单价版本化与冲正流程。
3. 注入检测小模型的档位与成本：检测本身消耗推理资源，是否用 fast 档同集群承载？（15 篇开放问题 2 联测。）
4. 私有 vLLM 集群的排队策略：网关侧短队列（≤30s）与 vLLM 自身排队（max_queue）参数如何对齐，避免双层排队叠加放大延迟。
5. embed 模型版本升级路径：bge-m3 若换代，全量重嵌入的成本窗口与新旧向量并存期的检索一致性（11 篇 §4.2 增量更新机制能否复用）。
