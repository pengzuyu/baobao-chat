## 1. 概述

### 1.1 范围与原则

本篇将 00 篇五条 P0 原则（身份一致性、本地优先执行、最小授权、一切可审计、多租户硬隔离）落为可验证的控制措施。原则：

| # | 原则 | 含义 |
|---|---|---|
| 1 | 纵深防御 | 任一单点失守（客户端、网关、DBA 账号、供应链）不导致全量数据失陷 |
| 2 | 判定服务端化 | 权限判定、配额、签名校验全部以服务端为唯一权威；客户端控件仅是体验层 |
| 3 | 默认安全 | 出厂即加密、即审计、即最小权限；放宽必须显式配置并留痕 |
| 4 | 可验证 | 每条控制措施对应"验证方式"（自动化测试 / 渗透用例 / 指标告警），不可验证的措施不写入 |

### 1.2 与其它篇分工

- 09 篇：Agent 工具沙箱、权限门控 UX、提示注入防御体系（本篇 §3.5 仅汇总服务端防线）。
- 10 篇：应用/技能包清单签名链、凭证代持（本篇引用不重复）。
- 03 篇：认证协议、令牌模型、RBAC/OBO 判定逻辑。
- 12 篇：二次验证矩阵、审计导出水印、双审计。
- 16 篇：证书运维轮换节奏、备份、告警通道落地。

### 1.3 安全体系总览（纵深分层）

```
┌─ 第0层 身份 ── 口令/SSO/MFA · 设备绑定 · 一次性轮换 refresh · OBO(无Agent账号) ─┐
├─ 第1层 传输 ── TLS1.3 全链路 · WSS · SRTP · 固定企业根 CA(pinning) ────────────┤
├─ 第2层 边界 ── 网络分区 · 最小权限账号 · 中间件 ACL/TLS · Agent 通道独立限流 ──┤
├─ 第3层 判定 ── RBAC 权限点 + 数据范围 + 资源 ACL(03篇) · RLS 租户硬隔离 ──────┤
├─ 第4层 数据 ── 磁盘加密/TDE · SSE-S3 · 客户端 OS 级加密 · 分类分级(§3.9) ─────┤
├─ 第5层 供应链 ─ ed25519 签名链(10篇) · 更新签名 · 依赖/密钥扫描 CI ───────────┤
├─ 第6层 审计 ── 一切可审计 · 哈希链+每日锚点 · 双审计 · 对账 ──────────────────┤
└─ 第7层 响应 ── 指标告警(16篇) · killswitch 止损 · 漏洞 SLA(§4.3) · 演练 ─────┘
   失效假设：任一单层被突破时，第3/6层保证"进得来、拿不多、赖不掉"
```

## 3. 控制措施

### 3.1 传输安全

| 项 | 措施 |
|---|---|
| 全链路 TLS 1.3 | 客户端↔gateway（WSS + REST）、Web 管理台、更新源 HTTPS、ai-gateway↔模型上游、服务↔PG/Redis/MinIO 连接加密；最低 TLS 1.2，禁用弱套件，优先 1.3 |
| 证书签发 | **内网自建 CA 或企业 CA** 统一签发服务端证书：叶子证书有效期 90 天、含服务 SAN；签发自动化（K8s cert-manager / 内部 ACME），人工签发仅限离线环境（登记台账） |
| 证书轮换 | 到期前 14 天告警（16 篇）、自动重签滚动替换；轮换流程见 16 篇 §4.7 |
| Pinning 策略 | **客户端固定企业根 CA**（非叶子证书指纹）：Rust 核心内置根 CA 指纹，所有 TLS 校验要求链至固定根；更新源与 OnlyOffice 域名同样纳入；根 CA 轮换采用**预置双根**（当前根+继任根）重叠期 ≥12 个月，随客户端版本切换信任 |
| 媒体面 | WebRTC DTLS-SRTP（端到端加密的密钥协商经 WSS 信令，05 篇）；coturn 仅 long-term credential + TLS/DTLS，内网默认关闭中继 |
| 服务间 | 模块化单体时期进程内调用无网络面；拆分部署后启用 mTLS（同一内部 CA），中间件端口仅监听内网网段 |

### 3.2 存储安全

| 组件 | 措施 |
|---|---|
| PostgreSQL | ① 磁盘加密（LUKS/云盘加密）必选，TDE（透明数据加密）作为高合规租户可选；② **最小权限账号**：应用账号无 SUPERUSER/CREATEDB，禁 `COPY PROGRAM`，DDL 走独立迁移账号（发布窗口外禁用）；③ **RLS 强制**：所有业务表 `tenant_id` + 行级安全策略，应用连接池按请求上下文设置 `app.tenant`（02篇§5），验证方式见 §3.6；④ 审计相关表收回 UPDATE/DELETE 权限（追加写） |
| MinIO | ① 默认 **SSE-S3** 服务端加密（KMS 管理主密钥）；② 桶策略：应用服务账号按 `t/{tenant_id}/` 前缀授权（IAM policy 显式 deny 根路径与跨前缀），预签名 URL 时效 ≤15 min 且绑定操作；③ 版本化开启（与 16 篇备份联动）；④ 控制台端口不对客户端网段开放 |
| Redis | ① TLS + **ACL**：按服务分账号，仅授予所需命令 pattern（禁 KEYS/FLUSHALL/CONFIG）；② **不存敏感明文**：口令、token、OBO 凭证、消息正文不入 Redis（仅在线状态、seq 游标、限流计数、ACL 缓存等元数据）；③ key 一律 `t:{tenant_id}:` 前缀（02篇§5）；禁用危险命令改名+监控 |
| 客户端 SQLite | 敏感字段（消息缓存、Agent 会话镜像）**OS 级加密**：数据库密钥随机生成，macOS 以 **Keychain wrapped key**、Windows 以 **DPAPI**、Linux 以 libsecret 包裹存储，启动时解密仅驻内存；库文件不落明文目录；登出可选清除本地库 |
| 系统钥匙串 | refresh token 仅存钥匙串（03篇§2.2）；按服务条目隔离、设备绑定；永不写入 SQLite/日志/配置文件 |

### 3.3 密钥管理

**密钥清单**：

| 密钥 | 用途 | 持有方 | 算法/形态 |
|---|---|---|---|
| 模型 API Key | ai-gateway → 模型上游 | 服务端（KMS） | 供应商签发 |
| 应用代持凭证 | app-registry 代生态应用转发（10篇§7） | 服务端（KMS） | 各目标系统签发 |
| Access/OBO 签名密钥 | JWT 签发与验签（03篇§2.2/§6） | auth 服务 | **ES256，kid 轮换**，公钥经 JWKS 发布 |
| 更新签名密钥 | 客户端更新包/应用/技能包签名链（10篇） | 发布方（离线保管私钥） | **ed25519**（minisign 风格） |
| TLS 服务端证书/根 CA | §3.1 | 各服务/CA | X.509 |
| DB/Redis/MinIO 凭据 | 组件访问 | 部署配置（16篇§5 敏感配置下发） | 强随机 |

**KMS 或信封加密方案**：

- 首选企业 KMS；KMS 不可用时降级为**信封加密**：每密钥一条记录（`security_key`），数据密钥 DEK 加密存库，KEK 由离线保管的根密钥（拆分双份纸质/密钥卡）保护；可选自托管 Vault 作为折中。
- 私钥类（ES256/ed25519）生成于 KMS/HSM 或离机生成后加密导入；**任何私钥不落代码库、CI 变量明文、日志**。

**轮换流程与窗口**（详见 §4.1）：ES256 kid 双钥窗口 ≥24 h；ed25519 更新签名双签重叠 ≥90 天且客户端版本覆盖 ≥99% 后撤销旧钥；模型 Key/代持凭证 90 天轮换、双凭证并行引流切换；根 CA ≥5 年规划、双根预置。

### 3.4 客户端加固

| 项 | 措施 |
|---|---|
| Tauri CSP | 严格 CSP：`default-src 'self'`；connect/frame/img 按白名单（自有 API 域、更新源、OnlyOffice 域）；禁 inline script；release 构建关闭 devtools 与 inspector |
| Capability 最小化 | Tauri 2 capability 清单仅声明实际使用的插件与权限粒度（如 fs 限定目录 scope、shell 禁 arbitrary）；CI 校验 capability diff，新增需安全会签（§3.8 红线） |
| 更新包签名与降级防护 | 更新包 ed25519 签名 + 清单内 sha256 双校验；**降级防护**：拒绝安装低于 `force.min_version` 或低于当前版本的包，除非签名密钥显式授权的"受控回滚清单"（16篇§4.2），防降级攻击 |
| 反调试（仅告警） | 检测调试器附加/内存补丁特征 → 上报审计事件与指标；**仅作告警信号，不作为安全边界依赖**（判定已在服务端） |
| 本地日志脱敏 | 客户端/Runtime 日志正则遮蔽 token、口令、密钥、路径中的用户名；日志默认 INFO 级且可关闭（16篇§6.2） |
| 会话屏幕保护 | **管理台闲置锁定**：15 min 无操作遮罩 + 重验口令/MFA（12篇§1.1）；客户端主界面可选同策略（租户策略） |
| WebView 隔离 | OnlyOffice iframe 域隔离、postMessage origin 白名单；WebView 不注入任何凭据，文档访问凭证按 WOPI 短时效下发（06篇） |

### 3.5 Agent 专项安全（汇总 + 服务端防线）

细节（沙箱、权限模式、提示注入防御、本地审计 JSONL）见 **09 篇**；本篇固化服务端防线：

| 防线 | 措施 | 联动 |
|---|---|---|
| 工具调用限流 | Agent/OBO 通道独立限流阈值（严于用户通道，14篇§5.1；03篇§6.3）；单会话 QPS 上限 + 突发桶 | 超限 9003，计入 §6 指标 |
| 异常检测 | 高频写操作、批量删除、重复失败循环等模式检测（滑动窗口计数）→ 告警 + 自动降速/挂起会话 | 09 篇权限门控、16 篇告警 |
| OBO 审计对账 | 服务端 audit 记录（actor=agent:*）与客户端本地上报的 Runtime JSONL 摘要**每日抽样比对**（admin_task(type=security_reconcile)，12篇） | 差异 → P1 安全告警 |
| 失控止损 | ① 管理员吊销指定 Agent 会话：`agent.revoked` 推送（03篇§6.4）宿主立即终止；② 租户级暂停 Agent 开关（admin:policy:manage）；③ **全租户暂停 Agent 总开关**（platform:agent:killswitch，12篇§6.1），用于平台级事件应急 | 12 篇矩阵：总开关需双人审批 |

### 3.6 多租户隔离验证

| 验证项 | 方式 | 频率 |
|---|---|---|
| RLS 单元测试强制 | CI 强制：所有仓储层测试继承统一基类（TenantIsolationTestCase），内置断言"以租户 A 上下文读/写租户 B 数据必须 0 行/报错"；未覆盖新表的流水线**阻塞合并** | 每次 CI |
| 渗透测试用例清单 | ① 跨租户读：篡改 `tenant_id`、直接猜资源 ID 访问；② 注入：SQL 注入（REST 参数/检索语法）、命令注入（Agent 工具入参）、提示注入（09 篇样例集）；③ 越权：无权限点调用 `admin:*`/`platform:*`、数据范围越界（部门外用户）、ACL 绕过（构造 grant_type）；④ API 侧行为：Idempotency-Key 重放、预签名 URL 越权与过期重用 | 发布前全量 + 大版本前第三方渗透（§3.8） |
| 对象存储前缀逃逸 | 构造 `../`、绝对 key、空租户 ID、超长路径等访问他租户对象；预签名 URL 换 key 重放 | 同上 |
| 缓存隔离 | Redis key 无前缀读写扫描（代码扫描 + 运行断言） | CI |

### 3.7 合规与审计

| 项 | 设计 |
|---|---|
| 审计不可篡改 | audit 事件**哈希链**：每事件含 `prev_hash`/`hash`（租户内单调 seq 串联），追加写；**每日锚点**：各租户链头哈希写入独立库的 `audit_anchor` 并导出至 WORM/离线归档；周期校验任务重放比对，断裂 → P1 告警并冻结审计导出（流程见 §4.2） |
| 保留期 | 审计日志默认 **3 年，租户可配（1–10 年）**（12篇 admin_policy: compliance.audit_retention_days）；与消息漫游保留（默认 180 天，14篇§4.2）相互独立 |
| 数据主体权利 | **导出**：用户级数据打包任务（消息/文件清单/文档列表，admin_task）；**删除**：禁用 + 匿名化（保留审计骨架，抹去 PII 字段）；两流程均走管理后台并留痕 |
| 私有化数据不出边界声明 | 默认全组件内网闭环：模型走内网 vLLM 或租户**明示授权**的外部 API（出边流量单独计量与审计）；遥测默认关闭，开启时仅内网 OTel Collector；更新源内网化（16篇）；客户端不含任何公网回传通道 |
| 审计事件字段 | 统一 `subject/actor/action/resource/result/trace_id`（03篇§6.3）；Agent 动作 actor=`agent:{会话}`，双记录可归因 |

### 3.8 安全开发生命周期（SDL）

| 环节 | 措施 |
|---|---|
| 依赖扫描 | 客户端（cargo audit + npm audit）、服务端（govulncheck）CI 每次构建；高危漏洞阻塞合并，例外需安全会签 + 限期 |
| 密钥扫描 | gitleaks 类工具扫描全部提交与分支历史；命中即流水线失败 + 事件单 |
| 代码审查红线 | 以下文件变更需**安全会签**：权限判定中间件、RLS 策略与迁移、审计写入、密钥/凭证处理、capability/Tauri 权限清单、限流配置 |
| 渗透测试节奏 | 每大版本发布前第三方渗透 + §3.6 用例全量回归；季度红蓝演练（含 Agent 场景） |
| 漏洞响应 SLA | 见 §4.3（P0 1 h 响应/24 h 修复，24 h 内通报受影响租户）；通报模板要素：编号/级别/影响面/受影响数据/原因/缓解/时间线/联系人 |
| 安全需求前置 | 涉及新数据类别的需求须先过 §3.9 分级表定级并补齐对应控制措施 |

### 3.9 数据分类分级表

分级：L1 公开 / L2 内部 / L3 机密 / L4 受限（最高）。

| 数据 | 级别 | 传输 | 存储 | 访问审计 | 导出/共享控制 |
|---|---|---|---|---|---|
| 消息内容 | L3 | TLS/WSS | PG 加密 + 本地 SQLite OS 级加密 | 会话内访问审计（合规策略范围内，12篇） | 撤回窗口/保留期策略；审计导出含水印与限流 |
| 文件/文档本体 | L3 | TLS + 预签名 | MinIO SSE-S3 + 桶策略 | 下载/预览入审计 | ACL + 分享链接时效；批量下载限流 |
| 知识库内容 | L3（敏感标记节点视同 L4 管控） | TLS | PG + pgvector（加密盘） | kb.query 全量审计（OBO 可归因） | 检索结果带权限过滤（11篇）；敏感节点显式拒绝 |
| Agent 会话/上下文 | L3（含用户代码即随代码定级） | TLS（SSE/REST） | 默认仅本地（02篇§5），云端备份默认关 | 本地 JSONL + 服务端 OBO 审计对账（§3.5） | 不提供管理端直接读取，仅元数据 |
| 审计日志 | L2 内容 / **L4 完整性** | TLS | 追加写 + 哈希链 + 每日锚点 | 读取本身入审计 | 元数据/内容项分级导出（12篇§7.2） |
| 用户 PII（姓名/邮箱/手机号） | L2 | TLS | PG 加密 | 批量查询限流 + 审计 | 匿名化删除流程（§3.7） |
| 凭证与密钥（口令哈希、MFA 秘密、refresh token、代持凭证、签名私钥） | **L4** | TLS | argon2id / 钥匙串 / KMS 信封 | 任何读取告警 | 永不导出；日志脱敏 |

## 4. 核心流程

### 4.1 密钥轮换流程（以 ES256 kid 双钥窗口为例）

```
t0  KMS/HSM 生成新密钥对 kid=N ──► JWKS 追加发布（N 与旧 kid=O 并存）
t1  auth 切换签发：新 token 一律 kid=N；kid=O 仅用于验签
t2  等待窗口：token 最长 TTL=15 min → 保守保留 O 至 t1+24 h（覆盖离线端时钟漂移）
t3  JWKS 移除 O ──► 私钥离线归档/销毁（全程审计）
客户端策略：JWKS 缓存 ≤1 h；验签遇未知 kid → 强制拉取 JWKS 重试一次再判失败

ed25519 更新签名密钥：清单双签重叠（同时携带新旧签名），客户端版本 ≥ vX 才信任新钥；
                      更新看板覆盖 ≥99% 且 ≥90 天后撤销旧钥（10篇签名链联动）
模型 Key/代持凭证：双凭证并行 → 新凭证引流 10%→50%→100% → 吊销旧凭证；失败即回切
```

### 4.2 审计哈希链生成与校验流程

```
生成（写入路径）：
  audit-svc 落事件 → hash = H(prev_hash ‖ canonical(event))
  → 更新链头（租户内 seq 单调） → 追加写，禁改禁删（DB 权限 + 应用双重保证）

锚点（每日 00:05 定时任务）：
  取各租户链头 head_hash → 写 audit_anchor（独立数据库账号，仅 INSERT）
  → 导出锚点文件（含前日全链摘要）至 WORM 存储/离线归档 → 锚点动作本身留痕

校验（周期任务 + 按需触发）：
  重放区间哈希链 → 与最近锚点比对
  ├─ 一致 → 记录指标 chain.verify.ok
  └─ 断裂/缺失 → P1 告警（16篇§6.5）+ 冻结审计导出 + 安全事件流程（§4.3）
```

### 4.3 漏洞响应与通报流程

```
发现（外部报告/扫描/监控）→ 定级（CVSS + 业务权重）
 → P0: 1h 响应组就位；隔离/止血（killswitch、吊销、封禁）
 → 修复: P0 ≤24h / P1 ≤72h / P2 下一版本（含回归用例入库 §3.6）
 → 通报: P0/P1 24~72h 内通知受影响租户（模板 §3.8）；内部复盘入审计
 → 补丁走正常发布通道，紧急通道允许跳过灰度（登记豁免）
```

### 4.4 安全例外与豁免管理

```
例外申请（如：暂时跳过依赖升级、放宽某内网段 ACL）
 → 工单：申请人/原因/影响面/补偿措施/到期日（最长 90 天，不得续期超过一次）
 → 审批：安全负责人 + 业务负责人双签（P0 风险须平台运营会签，12篇矩阵同源）
 → 台账：例外清单纳入月度安全例会复盘；到期未关闭 → 自动告警并转 P2 事件
 → 补丁发布豁免（§4.3 紧急通道）同样入此台账，事后补回归用例（§3.6）
```

## 5. 数据模型（安全域）

> 汇总登记至 13 篇。

```
security_key(                    -- 密钥台账（KMS/信封加密）
  id, tenant_id nullable,        -- 租户级密钥（代持凭证）可空=平台级
  key_type,                      -- model_api | app_delegate | jwt_es256 | update_ed25519 | dek
  kid,                           -- 轮换标识（JWT 类必填）
  material        bytea,         -- 密文（DEK 包裹的私钥/凭证；公钥明文字段另存）
  status,                        -- active | retiring | retired
  activated_at, retire_at, rotated_from,
  created_at)
  约束: 私钥 material 仅经 KMS/信封解密于内存使用；读取动作入审计并告警

audit_anchor(                    -- 审计链每日锚点（独立库/账号，仅追加）
  id, anchor_date, tenant_id,
  head_hash, event_count,
  signature,                     -- 由离线锚点密钥对 head_hash 签名（可验锚点真伪）
  external_ref,                  -- WORM/离线归档位置
  created_at)

audit_event（安全字段约束，主表归 audit 域/13 篇）:
  追加 seq(tenant 内单调) / prev_hash / hash / anchor_date；
  DB 层 REVOKE UPDATE, DELETE；写入与校验指标见 §6
```

## 7. 边界与预案

| 场景 | 预案 |
|---|---|
| TLS 根 CA 私钥泄漏 | 立即吊销根 → 紧急发布预置新根的客户端强更（16篇§4.2 强更通道）→ 全服务重签；事后全量审计复查 |
| ES256/ed25519 私钥泄漏 | 按 §4.1 反向执行：新 kid 签发 + 旧 kid 立即出吊销名单（Redis jti 机制扩展）→ 强制全端重新登录；更新签名泄漏则升级为 P0 供应链事件 |
| 无 KMS 的离线环境 | 降级信封加密（§3.3），KEK 双人分持；文档声明残余风险与升级路径 |
| 内网无法访问公共 CRL/OCSP | 固定根 CA（pinning）本身免除外部信任链；内部 CA 配套内网 OCSP 响应器或以周期分发 CRL 替代 |
| 高保密租户要求 E2EE | 01 篇 §7 已声明延后：作为租户可选特性设计（端到端加密会话与审计/合规检索的冲突由"可检索的客户端侧密钥托管"折中），本篇不展开 |
| Break-glass（应急超管） | 03 篇开放问题；若引入：双人开启、全程录像级审计、24 h 自动回收 |
| 审计锚点任务连续失败 | 视同链断裂处理（P1）；WORM 归档不可用期间锚点降级为"双库异地写" |
