## 1. 功能概述

文档域（doc-svc）提供企业级在线文档能力，覆盖以下场景：

| # | 场景 | 说明 |
|---|---|---|
| S1 | 新建/编辑 Word·Excel·PPT | OnlyOffice Document Server CE 集成，WOPI 协议（01 篇 §5.4 已定稿） |
| S2 | 聊天文件一键"转为协作文档" | IM 收到的 docx/xlsx/pptx 等转为可协作 doc_file，会话内回发文档卡片 |
| S3 | 只读预览 | 非编辑场景统一走 PDF 预览管线（LibreOffice headless） |
| S4 | 多人协同编辑 | OnlyOffice 协同协议，实时合并；IM 卡片/列表展示在线状态与协作头像 |
| S5 | 评论与 @提及 | OnlyOffice 原生评论；@提及由壳层捕获并转 IM 通知 |
| S6 | 版本历史与恢复 | 自动快照（每 5min/会话关闭）+ 手动恢复（恢复产生新版本，不覆盖） |
| S7 | 模板库（租户级） | 管理员上传模板，全员新建时可选；基于模板创建 = 复制到个人空间 |
| S8 | 回收站 | 删除软回收，保留期（默认 30 天，租户可配）内可恢复/彻底删除 |

设计基线：单文件默认上限 10 GB 是**文件域（07 篇）**口径；本域"可在线编辑/可预览"的文件另设更低上限（§7）。

## 2. 角色与场景

| 角色 | 典型操作 | 关键约束 |
|---|---|---|
| 普通成员 | 新建/编辑/分享自己的文档、用模板、从 IM 转协作文档、申请他人文档权限 | `doc:file:create` `doc:file:edit` `doc:share:create` |
| 文档查看者/评论者 | 只读预览、加评论、@提及 | 由资源 ACL 决定，禁止触发 PutFile |
| 部门管理员 | 管理部门公共区文档、处理权限申请 | 数据范围=本部门及以下 |
| 租户管理员 | 模板库管理、水印/保留期策略、锁定文档、撤链接 | `doc:template:manage` 等 |
| 审计合规员 | 文档访问审计检索/导出 | `doc:audit:read`，只读 |
| Agent（OBO） | 不直接进入编辑器；仅读元数据/版本/触发"Agent 产出转协作文档" | 一切以用户身份（03 篇 §6） |

## 4. 核心流程

### 4.1 WOPI 集成架构

```
┌──────────────────────── 客户端（Tauri）────────────────────────┐
│  UI: 文档中心 / IM 文档卡片                                      │
│   └─ WebView iframe：OnlyOffice 编辑器（JS API + DS 静态资源）     │
└─────┬────────────────────────────────────────────┬────────────┘
      │ HTTPS（编辑器资源 + 协同 WebSocket 均终止于 DS） │ REST /api/v1/doc/*
      ▼                                            ▼（会话/心跳/续期/版本）
┌───────────────────┐    WOPI REST（每次请求带     ┌────────────────────────┐
│ OnlyOffice DS CE   │◄── access_token，逐请求鉴权）─│ doc-svc（WOPI Host）     │
│ docker 独立部署    │  CheckFileInfo / GetFile /   │  会话管理 · 权限 · 版本    │
│ 协同协议在 DS 内部  │──► PutFile / PostAction      │  模板 · 回收站 · 审计     │
│ 完成多人实时合并    │                              └────┬────────────┬──────┘
└───────────────────┘                                   │            │
                                                   ┌────▼─────┐ ┌───▼──────────┐
                                                   │ MinIO    │ │ PG16          │
                                                   │ 工作副本/  │ │ doc_* 表 +    │
                                                   │ 版本对象/  │ │ resource_acl  │
                                                   │ 预览PDF   │ │ (03篇§4.4)    │
                                                   └──────────┘ └──────────────┘
```

要点：

| # | 要点 | 说明 |
|---|---|---|
| 1 | 编辑流量不经过我方 UI | iframe 直连 OnlyOffice DS；客户端壳层只管会话创建/关闭/心跳与壳层 UI |
| 2 | 会话 access token 短时效 | JWT，exp ≤ 10min，绑定 `session_id + user + file + mode + did`；滚动机制见 §4.3 |
| 3 | 每次 WOPI 请求按用户鉴权 | doc-svc 对 CheckFileInfo/GetFile/PutFile 逐请求执行 03 篇三层判定（RBAC `doc:file:edit` → 数据范围 → resource_acl），结果决定能力集；绝不因"会话已建立"而跳过 |
| 4 | 文件本体只存 MinIO | doc-svc 以流式读写 MinIO，不落本地盘；对象布局见 §5.8 |
| 5 | OnlyOffice 与 MinIO 不直连 | DS 无 MinIO 凭据，一切字节流经 doc-svc（便于审计与病毒扫描钩子） |

### 4.2 打开文档全时序（编号步骤）

```
 1. 用户点击文档卡片 → 客户端 REST: POST /api/v1/doc/files/{id}/session {intent:auto|view}
 2. doc-svc 三层鉴权: RBAC(功能入口) → 数据范围 → resource_acl 得有效 perm
    → 折叠打开模式: owner/editor→edit, commenter→comment, viewer→view
    → perm 不足 view 则 6001/2003
 3. 建 doc_session(token_family, JWT exp≤10min) → 返回
    { action_url(OnlyOffice 编辑器页), wopi_src(doc-svc WOPI 端点), access_token,
      mode, file:{id,name,format,version}, presence:{participants} }
 4. 客户端 WebView iframe 加载 action_url，编辑器配置注入 document.url=wopi_src + token
 5. OnlyOffice DS → GET /wopi/files/{id}?access_token=…（CheckFileInfo）
    doc-svc: 验签 + 会话有效 + 按用户重算权限
    → 返回元数据与能力: 可编辑/可下载/可打印/可复制/水印用户名(策略) 等
 6. OnlyOffice DS → GET /wopi/files/{id}/contents
    doc-svc: 同上鉴权(perm≥viewer) → 从 MinIO 流式返回当前工作副本
 7. 多人编辑: 输入经 DS 协同协议实时合并(DS 内部 WebSocket, 我方不感知)
 8. DS 节流自动保存(静默约10s/关闭前强制保存点)
    → POST /wopi/files/{id}/contents(PutFile)
    doc-svc: 鉴权(perm≥editor, 否则403→编辑器自动转只读+提示) → 写 MinIO 工作副本(写穿)
 9. 快照策略: 会话内每 5min 将工作副本固化为 doc_version(不可变对象)
10. doc-svc 发 doc.updated(kind=version) → 其他编辑参与者/列表/IM 卡片刷新
11. 关闭 iframe → 客户端 POST /doc/files/{id}/session/close
    → 该用户最后一个会话结束时: 终版快照 + 会话关闭 + doc.updated(kind=closed)
```

### 4.3 会话令牌滚动与回收（token ≤ 10min 滚动）

| 机制 | 说明 |
|---|---|
| 初始时效 | JWT exp = 10min，payload：`{sid, sub, file, mode, did, fam}` |
| 滚动续期（双通道） | ① 编辑流量：任一 WOPI 请求校验通过即顺延该 token_family 的服务端 deadline +10min（编辑器自动保存天然产生流量）；② 宿主心跳：客户端每 5min 调 `POST /doc/files/{id}/session/heartbeat`（用户身份 + iframe 存活检测）续期 |
| 失效判定 | 距最后一次有效流量/心跳 > 10min → token 过期；下一次 WOPI 请求 401 → DS 报连接错误 → 客户端捕获后静默重开（OnlyOffice 本地缓存约 10min，内容不丢，见 §7.2） |
| 即时吊销 | 会话关闭 / 权限被收回（doc.updated 触发重算）/ 用户登出 / `force.logout` → session 表置 revoked，token 立即失效 |
| 孤儿回收 | 心跳与 WOPI 流量均停止：10min 标记 orphan（可被重开唤醒）；30min 强制结束会话并触发终版快照（§7.3） |

### 4.4 权限模型（四档 + 分享 + 水印 + 审计）

有效权限 = 03 篇三层判定结果，落点为 resource_acl `perm`：

| 档位 | resource_acl.perm | 能力 |
|---|---|---|
| 查看者 | viewer | 预览/在线只读、下载（可被分享链接"禁止下载"收窄）、搜索命中 |
| 评论者 | commenter | viewer + 评论与 @提及（OnlyOffice 审阅模式） |
| 编辑者 | editor | commenter + 内容编辑(PutFile)、恢复版本、重命名 |
| 所有者 | owner | editor + 授权/撤销、删除入回收站、转让、创建分享链接 |

**租户内链接分享**（doc_share）：

| 属性 | 取值 |
|---|---|
| 链接范围 | 仅租户内登录用户（无匿名外链，外部分享走 07 篇文件域并强制水印/审计） |
| 权限上限 | view / comment（链接权限 ≤ 所有者授予链接创建者的上限） |
| 有效期 | 1h / 1d / 7d / 30d / 永久（租户策略可封顶） |
| 密码 | 可选（访问时二次校验） |
| 禁止下载 | 可选（CheckFileInfo 返回 `download=false`，DS 隐藏下载入口；PDF 预览侧禁右键/另存） |

**水印策略**：租户开关 + 文档可覆盖。开启时预览 PDF 由转换 worker 叠加动态水印（`用户名 + 工号 + 时间 + IP`）；编辑视图由客户端壳层全幅半透明覆盖水印（OnlyOffice 内嵌水印依赖其版本能力，见 §9 开放问题）。

**访问审计**：打开/预览/下载/分享创建/撤销/版本恢复/权限变更全部写 audit 域（哈希链，03 篇），`doc:audit:read` 可检索导出；Agent 触发（OBO act）单独标记。

### 4.5 版本管理

| 项 | 设计 |
|---|---|
| 自动快照 | 编辑会话内每 5min 一版；会话关闭（最后编辑者离开）终版；版本对象不可变：`…/doc/{fid}/v{n}/{name}` |
| 手动快照 | 编辑者可"保存版本并备注"（snapshot_type=manual） |
| 版本列表 | 版本号、快照类型(auto/close/manual/restore/import)、作者、时间、大小、备注 |
| 版本对比 | 入口在"历史版本"：选两版 → `POST /doc/files/{id}/versions/diff` 返回 OnlyOffice 对比视图 action_url+token；DS 版本不支持时降级为"双版本 PDF 并排预览"（§7.6） |
| 恢复 | 恢复 = 把目标版本对象复制为新版本 vN+1（snapshot_type=restore，备注"恢复自 vK"），当前版本指针前移；**绝不覆盖既有版本**；恢复者需 perm≥editor |
| 版本下载 | 任意版本可单独下载（受下载权与水印策略约束） |

### 4.6 预览管线（非编辑场景）

```
请求预览 GET /doc/files/{id}/preview
 → 已有缓存且版本匹配? ──是──► 返回预签名 PDF URL（短期）
 → 无/版本更新 ──► 入 LibreOffice headless worker 队列（Redis Stream）
      状态 converting（前端轮询/WS doc.updated kind=preview_ready）
      完成 → PDF 存 MinIO …/preview/{fid}/v{n}.pdf → 返回
      失败/超限 → 6003 → 降级: 提供原文件下载（07 篇下载票据）
```

| 格式 | 在线编辑 | PDF 预览 | 说明 |
|---|---|---|---|
| docx / xlsx / pptx | ✅ | ✅ | 主路径 |
| doc / xls / ppt | ❌（转存为 docx 后可编辑，转换后新版本） | ✅ | legacy 经 LibreOffice 转换 |
| md / txt / csv | ❌（只读预览 + 源文件编辑下载） | ✅（渲染为 PDF） | |
| pdf | ❌ | ✅（原生直出，无需转换） | |

大小限制（默认，租户可配）：在线编辑 ≤ 100 MB；预览转换 ≤ 200 MB；超限 → 6007 + 降级下载。

### 4.7 模板库与回收站

- **模板**：管理员（`doc:template:manage`）上传 OOXML 模板（分类/名称/封面缩略图）→ doc_template 登记，对象存 `…/template/{tid}/{tpl_id}`；全员"从模板新建"（`doc:template:use`）= 复制模板对象为新 doc_file v1（snapshot_type=import）到**个人空间**；模板下架不影响已创建文档。
- **回收站**：删除 = doc_file.status=trashed + doc_trash 记录（保留期默认 30 天，租户 7–90 可配）；保留期内本人或 owner/管理员可恢复（同名冲突自动追加" (恢复)"）或彻底删除（级联清除对象、版本、ACL、分享链接、预览缓存，audit 留痕）；到期定时任务自动彻底删除；`doc:trash:purge` 可清空本人回收站。

### 4.8 与 IM 联动（详见 04 篇消息类型）

| 联动点 | 设计 |
|---|---|
| 文档卡片消息（type=doc_card） | 展示：图标/标题/在线编辑状态（N 人编辑中）/协作头像列表/最新版本号；点击卡片 = §4.2 步骤 1 |
| 聊天文件一键转协作文档 | 文件消息 →"转为协作文档"→ `POST /doc/files/import {file_id, conv_id}`：doc-svc 从 file 域**复制**对象（源文件不动）→ 可编辑格式落 v1，其余格式建只读型 doc_file → 会话内回发 doc_card |
| 转发文档 = 转发授权提示 | 转发 doc_card 时客户端本地检查接收方是否在 ACL（可命中本地权限摘要缓存）；无权限接收方看到卡片为"🔒 需申请权限"态 → `POST /doc/files/{id}/permissions/request` → owner 收 `doc.access.requested`（经 notify）→ 批/拒（授予 viewer/editor）→ 双方收 doc.updated(kind=perm) |
| 评论 @提及 | 评论内容随 OOXML 存储；@提及由壳层捕获 OnlyOffice 插入评论事件 → 解析 @user → `doc.mention` 推送 + IM 卡片（含跳转锚点 anchor） |
| Agent 产出 | Agent 生成的 docx/xlsx（经用户确认）→ 转协作文档入库，source_type=agent（08/09 篇） |

## 5. 数据模型（本域，物理表清单入 13 篇）

> 单一事实源：资源授权一律写 03 篇 `resource_acl`（resource_type=`doc_file`）；`doc_permission` 为域内投影视图表（同事务双写），供列表联查/批量失效加速。

### 5.1 doc_file（文档元数据，当前版本指针）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | bigint | 雪花 ID |
| tenant_id | bigint | RLS |
| name | text | 名称（含扩展名） |
| doc_type | text | word/excel/ppt/md/txt/csv/pdf |
| editable | bool | 是否 OnlyOffice 可编辑格式 |
| owner_id | bigint | 所有者 |
| current_version_id | bigint | 当前版本指针 → doc_version |
| version_seq | int | 版本计数（单调） |
| working_key | text | MinIO 工作副本对象键（被 PutFile 写穿更新） |
| size | bigint | 当前字节 |
| status | text | active / trashed |
| source_type | text | created / imported(聊天文件) / template / agent |
| source_ref | text | 源引用（file_id / template_id / agent_session） |
| last_activity_at | timestamptz | 最后编辑/打开 |
| created_at / updated_at / deleted_at | timestamptz | |

### 5.2 doc_version（版本）

| 字段 | 说明 |
|---|---|
| id, tenant_id, file_id | — |
| version_no | 会话内递增，= file.version_seq 快照值 |
| storage_key | 不可变版本对象键 |
| size, sha256 | 校验与秒传复用 |
| snapshot_type | auto(5min) / close / manual / restore / import |
| note | 手动备注/恢复说明 |
| created_by, created_at | 快照触发者（auto 取最后一个活跃编辑者） |

### 5.3 doc_permission（resource_acl 域内视图）

| 字段 | 说明 |
|---|---|
| id, tenant_id, file_id | — |
| grant_type / grant_target | user / dept / role / tenant（03 篇 §4.4） |
| perm | viewer / commenter / editor / owner |
| granted_by, expires_at, created_at | 过期授权到期自动失效并失效 ACL 缓存 |

### 5.4 doc_session（编辑会话）

| 字段 | 说明 |
|---|---|
| id, tenant_id, file_id, user_id | 一个用户对一文档可多会话（多窗口/多端） |

## 7. 边界 / 异常 / 降级

### 7.1 并发冲突

| 场景 | 处理 |
|---|---|
| 协同编辑者之间 | OnlyOffice DS 协同协议在 DS 内合并，PutFile 一定是**全量一致性快照**，无互相覆盖 |
| 外部非法并发（绕过编辑器：对象直改/离线改后经文件域回传/恢复旧基线） | PutFile 校验 `base_version`：落后或 sha256 基线不符 → 拒绝 6004，落"分叉副本"为独立版本并提示：在 OnlyOffice 对比视图中选择合并，或以新基线重开 |
| 同名恢复/导入冲突 | 名称追加后缀，不阻塞操作 |

### 7.2 断线编辑

OnlyOffice 前端本地缓存约 10min：DS 不可达/网络闪断期间可继续编辑，重连后自动续传；超过 10min 未重连 → 编辑器提示"连接丢失"，未保存内容由客户端引导手动复制；doc-svc 侧对应会话按 §4.3 孤儿回收路径处理，**回收前强制尝试终版快照**（若 DS 存有该会话状态）。

### 7.3 孤儿编辑会话回收

心跳与 WOPI 流量均停止 10min → orphan 标记（客户端重开 iframe 可唤醒并重新续期）；30min 仍无流量 → 强制关闭：触发终版快照、清 session、发 doc.updated(kind=closed)。防泄漏：会话关闭即吊销 token_family。

### 7.4 OnlyOffice 故障（对齐 02 篇 §7）

健康探测失败 → 新打开请求自动降级为 PDF 预览（LibreOffice 管线，与 OnlyOffice 独立）；进行中的编辑会话依赖 7.2 本地缓存；恢复后提示"重新进入编辑"。

### 7.5 预览转换故障/积压

worker 队列积压（>5min）→ 返回 converting+排队位次；LibreOffice 失败 3 次重试后 6003 → 降级提供原文件下载（07 篇票据，受下载权与水印约束）。

### 7.6 其它

| 场景 | 处理 |
|---|---|
| 版本对比能力缺失（DS 版本差异） | 降级"双版本 PDF 并排预览" |
| 权限会话中被收回 | CheckFileInfo 能力降级/PutFile 403 → 编辑器转只读 + toast 提示 |
| 租户禁用/用户离职 | `force.logout` → 会话与 token 全吊销；文档 owner 空缺由管理员接管（12 篇） |
| 工作副本损坏（sha256 校验失败） | 回退上一版本对象为工作副本 + 管理员告警 + audit |

## 9. 开放问题

1. OnlyOffice CE 当前版本是否内置文档级水印与差异对比视图？缺失则长期采用壳层水印 + PDF 并排对比，或评估商业版。
2. 会话令牌滚动采用"服务端 deadline 顺延"实现（WOPI 无标准 token 刷新）；若后续 DS 支持 token 轮换回调，切换为硬 exp 短令牌。
3. 文档中心是否需要个人文件夹层级（当前为权限视图扁平模型）？若需要，引入 doc_folder 并扩展继承链。
4. legacy 格式（doc/xls/ppt）转存编辑的自动化程度：静默转换 or 用户确认（涉及排版损失提示）。
5. 协作者人数上限（默认 50 并发编辑/文档，租户可配）与 6002 的具体阈值压测待定。
