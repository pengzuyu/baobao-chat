## 1. 功能概述

### 1.1 背景与定位调整

编码是高门槛能力：自研循环要达到 Claude Code / zcode 的项目级编码质量，投入产出比低。因此本产品的 Agent 架构采用**编排与执行分离**：

```
┌───────────────────────────────────────────────────────────────────┐
│ 编排层（自研 Agent Runtime，08 篇）                                  │
│  需求澄清 · 公司上下文收集(KB/文档/OA) · 任务拆分 · 委派 · 审查 · 汇总 │
│  权限门控 · 审计 · OBO 鉴权（公司域工具只有编排层持有凭证）             │
└───────────────┬───────────────────────────────────────────────────┘
                │ CodingBackend 统一适配接口（本篇 §3）
┌───────────────┼───────────────────────────────────────────────────┐
│ 编码执行后端（可插拔，按优先级）                                       │
│  ① Claude Code（本地 CLI，headless 模式）   ② zcode（本地 CLI）      │
│  ③ 其他（Codex / Gemini CLI / …，适配器扩展点）                       │
│  ④ 内置后端（08 篇自研编码循环，兜底）                                 │
└───────────────────────────────────────────────────────────────────┘
```

**一句话**：用户对 BaobaoWork 的 Agent 说"帮我在订单服务里加个退款接口"，编排层从知识库捞回服务规范、从文档中心捞回接口约定，生成任务简报，交给 zcode/Claude Code 在本地项目里实现，改动以 diff 审查卡回到用户面前——全过程在 BaobaoWork 一个 UI 内完成、一套权限门控、一份审计。

### 1.2 设计目标

| # | 目标 | 说明 |
|---|---|---|
| 1 | 可插拔后端 | 新增一个编码智能体只需实现一个适配器，不动编排层 |
| 2 | 权限不旁路 | 委派出去的任务仍受 09 篇权限模式约束；**子智能体不持有任何公司凭证** |
| 3 | 审计不缺位 | 子智能体的每次工具使用被归一化记录进本地审计 JSONL（09 篇） |
| 4 | 体验一体化 | 进度流、审批卡、diff 审查、结果汇总都在 BaobaoWork 的 Agent 工作台 |
| 5 | 兜底可用 | 无外部后端时自动降级到内置编码循环（08 篇） |

### 1.3 后端对比与默认策略

| 后端 | 编码质量 | 可用条件 | 我们的集成方式 | 定位 |
|---|---|---|---|---|
| Claude Code | 高（项目级编辑/命令/子任务成熟） | 用户本机已安装并登录 | headless CLI（`claude -p` + stream-json） | 首选之一 |
| zcode | 高（同上，且与本公司模型生态亲和） | 用户本机已安装并登录 | headless CLI（对齐其 CLI 协议） | 首选之一 |
| 其他 CLI 智能体 | 视产品 | 各自安装 | 通用行协议适配器（降级为纯文本流） | 扩展点 |
| 内置后端（08 篇） | 中（轻量编辑/脚本够用） | 无依赖，永远可用 | 进程内循环 | 兜底 + 轻量任务 |

| 审计合规员 | 追查"这次代码改动谁做的" | 审计链：编排会话→委派任务→子智能体 tool_use 事件（本地 JSONL + 服务端 OBO 审计） |

## 3. 后端抽象与适配器

### 3.1 CodingBackend 统一接口

编排层只依赖此抽象（Rust trait / 消息协议）：

| 方法 | 入参 | 出参/行为 | 说明 |
|---|---|---|---|
| detect() | — | {installed, path, version, capabilities} | 探测安装与能力 |
| probe_health() | — | ok / 降级原因 | 会话前健康检查（版本、登录态） |
| launch(task_brief, opts) | 简报+工作区+权限映射 | 子进程 + 会话句柄 | headless 启动 |
| stream_events() | — | 归一化事件流（§3.3） | 订阅子进程输出 |
| send_input(text) | 用户/编排层追加指令 | — | 追问、补充约束 |
| cancel(graceful) | — | SIGINT→3s→SIGKILL 进程树 | 紧急停止 |
| finalize() | — | {summary, changed_files, session_ref} | 收尾：提取改动清单与续接句柄 |

### 3.2 各后端适配要点

| 后端 | 启动形态 | 事件通道 | 权限映射 | 会话续接 |
|---|---|---|---|---|
| Claude Code | `claude -p "<简报>" --output-format stream-json --verbose`（cwd=项目工作区） | stdout stream-json（system/result/assistant/tool_use 等消息） | `--permission-mode`（plan/acceptEdits/bypassPermissions 受我们门控换算，见 §5.2）+ `--allowedTools`/`--disallowedTools` 白黑名单 | `--resume <session>` |
| zcode | 等价 headless CLI（协议细节以实际 CLI 文档为准，适配器内隔离差异） | 同类 JSON 事件流（缺字段则降级文本行） | 同上思路（命令级白名单/确认模式） | 会话续接参数 |
| 通用 CLI | `spawn(bin, args)`，stdin 喂简报 | 仅 stdout 行文本 → 包装为 `stream.delta` | 无法细粒度映射 → 仅允许 auto-edit 模式以上委派，且工作区只读或强 diff 审查 | 不支持则每次新会话 |
| 内置后端 | 进程内直接调用 08 篇循环 | 天然归一化事件 | 09 篇权限矩阵原生生效 | 会话文件 |

> MCP 说明：Claude Code / zcode 均支持 MCP。**一期不采用**"把我们编排层做成 MCP server 给子智能体回调公司工具"的方案（会让子智能体间接持有公司域能力，权限模型复杂化）；二期评估作为增强通道（此时工具调用仍经编排层 OBO 转发、审计不旁路，见 §9 开放问题）。

### 3.3 事件归一化（子智能体 → 我们的事件模型）

| 子智能体事件 | 归一化为（08 篇 stdio JSONL） | 审批联动 |
|---|---|---|
| 流式文本输出 | `stream.delta` | — |
| 工具调用请求（编辑/命令） | `tool_call`（带 source=backend 标记） | 按权限模式决定：自动放行 / 升级为审批卡（§5.2） |
| 工具结果 | `tool_result` | — |
| 子智能体内部权限询问（headless 下不应出现，出现即异常） | `delegate.warning` | 提示用户改用支持非交互模式的参数组合 |
| 进程退出 | `delegate.end`（exit_code, summary） | 触发 diff 审查卡 |

## 4. 委派协作模式

| 模式 | 流程 | 适用 | 审查粒度 |
|---|---|---|---|
| A 全程委派 | 编排层生成任务简报→后端一次跑完→整体 diff 审查 | 边界清晰的单任务（改一个函数/加一个页面） | 一次（任务级） |
| B 分步协同 | 拆 N 个子任务→逐个委派→逐个 checkpoint+审查→下一个 | 大特性/跨模块改造 | 每子任务 |
| C 会话续接 | 对同一后端会话追问/返工（`--resume`） | "再改改刚才那个" | 增量 diff |
| D 内置兜底 | 无可用后端或任务过轻（改个文案） | 轻量编辑、无后端环境 | 09 篇原矩阵 |

**任务简报（Task Brief）格式**——编排层的核心增值在右列"公司上下文注入"：

```yaml
task: 在订单服务 order-svc 增加 POST /refunds 退款接口
workspace: /Users/dev/repos/order-svc          # 委派边界=工作区白名单（§5.1）
constraints:                                    # 来自项目 AGENTS.md + 用户补充
  - 遵循仓库现有分层（controller/service/repo）
  - 使用 Go 1.22，禁止引入新框架
context:                                        # 编排层用公司域工具（OBO）检索注入
  - 来源: kb:公司空间/《订单域接口规范v3》→ 摘录: 错误码/鉴权要求…
  - 来源: doc:接口约定文档 #42 → 摘录: 请求响应结构…
  - 来源: im:与产品经理的确认结论 → 摘录: 仅支持整单退款
acceptance:
  - 编译通过（make build）
  - 单测覆盖退款分支
forbidden: [修改 db/migration 目录, 触碰部署脚本]
```

**后端选择顺序**：用户显式指定（"用 zcode 做"）> 项目配置（AGENTS.md 中 `preferred_backend`）> 用户默认设置 > 自动（健康检查 + 任务复杂度：重任务选外部后端，轻任务内置）。

## 5. 权限与安全（与 09 篇联动）

### 5.1 委派边界

- **工作区白名单**：子进程 cwd 与文件访问被限定在项目工作区（符号链接检查同 09 篇）；工作区外的读写请求会被编排层拒绝并提示。
- **凭证隔离（关键）**：**任何公司凭证不下发**。OBO token、生态应用凭证、模型 Key 都只在编排层；子智能体需要公司信息时，由编排层检索后以**文本注入简报**。子智能体 = 纯本地编码工人，无公司身份。
- **同工作区互斥**：同一项目工作区同时只允许一个委派任务运行（文件锁），避免两个智能体互相踩改动；排队或拒绝并提示。

### 5.2 权限模式映射（编排层模式 → 子智能体启动参数）

| 我们的权限模式（09 篇） | 委派行为 | Claude Code 参数示例 | 审查 |
|---|---|---|---|
| ask（询问） | 允许委派，但子智能体被限制为"只读探查 + 产出方案" | `--permission-mode plan` 类等价 + 禁编辑/命令工具 | 方案以卡片呈现，改代码需用户切模式 |
| auto-edit（自动编辑） | 允许文件编辑，禁止任意的 shell 命令（白名单命令除外） | `--permission-mode acceptEdits` 等价 + `--allowedTools "Edit,Read,Glob,Grep"` | 任务结束强制 diff 审查卡 |
| full-auto（全自动） | 允许编辑 + 白名单命令（构建/测试） | bypass 类参数 + 命令白名单映射 | 事后 checkpoint 审查 + 告警阈值 |

> 原则：**子智能体的自主性不得超过用户给本产品 Agent 授权的档位**。映射表在适配器内声明，编排层启动前校验；无法表达限制的后端（如通用 CLI）最高只允许 auto-edit 且必须强审查。

### 5.3 审计

- 子智能体全部工具事件（stream-json 捕获）归一化写入本地审计 JSONL（09 篇），`event.kind` 前缀 `delegate.*` / `child.tool_use`，字段含：父编排会话 ID、委派任务 ID、后端类型与版本、工具、参数摘要、结果摘要。
- 服务端视角：委派本身不触碰公司 API（子智能体无凭证），公司数据访问发生在编排层检索阶段（已有 OBO 审计），链条完整。
- 委派任务的最终改动（diff 摘要 + 用户接受/拒绝）入本地审计；如项目启用了"会话云端备份"（08 篇，租户开关），随备份上报。

### 5.4 提示注入与不可信产出

- 子智能体输出（含其阅读的网页/依赖 README 得出的结论）一律视为**不可信内容**：渲染隔离、不因其中"请运行 XX 命令"自动执行（09 篇防御策略同样适用于委派产物）。
- 子智能体请求工作区外路径、请求网络下载脚本等 → 编排层拒绝并转用户确认。

## 6. 页面与交互

### 6.1 Agent 工作台（在 08 篇线框上扩展）

```
┌─ Agent 工作台 ───────────────────────────────────────────────────────┐
│ 会话列表 │  会话: 订单退款接口        后端: [zcode ▾] 模式: auto-edit │
│          │ ┌─ 对话流 ─────────────────────────────────────────────┐ │
│ ▸ 退款接口│ │ 用户: 帮我在 order-svc 加退款接口（用zcode）          │ │
│ ▸ 周报   │ │ 编排: 已检索《订单域接口规范v3》+接口约定#42 → 生成简报│ │
│ ▸ …      │ │ ┌─ 委派任务卡 #d-101 ──────────────── [zcode] ─────┐ │ │
│          │ │ │ 状态: 运行中 04:32   ▸ 展开实时输出(折叠流)       │ │ │
│          │ │ │ 工具: Read×12 Edit×3 Grep×7    ▸ 事件明细        │ │ │
│          │ │ └───────────────────────────────────────────────────┘ │ │
│          │ │ [取消] [追加指令…]                                     │ │
│          │ │ ┌─ 审查卡: 3 个文件改动 ────── checkpoint #2 ──────┐ │ │
│          │ │ │ api_refund.go  +86 -4   [逐hunk diff] [拒绝hunk] │ │ │
│          │ │ │ refund_test.go +41        [全部接受] [全部拒绝]   │ │ │
│          │ │ └───────────────────────────────────────────────────┘ │ │
└──────────┴─┴────────────────────────────────────────────────────────┴┘
```

### 6.2 关键交互流（委派全流程）

1. 用户输入任务（可带 "用 claude/zcode 做"）；编排层澄清关键缺口。
2. 编排层检索公司上下文（KB/文档/IM 结论，OBO）→ 生成任务简报卡（可编辑）→ **首次委派需确认**（显示：后端、工作区、简报、将获得的能力档位）。
3. 启动子进程；实时流内嵌展示（默认折叠摘要，展开明细）；可追加指令/取消。
4. 结束：提取 diff → checkpoint（git 快照，08 篇）→ 审查卡（逐文件/逐 hunk）。
5. 用户接受 → 改动落盘 + 会话归档 + 审计；拒绝 → 一键恢复到 checkpoint。
6. 结果可"分享到 IM"（Agent 分享卡片，08 篇）。

## 8. 接口与错误码

- 本地 stdio JSONL 新增消息（08 篇协议扩展）：`delegate.launch` / `delegate.event` / `delegate.cancel` / `delegate.review`。
- REST：无新增（探测/委派均本地完成）；策略读取复用 `GET /api/v1/me/permissions` + 租户策略通道。
- 错误码 8xxx 扩充（登记 14 篇 §7；本篇占用 8030-8035，与 08 篇 8010-8011、09 篇 8012/8020-8028 不冲突）：`8030 后端未安装或路径无效` · `8031 后端版本不满足最低要求` · `8032 后端被租户策略禁用` · `8033 子进程异常退出` · `8034 委派超时已终止` · `8035 工作区被其他委派任务占用`。
- 权限点：`agent:delegate:use`（默认普通成员；与 03 篇 agent:* 并列登记）。

## 9. 边界与异常

| 场景 | 处理 |
|---|---|
| 后端未安装/未登录 | 探测失败→引导安装（不代装、不代持登录）；用户可切内置后端继续 |
| 后端版本升级破坏 CLI 协议 | 适配器维护"版本能力矩阵"；启动时冒烟（`--version` + 最小 headless 调用）；不兼容→提示锁定版本或降级 |
| 子进程卡死/失控 | 取消（优雅→强杀进程树）；资源上限与输出上限同 09 篇 run_command |
| 子智能体在 headless 下弹权限询问 | 视为配置错误：终止 + `delegate.warning` + 建议改参数组合 |
| 用户在终端手动改了同一仓库 | 委派前/审查时 diff 基线不一致 → 提示并以新 checkpoint 重建基线 |
| 多会话并发委派不同项目 | 允许（不同工作区）；同工作区互斥（§5.1） |
| 离线环境 | 外部后端依赖各自登录态/网络时由用户自理；内置后端可用内网 ai-gateway 离线工作 |

## 10. 与其它模块的依赖

- 08 篇：编排层是委派的发起方；内置后端即其自研循环；checkpoint/会话模型复用。
- 09 篇：权限模式映射、审批卡组件、审计流、危险内容防御全部复用。
- 10 篇：租户策略下发通道复用（`agent.allowed_backends` 随租户策略同步）；编码后端**不是**生态应用（用户自装，不走签名分发，但受策略准入）。
- 12 篇：管理台 Agent 策略域增加"允许的编码后端类型"配置。
