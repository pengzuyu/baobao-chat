## 1. 文档目的与范围

本文档是 BaobaoWork 的**总纲**：定义产品定位、用户角色、功能全景、核心设计原则、术语与里程碑，并给出整套设计文档的导航。各子系统的详细设计（交互、数据、接口、边界）见对应分册，本文不展开。

范围：企业内部使用的桌面协作软件，包含 IM（私聊/群聊）、语音/视频通话、在线文档（Word/PPT/Excel）、文件与图片收发、自研 AI Agent（可对项目做开发、执行脚本、使用本机权限）、公司生态应用接入与技能分发、三级知识库、多租户多角色管理后台。

明确**不在**本期范围：移动端原生 App（架构预留）、外部客户访问、PSTN 电话、跨企业互联。

## 2. 产品定位

**一句话定位**：把"聊天 + 会议 + 文档 + 知识库 + 一个能干活的 AI Agent"装进一个轻量桌面客户端，让员工在一个入口内完成日常协作，让管理员一个后台管住整个组织。

### 2.1 规模假设（设计基线）

| 维度 | 假设 |
|---|---|
| 租户数 | 1 ~ 50 个（集团多子公司 / 多事业部场景） |
| 单租户用户 | 500 ~ 20,000 |
| 单租户日活 | 用户数的 60% |
| 消息量 | 峰值 5,000 msg/s（2 万用户租户） |
| 群规模 | 普通群 ≤ 500 人，广播群 ≤ 5,000 人（只读） |
| 文件 | 单文件默认上限 10 GB（租户可配） |
| 通话 | 1v1 + 多人 ≤ 16 方视频（SFU 转发），音频会 ≤ 64 方 |
| 网络环境 | 公司内网 / 专线为主，支持混合云部署，数据不出租户边界 |

### 2.2 与通用 IM 的差异点（设计重点）

1. **AI Agent 是一等公民**：不是聊天机器人插件，而是能打开本地项目、读写代码、执行脚本、调用公司内部系统的"数字员工"。
2. **Agent 身份一致性**：Agent 访问一切公司内部内容（文档、知识库、生态应用）**一律以用户本人身份鉴权**，不存在"Agent 超级账号"。
3. **生态应用 centrally 管、locally 用**：管理员统一接入公司生态应用与预置技能，用户客户端自动同步安装、更新、撤销。
4. **多租户 + 分级知识库**：组织隔离 + 个人/部门/公司三级知识库与分级授权。

## 3. 用户角色画像

| 角色 | 说明 | 核心诉求 | 主要使用模块 |
|---|---|---|---|
| 普通成员 | 公司员工 | 高效沟通、找文件找知识、让 Agent 替自己干活 | IM、通话、文档、KB、Agent |
| 部门管理员 | 兼业务的部门负责人 | 管本部门人员与部门知识库、部门群 | + 管理后台（部门域） |
| 租户管理员 | 公司 IT / 行政负责人 | 管组织、角色权限、安全策略、应用接入、合规审计 | + 管理后台（租户域） |
| 平台运营 | 部署方运维（若多租户托管） | 租户生命周期、配额、平台监控 | 管理后台（平台域） |
| 审计合规员 | 安全/法务 | 全链路审计检索、导出、告警处置 | 管理后台（审计域，只读） |
| 应用管理员 | IT 中台/集成负责人 | 接入/升级生态应用、发布技能包 | 管理后台（应用域） |

> 一个自然人可同时具有多个角色；角色与权限模型见 `03-身份认证与权限体系`。

## 5. 核心设计原则（P0，所有分册必须遵守）

| # | 原则 | 含义 |
|---|---|---|
| 1 | **身份一致性（On-Behalf-Of）** | Agent 与生态应用对内部资源的一切访问都以用户本人身份进行（用户 token + `act` 声明标记"由 Agent 代为操作"），服务端按用户权限判定并双写审计。禁止任何形式的服务级超级账号直连业务数据。 |
| 2 | **本地优先执行** | Agent 必须在用户设备本地执行（这是"使用本人系统权限"的唯一安全途径），服务端只做鉴权、分发、模型代理与审计，不执行用户代码。 |
| 3 | **权限最小化与显式授权** | 危险操作（写文件、执行命令、外发消息）必须经用户确认；权限模式（询问/自动编辑/全自动）可切换、可审计。 |
| 4 | **一切可审计** | 消息、文档访问、Agent 工具调用、管理操作全链路留痕；审计日志追加写、不可篡改（哈希链）。 |
| 5 | **多租户硬隔离** | `tenant_id` 贯穿所有表与 API，数据库启用行级安全（RLS）；对象存储按租户分桶/分前缀。 |
| 6 | **资源克制** | 客户端安装包 < 30 MB、空闲内存 < 300 MB、冷启动 < 2 s；一切后台任务可暂停、可降级。 |
| 7 | **协议开放与演进** | 内部工具协议对齐 MCP（Model Context Protocol）概念，为未来与外部生态互通留门；WS/REST 协议带版本号与兼容窗口。 |

## 7. 术语表

| 术语 | 英文/标识 | 定义 |
|---|---|---|
| 租户 | tenant | 顶级组织隔离单元（一家公司/一个子公司），全数据以 `tenant_id` 隔离 |
| 组织树 | org tree | 租户内 部门(dept) 树，用户可属多部门 |
| 会话 | conversation | 私聊/群聊/广播群的统一抽象，会话内消息按 `seq` 单调递增 |
| 消息序列号 | seq | 会话内服务端分配的单调序号，多端同步的游标基础 |
| 知识库空间 | KB Space | 知识库容器，分 `personal` / `dept` / `company` 三级 |
| 生态应用 | Ecosystem App | 管理员统一接入的公司内部系统连接器（OA、审批、Jira…），向 Agent 提供工具 |
| 技能 | Skill | 预置的可安装能力包（提示词 + 脚本 + 资源），格式对齐 SKILL.md 风格 |
| Agent 运行时 | Agent Runtime | 随客户端分发的 Rust 独立进程，执行 Agent 循环与工具调用 |
| 权限模式 | permission mode | Agent 会话级变更控制策略（官方名见 detail/D13）：`ask`＝**变更前确认模式** / `auto-edit`＝**自主模式**（危险命令仍审批）/ `full-auto`＝**完全控制模式** |
| 编排层 | Orchestrator | 自研 Agent Runtime 的定位：需求澄清、公司上下文收集、任务拆分与委派、审查汇总（17 篇） |
| 编码执行后端 | Coding Backend | 受编排层委派执行编码任务的可插拔后端：Claude Code、zcode、其他 CLI 智能体、内置自研循环（17 篇） |
| 专家 Agent | Expert Persona | 带独立工具集/技能/MCP 绑定的可复用角色定义包，公司库+个人库两级，可按协作图（Team Graph）组队协作（detail/D14） |
| 任务简报 | Task Brief | 委派给编码后端的任务书：目标/约束/公司上下文摘录/验收标准/禁忌（17 篇） |
| 用户代理凭证 | OBO credential | Agent 以用户身份调用内部 API 时使用的降权 access token，含 `act`（agent 会话）声明 |
| 工具 | Tool | Agent 可调用的原子能力（读文件、执行命令、查知识库、调生态应用） |
| 检查点 | checkpoint | Agent 修改前对工作区做的 git 快照，可一键恢复 |
| 权限点 | permission point | RBAC 的最小授权单元，命名 `域:动作:对象`，如 `doc:file:edit` |
| 上下文压缩 | compaction | 会话历史超预算时自动摘要归档以腾出模型上下文窗口 |

## 8. 里程碑规划（建议）

| 阶段 | 周期 | 交付 | 说明 |
|---|---|---|---|
| 一、协作底座 | M1–M3 | 认证/组织/角色、IM（私聊+群聊+消息同步）、文件与图片、管理后台基础、协议 v1 | 先让"能聊、能传、能管" |
| 二、内容与会议 | M3–M6 | 音视频通话、在线文档协同、公司/部门知识库（含检索）、ai-gateway 上线 | 内容生产与消费闭环 |
| 三、Agent MVP | M5–M9 | Agent Runtime（本地工具+权限框架+审计）、**编码后端委派（Claude Code/zcode 适配器，17 篇）**、个人知识库、Agent 卡片进 IM、生态应用注册与同步、预置技能安装 | 核心差异化能力落地 |
| 四、生态与规模 | M9–M12 | 技能市场（租户内）、会议纪要等深度 AI 场景、20k 用户规模优化、开放 API | 从产品到平台 |

> 阶段三与阶段二部分并行：ai-gateway 与审计底座需要在 Agent 之前就绪（详见 02/03/15）。

## 9. 文档约定

- 每篇分册统一模板：功能概述 → 角色与场景 → 页面结构与信息架构 → 核心交互流程 → 数据模型 → 接口设计 → 边界/异常/降级 → 模块依赖 → 开放问题。
- 交互流程用编号步骤 + ASCII 状态机/时序图；接口用表格（伪 REST / WS 事件），设计阶段不写实现代码。
- 权限点命名 `域:动作:对象`；错误码分段见 `14-通信协议设计` §7。
- 文档变更在本文件头登记版本；跨文档引用使用相对链接。
