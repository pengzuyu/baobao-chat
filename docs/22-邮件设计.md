## 1. 概述

### 1.1 定位与边界

公司没有可依托的既有邮件服务器，本篇定位为**自建私有化邮件系统**。四条边界决策：

| # | 决策 | 说明 |
|---|---|---|
| 1 | **不自研协议栈** | SMTP/IMAP 协议服务器自研是安全与兼容性天坑；邮件栈＝开源组件化组合（§3.2 选型） |
| 2 | **自研的是管理面** | bbw-mailadm 并入 mail-svc：邮件域管理、账户生命周期与 org 域打通、别名/群发列表、配额、反垃圾策略下发（§4.1） |
| 3 | **数据不出租户边界** | 邮件存储于私有部署内（本地卷/MinIO 缓存），对齐 00 篇原则 5 |
| 4 | **身份唯一，无第二套账号密码** | 邮箱账户唯一权威源＝org 域 user 表；三条认证路径全部回源 03 篇 auth（§3.4，核心卖点） |

客户端能力边界：统一收发/全文搜索/重要来信 IM 提醒/邮件转发 IM 卡片/iCal 会议日历联动（21 篇）/另存知识库（11 篇）/Agent 邮件工具（09 篇）。

### 1.2 场景

| # | 场景 | 说明 |
|---|---|---|
| S1 | 登录即有邮箱 | 客户端登录后主导航出现 📧，零配置、无邮箱密码概念 |
| S2 | 日常收发 | 三栏收件箱、会话线程、未读/星标、写信（富文本/附件/抄送密送/定时发送） |
| S3 | 搜索与提醒 | 服务端全文搜索（zhparser）；重要来信 IM 提醒（默认克制） |
| S4 | 协作联动 | 邮件转 IM 卡片（附件可存文件域）；iCal 邀请→21 篇日历；另存知识库 |
| S5 | 第三方客户端 | Outlook/Foxmail/系统邮件 App 经应用专用密码接入（§3.4 路径②） |
| S6 | 共享邮箱 | 部门邮箱：ACL 授权（viewer 可读/owner 可代发），代发显示"XX 代部门邮箱发送" |

### 1.3 非目标

Webmail（阶段四开放问题，移动场景，届时直接 OIDC 对接我们登录）、日历/联系人全套 groupware（日历由 21 篇承担，联系人复用 03 篇通讯录）、公网免费邮箱聚合、短信网关。里程碑建议：**阶段三**整体交付（依赖 org 生命周期事件、D10 策略中心、16 篇 mail profile 就绪）；Webmail 与历史迁移工具阶段四。租户未启用邮件 profile 时导航不显示 📧（feature flag，14 篇灰度机制）。

## 2. 角色与场景

| 角色 | 邮件行为 |
|---|---|
| 普通成员 | 收发/搜索/规则/签名/转发 IM/应用专用密码管理 |
| 部门管理员 | 部门共享邮箱治理（ACL 授权、代发审计） |
| 租户管理员 | 邮件域与邮箱治理：域/DNS/别名/群发列表/反垃圾/配额策略（§3.5 管理端） |
| 应用管理员/平台运营 | 邮件栈部署与容量（16 篇 mail profile） |
| 审计合规员 | 邮件元数据只读检索（收发记录/策略命中/代发），正文不入审计 |
| Agent（经 OBO） | mail.read 检索摘要、mail.send/mail.reply 外发（§4.7） |

## 3. 架构与信息结构

### 3.1 总体架构

```
┌ 客户端(一等路径①) ──────────┐   ┌ 第三方客户端(路径②: Outlook/Foxmail/系统App) ┐
│ 📧 邮件 MAI-01..04          │   │   IMAP(993/TLS) · SMTP 提交(465/587, SASL)    │
│ 三栏/写信/邮箱设置/搜索      │   └───────────────┬─────────────────────────────┘
└──────┬──────────────────────┘                   │ LOGIN=应用专用密码(非主口令)
       │ REST + WSS(我们的 access token / OBO)     ▼
┌──────▼─────────────────── mail-svc(自研, 并入模块化单体) ──────────────┐
│ 收发代理: 客户端 REST → 邮件栈(服务级凭证 master/admin API, KMS 代持)   │
│ bbw-mailadm 管理面: 域/别名/群发列表/配额/反垃圾策略下发/邮箱生命周期    │
│ 增量同步引擎(IMAP IDLE/轮询) · 搜索索引(PG FTS+zhparser) · 提醒规则引擎 │
│ auth-bridge(自研薄组件≈百行): 「转发校验+用户映射」, 无状态可多副本       │
└──────┬──────────────────────────────────────────┬──────────────────────┘
       │ 路径③: admin API(服务级凭证)               │ 路径② auth 回源(HTTP)
┌──────▼────────────── 邮件栈(开源组件化, 部署可选 profile) ─────────────┐
│ SMTP/MTA(Postfix 或 Stalwart) → 反垃圾(Rspamd) + 病毒(ClamAV)          │
│ 投递/存储(IMAP: Dovecot 或 Stalwart; Maildir/卷存储)                    │
│ 对外模式: 公网 MX/PTR/smarthost 中继(§3.3)                              │
└────────────────────────────────────────────────────────────────────────┘
   存量依赖: PostgreSQL(元数据/搜索索引) · MinIO(正文缓存) · auth/org(03)
```

### 3.2 邮件栈选型对比

| 方案 | 组成 | 许可证 | 资源/运维 | 能力 | 结论 |
|---|---|---|---|---|---|
| **A（推荐）** docker-mailserver | 单容器：Postfix + Dovecot + Rspamd + ClamAV | docker-mailserver MIT；Postfix EPL-2.0/IPL；Dovecot MIT/LGPL；Rspamd Apache-2.0 | 部署最简；compose/K8s 双形态友好 | SMTP/IMAP/反垃圾/病毒扫描齐全，社区成熟 | **阶段三基线** |
| B 分组件自组 | Postfix + Dovecot + Rspamd 独立部署 | 同 A（各组件原生许可证） | 可控性最高，参数面大、运维复杂 | 同 A，可精细调优/独立扩容 | 大租户或特殊合规时自 A 平滑演进 |
| C Stalwart | Rust 一体化（SMTP/IMAP/JMAP 单二进制） | AGPL-3.0 | 资源占用小 | 自带 JMAP 与外部 HTTP 认证适配（auth-bridge 更薄） | 观察项：AGPL 不改源码内部使用可接受（同 OnlyOffice 逻辑），JMAP 演进备选 |

许可证登记 **01 篇附录 A**：Postfix（EPL-2.0/IPL）、Dovecot（MIT/LGPL）、Rspamd（Apache-2.0）、docker-mailserver（MIT）、ClamAV（GPLv3，独立进程调用、不修改源码）归 **A.1 宽松/进程隔离档**；Stalwart（AGPL-3.0）归 **A.2 内部使用可接受档**。

### 3.3 运行模式与 DNS 前置

| 模式 | 前置条件 | 说明 |
|---|---|---|
| ① 纯内网域（默认） | 内部 DNS MX 指向邮件栈；域如 `corp.company.internal` | 域内互发不触公网；多数内网企业场景 |
| ② 对外收发 | 公网域名 + MX + 反向 PTR + IP 信誉管理；可配 smarthost 企业中继 | 列为**部署前置评估项**；未就绪时外域发送返回 9035/9036 |

初始化向导（16 篇 init 工具新增检测项，**回填 16 篇**）：逐条检测 + 修复指引，检测结果写入 mail_domain.dns_status，管理端以状态灯展示（§3.5 管理端）：

| 检测项 | 记录示例（内网域/对外域） | 用途 |
|---|---|---|
| MX | `corp… 3600 IN MX 10 mail.corp…` | 邮件路由指向邮件栈（内网=内部 DNS，对外=公网权威 DNS） |
| SPF | `v=spf1 mx -all` | 声明合法发信源，防域内地址被伪造 |
| DKIM | `2026a._domainkey TXT "v=DKIM1; k=rsa; p=…"` | 发信签名；私钥由 bbw-mailadm 生成、KMS 保管，向导引导发布公钥 |
| DMARC | `v=DMARC1; p=quarantine; rua=mailto:…` | SPF/DKIM 未通过对齐时的处置与报告 |
| autodiscover | `CNAME autodiscover → mail.corp…` | 第三方客户端自动配置（路径②首次体验） |

### 3.4 与统一身份的集成（SSO）★核心

**身份权威唯一**：邮箱账户唯一权威源＝org 域（03 篇 user 表）。邮件栈内**不维护独立用户库**——bbw-mailadm 经邮件栈 admin API 创建/停用 mailbox（维护 user_id ↔ mailbox 映射）；入职自动开户 `employee@{domain}`；离职 offboarded 自动停用（D02 事件总线 `user.offboarded` 消费方新增 mail，**回填 D02**）。

```
路径① 客户端内（一等路径, 零感知）
  用户(我们的 access token/OBO) → mail-svc → [服务级凭证 master/admin API] → 邮件栈
  · 用户无"邮箱密码"概念；登录客户端即有邮箱

路径② 第三方客户端（Outlook/Foxmail/系统邮件 App）
  客户端 IMAP LOGIN(应用专用密码) → Dovecot/Stalwart auth 转发(auth-bridge 薄组件)
  → 回源我们 auth 校验(校验"应用专用密码"hash, 非主口令) → 放行
  · SMTP 提交(SASL)同路径；应用专用密码在 MAI-03 生成/吊销, 绑定用户, 吊销即时生效

路径③ 管理面/服务间
  bbw-mailadm → 邮件栈 admin API（服务级凭证 KMS 代持, 同 10 篇连接器机制）

  ══ 三条路径全部回源 03 篇 auth；主口令永不落入邮件栈 ══
```

auth-bridge 实现要点（选型注记，非实现代码）：Dovecot 走 passdb checkpassword/LUA 指向 auth-bridge HTTP；Stalwart 用内置外部 HTTP 认证适配；Postfix SASL 复用 Dovecot。auth-bridge 为自研约百行薄组件，只做"转发校验＋用户↔mailbox 映射"，无状态、可多副本。

三路径凭证矩阵（谁持有什么）：

| 凭证 | 形态 | 持有方 | 存储位置 | 失效方式 |
|---|---|---|---|---|
| 用户 access token / OBO | JWT（03 篇签发） | 客户端内存 / Agent Runtime | 不落盘 | 15 min 到期 / 登出吊销 |
| 服务级凭证（master/admin API） | 邮件栈管理员凭证 | mail-svc | KMS 引用（同 10 篇 auth_ref(kms://…)） | 定期轮换 |
| 应用专用密码 | 随机串，仅生成时显示一次 | 用户抄录进第三方客户端 | 我们侧仅存 hash（mail_app_password） | 用户即时吊销 / 离职随邮箱停用 |
| 用户主口令 | — | **永不出 03 篇 auth，邮件栈全程不可见** | — | — |

**权限模型归属我们，邮件栈只执行**：个人邮箱＝本人；部门/共享邮箱＝ **resource_acl 的 mail 资源**（03 篇 §4.4 授权：user/dept/role → viewer 可读 / owner 可代发）；Agent 邮件工具（mail.read/mail.send）以用户 OBO 身份，仅能访问"本人邮箱＋被授权的共享邮箱"；代发外显"XX 代部门邮箱发送"。阶段四 Webmail 直接 OIDC 对接我们登录，不新增账号体系。

## 4. 核心流程

### 4.1 开户与生命周期（与 org 打通）

```
入职: org 建户 → D02 事件总线 → mail 消费 → bbw-mailadm 调 admin API 开 mailbox
      (employee@{默认域}, 配额=租户默认 5GB) → 客户端登录即见 📧
      命名策略: 默认 employee_no@域; 租户可配姓名拼音并自动生成别名
      (mail_alias) 兼顾可读性与避免工号外泄
异动: 部门调动 → 共享邮箱权限随 resource_acl 重算(03 篇 §4.5 收敛联动)
离职: user.offboarded → 停用 mailbox(拒收+拒登, 应用专用密码即时失效)
      → 保留期(默认 90 天, 租户可配) → 管理员归档导出 → 清除
```

### 4.2 收信与提醒

```
发件人 ──SMTP──► MTA → Rspamd 评分(策略由 bbw-mailadm 下发) → ClamAV 扫描
  ├ 垃圾 → 隔离区(MAI-01 可见, 管理员放行)
  ├ 病毒 → 拒收/删除标记(审计)
  └ 通过 → LMTP 投递 mailbox → mail-svc 同步引擎(IDLE 推送/轮询兜底)
       → 元数据+摘要落 PG(mail_message), 正文按需缓存(§5)
       → 命中 mail_rule? ──► WS mail.new{kind:reminder} + IM 内提示(默认克制:
          仅"通讯录发件人且收件人含我"默认开, 自定义规则可加; 不@不打扰)
```

同步与游标（mail-svc ↔ 邮件栈）：

| 项 | 约定 |
|---|---|
| 推送 | IMAP IDLE 长连接推送为主；断连自动退化为 ≥5 min 轮询兜底 |
| 游标 | 每文件夹记 uidvalidity + uid_next；uidvalidity 变化 → 该文件夹全量重同步 |
| 幂等 | 以邮件栈 UID/message_id 去重，重拉不产生重复索引行 |
| 首次同步 | 开户后全量回拉（分批限速），进度在 MAI-03 可见；完成前搜索返回 9025 |

### 4.3 写信与发送

| 项 | 约定 |
|---|---|
| 富文本 | 编辑器＋签名（按发件身份） |
| 附件 | 走文件域（07 篇）：≤25 MB 内嵌；超限自动转外链（下载页三要素：时限/次数/密码），收件人体验为链接 |
| 抄送/密送 | 标准 Cc/Bcc |
| 定时发送 | send_at 暂存草稿＋定时 worker 提交；发送前可撤回；时间非法 9029 |
| 外发检查链 | 敏感词（**04 篇 sensitive_word 库复用**，三模式，9034）→ 对外模式判定（内网域发外域而 DNS 未就绪→9035；被中继/信誉策略拒绝→9036）→ 频率限制（9031） |
| 代发 | 共享邮箱 owner 提交，From=共享地址，头域标注代发人，外显"XX 代部门邮箱发送"；审计 |
| 退信 | 异步 DSN 解析→发件箱回执卡片＋mail.new 通知 |

### 4.4 全文搜索

服务端索引：PG FTS（**zhparser** 中文分词）覆盖 主题/发件人/摘要/收件人 + 已缓存正文；范围＝本人邮箱＋被授权共享邮箱（ACL 前置过滤，复用 03 篇判定链）；结果高亮跳转；索引随同步增量构建，未就绪返回 9025。

### 4.5 邮件转发到 IM

新消息类型 **15 `mail_card`（回填 04 篇 §1.2）**：body={subject, from, date, snippet, attachments[]}；收件人无需邮箱权限即可看卡片；[存文件域] 动作由**转发者**触发：mail-svc 从邮件栈拉取附件→走 07 篇上传管线（sha256 秒传）得 file_id 后随卡片分发。

### 4.6 iCal 与会议日历联动（21 篇）

入站：检测 text/calendar → 解析 VEVENT → 建 21 篇 calendar_event(source=ical_external) ＋ 阅读 pane 内 [接受/暂定/拒绝]；回执经我们 SMTP 发送 iCal REPLY（写回）。出站：21 篇组织者邀请外部邮箱 → mail-svc 发 text/calendar REQUEST（21 篇 §4.4，对端即本篇自有邮件栈）。解析失败 9033，不影响邮件正文阅读。

### 4.7 Agent 邮件工具（OBO，**登记 09 篇工具目录扩展**）

| 工具 | 能力 | 风险级 | 门控（09 篇矩阵） | 需权限点/scope |
|---|---|---|---|---|
| mail.read | 搜索/读取/摘要（仅本人邮箱＋被授权共享邮箱） | 低 | 全模式自动 | mail:agent_tool |
| mail.send | 新邮件外发（含共享邮箱代发） | 高 | **永不全自动**，逐次人工确认 | mail:agent_tool |
| mail.reply | 回复既有邮件 | 高 | **永不全自动**，逐次人工确认 | mail:agent_tool |

外发＝高危确认（**加入 09 篇"永不全自动清单"**）；工具经 mail-svc 以用户 OBO 身份执行，审计 subject=user / actor=agent（act 声明）；Agent 外发同样过敏感词与对外策略（9034/9035/9036），不因 Agent 通道放宽。

## 5. 数据模型（PG，RLS 同全局约定；**回填 13 篇 §3**）

**mail_domain** 邮件域：id, tenant_id, domain(UK), mode(1 内网 2 对外), dkim_key_ref(kms://…，**仅 KMS 引用**), dns_status jsonb{mx,spf,dkim,dmarc,autodiscover}, is_default, created_at。

**mailbox** 邮箱：id, tenant_id, domain_id, address(UK tenant 内), type(1 personal 2 shared), owner_user_id(personal) / govern_dept_id(shared 治理部门), quota_bytes(默认 5GB，租户可配), used_bytes, status(1 active 2 suspended 3 archived), created_at, suspended_at。应用专用密码独立成表（下行）。

**mail_alias** 别名与群发列表：id, tenant_id, alias_address, kind(1 alias→单 mailbox 2 list→成员展开), target_mailbox_id / members jsonb, enabled, created_by。

**mail_app_password** 应用专用密码（路径②）：id, tenant_id, user_id, name, hash, created_at, last_used_at, revoked_at；吊销即时生效（auth-bridge 在线校验）。

**mail_message** 邮件缓存索引（权威数据在邮件栈，本表为缓存+索引）：id, tenant_id, mailbox_id, folder_id, message_id(RFC822, UK per mailbox), in_reply_to/thread_id, from_addr, to_addrs jsonb, cc/bcc jsonb, subject, snippet, has_attachment, flags smallint 位标志(seen/flagged/answered/draft/scheduled), size, body_state(1 meta_only 2 cached), body_obj_key, send_at, received_at, fts tsvector。**正文缓存策略：按需拉取＋LRU**（每用户缓存配额默认 2 GB，逐出后可回源邮件栈重拉；附件不缓存，转存走 07 篇）。

**mail_folder_meta** 文件夹元数据：id, mailbox_id, name, type(inbox/sent/drafts/trash/junk/archive/custom), uidvalidity, uid_next, sync_cursor, total_count, unread_count。

**mail_rule** 提醒规则：id, tenant_id, user_id, kind(1 contact 2 custom), conditions jsonb(发件人在通讯录/发件人含/主题含/收件人含我), action(1 im_remind 2 daily_digest), enabled。

客户端本地（SQLite，**回填 13 篇 §4**）：local_mail_msg（列表镜像 + FTS5 虚表）/ local_mail_state（文件夹未读与游标）；均为缓存非权威源；离线可读范围=已缓存正文（与服务端 LRU 策略联动）。

配套登记（**回填 13 篇 §5/§6**）：Redis `t:{tid}:mail:sched`（定时发送 zset）、`t:{tid}:mail:quota:{mailbox_id}`（配额计数缓存）；MinIO 前缀 `t/{tid}/mail/{mailbox_id}/{sha256 前 2}/{sha256}/body.eml`（正文缓存，LRU 逐出）。

## 7. 边界与安全

| 项 | 约定 |
|---|---|
| 钓鱼防护 | 外链域名校验（高危 TLD、punycode/IDN 同形异义检测）＋仿冒域名提示（与自有域、常用联系人域相似度）；远程图片默认不自动加载（租户/用户策略） |
| 病毒 | 入站在 SMTP 网关 ClamAV 扫描（Rspamd 联动）；客户端附件下载复用 **07 篇病毒扫描钩子**（打开前扫描策略） |
| 附件外链 | 超限转外链走 07 篇 share_link 三要素（时限/次数/密码）；外链不携带任何邮箱凭证，可独立吊销 |
| 退信/异步回执 | DSN 解析后经 mail.new 通知发件人；发送状态在已发送列表留存 7 天可查 |
| 外发敏感词 | **04 篇 sensitive_word 库复用**（拦截/替换/审计三模式）；人与 Agent 外发同权生效 |
| 反垃圾 | Rspamd 策略由 bbw-mailadm 统一下发（得分阈值/黑白名单）；隔离区用户可见、管理员放行 |
| 凭证 | 主口令永不入邮件栈（§3.4）；服务级凭证仅存 KMS 引用（同 10 篇）；应用专用密码吊销即时生效（在线校验） |
| 隐私 | 管理员不可读他人正文；审计仅元数据（收发/策略命中/代发/应用密码变更）；共享邮箱读取经 ACL 判定并留痕 |
| 内容边界 | 邮件内容**不用于模型训练**（租户策略，默认禁）；Agent 摘要仅当前会话使用 |
| 传输 | 客户端↔mail-svc 走既有 WSS/REST（TLS）；第三方客户端强制 TLS（993/465），明文端口默认关闭 |
| 降级 | 邮件栈故障：客户端邮箱页明确错误（9022/9005）＋trace_id 上报；IM/文档等主链路不受影响；同步断点用 uidvalidity/uid_next 游标恢复，变更后全量重同步 |

## 9. 开放问题

1. 对外收发模式的 IP 信誉运维：发信 IP 被 listing 的处置流程、是否启用专用发信子域与独立发信出口。
2. 邮件归档合规（金融类租户）：journaling/法定留存的档位与检索承诺，需 15 篇合规清单定级。
3. Webmail（阶段四，移动场景）：OIDC 对接统一登录后，富客户端与三栏体验的功能对齐范围。
4. 历史邮件迁移：若未来从其他邮件系统迁入，IMAP 拉取式迁移工具的窗口期与双收策略。
5. Exchange 风格的全文委派（delegate access）是否支持（当前仅共享邮箱 ACL＋代发，个人对个人委派未开放）。
