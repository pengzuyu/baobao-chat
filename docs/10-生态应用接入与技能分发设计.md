## 1. 功能概述

### 1.1 概念模型：应用 / 技能 / 工具

```
┌────────────────────────────────────────────────────────────────────┐
│  生态应用(Ecosystem App) = 连接公司内部系统的"连接器"                  │
│    ├─ 声明工具(app.*) ──── executor=connector(服务端转发) ──► OA/Jira/… │
│    └─ 捆绑技能包(skills)                                                │
│  技能(Skill) = 可安装能力包: SKILL.md(提示词) + scripts/ + assets/       │
│    └─ 引导模型"何时、如何"组合工具(不新增原子能力)                       │
│  工具(Tool) = 原子能力: 内置(read_file…) 或应用提供(oa.todo.list)        │
└────────────────────────────────────────────────────────────────────┘
       三者汇入 Agent Runtime 的【工具注册表】(§4.6 合并规则)
         └─ 按需注入模型上下文(08 篇 §4.3 预算: 技能 5% + 工具描述)
```

| 概念 | 定义 | 归属 | 分发 |
|---|---|---|---|
| 生态应用 | 管理员统一接入的内部系统连接器（清单+包+连接器配置） | 租户 | app-registry → 客户端同步安装 |
| 技能 | SKILL.md 风格能力包（frontmatter 元数据+正文指令+scripts/+assets/） | 租户预置或用户本地 | 同上（签名增量） |
| 工具 | 应用清单声明或内置的原子能力，inputSchema 描述 | 应用/内置 | 随应用清单分发，无独立包 |

三者关系一句话：**应用提供工具，技能教模型用工具；技能可以独立于应用存在（只用内置工具），应用可以不带技能（纯工具）**。

### 1.2 与 MCP 概念对齐（为互通留门，P0-7）

| 本产品概念 | MCP 概念 | 对齐点 |
|---|---|---|
| 工具定义（§3.2 tools[].inputSchema） | MCP Tool（jsonschema input） | 字段结构一致，可直接换装 |
| 连接器只读内容（如 OA 待办列表视图） | MCP Resource | 清单预留 `resources[]` 段（本期不实现） |
| 技能包（SKILL.md 正文指令） | MCP Prompt | 同为"注入模型的指令模板"抽象 |

策略（**2026-11-07 用户裁决更新**）：连接器升级为 **MCP Server 网关暴露**——服务端把 connector 与公司域 API（kb/doc/oa/im/file）统一包成 MCP server，Runtime 引入 MCP client（bbrt-mcp，D11 §2.10）**连接期 list_tools 动态发现**工具（D14 §6.1）；新增服务/旧服务增能力**零客户端与 Runtime 改动**。AppManifest 的 tools[] 定义不变（本就对齐 MCP tool schema），executor=connector 的落地形态从"服务端私有转发"收敛为"MCP server 工具"；用户身份仍逐请求传播（§5 路径 A/B 与 `X-BBW-Acting-User` 机制不变，见 D14 §6.2 三层身份）。

## 2. 角色与场景

| 角色 | 场景 | 关键诉求 |
|---|---|---|
| 应用管理员（IT 中台） | 接入 OA/Jira 应用、发布技能包 | 清单化接入、灰度、可回滚 |
| 安全审查员/审批人 | 清单与包审查 | 风险级、scope、签名链核验 |
| 租户管理员 | 预置技能策略（强制/推荐/可选） | 组织级能力铺放 |
| 普通成员 | 无感获得工具与技能；可选包自装 | 不需要懂"安装" |
| Agent Runtime | 注册表合并、热加载 | 隔离、限数、按需注入 |

## 3. 清单与信息架构

### 3.1 AppManifest.yaml 完整示例

```yaml
apiVersion: bbw.eco/v1
id: com.company.oa                     # 全局唯一，逆序域名
version: 1.4.0                         # 语义化版本（§3.2 规则）
publisher: com.company.it-middleware   # 发布者（对应发布密钥证书）
display:
  icon: assets/icon.png                # 256x256
  color: "#2F6BFF"
  name: 公司OA审批
  description: 对接公司OA，提供待办查询与审批提交
  vendor: IT中台
  support: bbw://support/it-middleware
permissions:                           # 权限声明（供审查与运行时门控）
  oboScopes:                           # 需要的 OBO scope（用户权限子集，03篇§6）
    - oa:todo:read
    - oa:approval:submit
  maxToolRisk: high                    # 本应用工具最高风险级（09篇矩阵依据）
tools:                                 # 工具定义（MCP tool jsonschema 风格）
  - name: todo.list                    # 注册全名: oa.todo.list（§4.6 命名空间）
    title: 查询我的待审批
    description: 按状态查询当前用户的OA待办/待审批列表
    inputSchema:
      type: object
      properties: { status: { type: string, enum: [pending, done, all] } }
    risk: low
    executor: connector                # connector(服务端转发) | client(本地脚本)
  - name: approval.submit
    title: 提交审批单
    description: 按模板提交审批单（字段由模板定义）
    inputSchema:
      type: object
      properties:
        templateId: { type: string }
        fields: { type: object, additionalProperties: true }
      required: [templateId, fields]
    risk: high
    executor: connector
connectors:                            # 服务端连接器配置引用（凭证不出服务端）
  - id: oa-main
    type: http
    baseUrl: http://oa.internal.example.com/api
    authRef: kms://oa/prod-api-key     # KMS 引用，清单内绝不出现明文
    timeoutMs: 8000
    rateLimit: { requestsPerMinute: 60 }
skills:                                # 捆绑技能包（随应用一起分发）
  - id: com.company.oa.expense
    version: 1.1.0
    path: skills/expense-assistant
minRuntime: 1.2.0                      # 最低 Runtime 版本
signature:                             # 发布签名（§7.1 签名链）
  algorithm: ed25519
  signedBy: com.company.it-middleware  # 应用发布密钥（平台根密钥签发证书）
  digest: sha256:9f2a…                 # manifest+package 摘要
```

### 3.2 字段表与版本语义

| 字段 | 必填 | 说明 |
|---|---|---|
| apiVersion | Y | 清单格式版本 `bbw.eco/v1`，前向兼容 |
| id / publisher | Y | 应用全局 ID / 发布者 ID（发布密钥证书主体） |
| version | Y | **语义化版本**：MAJOR=工具签名/语义不兼容，MINOR=新增工具或技能，PATCH=提示词与修复；运行时按 semver 比较 |
| display.* | Y | 展示信息（名称/图标/描述/支持入口） |
| permissions.oboScopes | Y | 需要的 OBO scope；发布时静态校验为"合法 scope 字典"（防任意字符串） |
| permissions.maxToolRisk | Y | 工具风险级上限（tools[].risk 不得超越） |
| tools[] | Y* | 工具定义：name/title/description/inputSchema/risk/executor（无技能的纯工具应用必填） |
| connectors[] | C | executor=connector 时必填：目标地址、KMS 凭证引用 authRef、超时、限流；**凭证只存服务端 KMS 加密**（§6.3） |
| skills[] | C | 捆绑技能包 id/version/path |
| minRuntime | Y | 最低 Runtime 版本，不满足则跳过安装并提示 |
| signature | Y | ed25519 签名与摘要（§7.1） |

### 3.3 技能包结构与 SKILL.md

```
com.company.oa.expense/
├── SKILL.md            # 能力包入口
├── scripts/            # 可执行脚本（python/bash；执行受 09 篇 run_command 沙箱约束）
└── assets/             # 模板/参考资料
```

```
---                              # SKILL.md = frontmatter 元数据 + 正文指令
name: 报销助手
description: 指导 Agent 收集报销要素并调用 OA 提交审批单
version: 1.1.0
triggers: [报销, 费用报销, 差旅报销]
allowedTools: [oa.todo.list, oa.approval.submit]
risk: high                       # 包内含脚本执行 → 按 09 篇沙箱与确认
oboScopes: [oa:todo:read, oa:approval:submit]
---
# 报销助手
## 何时使用
用户提出报销/差旅费用提交请求时。
## 流程
1. 向用户确认: 事由、金额、日期、票据是否齐全
2. 调用 oa.todo.list 查询可用模板
3. 生成 fields 草稿并展示给用户
4. 用户确认后调用 oa.approval.submit（高危，须用户确认卡）

- 金额、收款账户必须逐字让用户确认，不得自行推断
```

## 4. 核心流程

### 4.1 管理员接入流程（编号步骤 + 泳道）

```
 应用管理员          app-registry            安全审查/审批人           客户端(员工)
     │ 1 登记应用        │                        │                      │
     ├─────────────────►│ 生成 app 记录/发布密钥证书申请                  │
     │ 2 上传清单+图标+包 ►│ 静态校验: schema/semver/签名链/病毒与密钥扫描   │
     │ 3 配置连接器 ────►│ 凭证录入 KMS(加密), 只存 authRef               │
     │ 4 选择授权范围 ──►│ eco_rollout: 全员/部门/角色/白名单 + 灰度比例    │
     │ 5 提交安全审查 ──►│───────────────────────►│ 6 审查清单(§7.2)      │
     │                  │◄───────────────────────┤ 7 审批(高危工具二级批)  │
     │ 8 发布 ─────────►│ 版本落库+对象上传MinIO+签名清单生效              │
     │                  │ 9 WS 推送 app.updated ────────────────────────►│ 10 增量同步
     │                  │                        │                      │ 11 安装+热加载
     │                  │                        │                      │ 12 工具可用
```

### 4.2 版本管理 / 回滚 / 下架

| 操作 | 语义 |
|---|---|
| 发布新版本 | 新 eco_app_version 记录；灰度按 eco_rollout 逐步放量（canary % → 全量） |
| 回滚 | 将 current_version 指回旧版 + 推送 `app.updated`（客户端按降级同步） |
| 下架（delist） | 应用状态置 delisted + 推送 `app.revoked`；**用户端工具立即失效**（§4.4） |
| 吊销发布密钥 | 平台侧吊销证书 → 所有该发布者的版本在下次校验时失效 |

版本共存：本地目录按 `{app_id}/{version}/` 保留最近 2 个版本（回滚快切），更旧版本清理。

### 4.3 客户端同步机制

```
登录: GET /apps/catalog?installed={id:ver,…} ─► 差异(新增/升级/撤销/无变化)
平时: WS app.updated / app.revoked (14篇§3.2, payload 含 subject_type=app|skill)
安装管线(每应用):
  [1] GET download-ticket(MinIO 预签名) ─► [2] 下载到临时目录
  [3] ed25519 签名校验(平台根密钥→发布密钥证书链, §7.1) + sha256 摘要比对
  [4] 解包到 {dataDir}/eco/{app_id}/{version}.new ─► 原子 rename 生效
  [5] 经宿主向 Runtime 发 tools.reload ─► 热加载(注册表重建, §4.6)
  失败: 任一步失败 ─► 删除 .new, 保留旧版本继续可用, 上报 8043 + 管理端可见安装失败率
离线: 使用本地缓存安装; 启动联网后补一次全量校验
```

### 4.4 撤销的即时生效语义

| 状态 | 语义 |
|---|---|
| 在线 | `app.revoked` WS 推送 → 宿主即刻 tools.reload → 该 app.* 工具从注册表移除；进行中调用返回 8003 |
| 离线/推送丢失 | **缓存时效 ≤ 10 min**：每次工具调用前检查本地 app 状态时间戳，>10 min 且可联网 → 在线刷新后再放行；无法联网 → 高危工具拒绝（保守），低危工具放行但记录 |
| 技能 | 撤销同样即时：SKILL.md 从注入清单移除，进行中会话下一轮不再注入 |

### 4.5 预置技能同步安装（租户策略三档）

| 策略 | 行为 |
|---|---|
| 强制安装（force） | 登录即自动下载安装（走 §4.3 管线+签名校验）；不可卸载、不可禁用（UI 锁定标记，提示为管理员策略） |
| 推荐安装（recommend） | 首次进入 Agent 工作台弹引导页，一键安装全部推荐包（可跳过）；可卸载 |
| 可选（optional） | 技能目录手动安装（需 `agent:app:install` 权限点，03 篇 §4.1）；阶段四开放租户内技能市场 |

技能更新与签名：技能包与 应用包 同链路（ed25519 签名 + 版本化 + 增量同步）；"技能更新同样是签名增量"。技能包与 Runtime 技能加载器衔接：宿主安装后发 `tools.reload{reason: skill}`，Runtime 扫描 `{dataDir}/eco/skills/*/SKILL.md` 载入 frontmatter 元数据（name/triggers/allowedTools/risk）进技能索引，正文按 08 篇 §4.3 预算命中注入。

### 4.6 Agent 侧工具注册表合并规则

| 规则 | 设计 |
|---|---|
| 来源 | ① 内置工具（无前缀，09 篇 §3.1，仅本地能力）② 生态应用 `{app_short}.{tool}`（如 `oa.todo.list`，**经 MCP 网关连接期发现注册**，D14 §6.1）③ 用户本地/技能捆绑 `skill.{skill_short}.{tool}`（仅当技能声明 executor=client 的本地脚本工具）；另有公司域直供命名空间 `mcp.{server}.{tool}`（kb/doc 等，网关 server） |
| 命名空间隔离 | app_short 取 manifest id 末段；注册时全名冲突 → 后注册者**拒绝注册**并告警（8044），管理端发布时静态预检 |
| 版本冲突 | 清单 minRuntime 不满足 → 跳过并提示升级客户端；同应用本地多版本只有 current 生效 |
| 数量上限 | 注册表 ≤ 200 工具；单应用 ≤ 40；超出拒绝装载超出部分并在管理端告警 |
| 按需注入 | system 段仅放"工具名+一句话"目录（≤ 1k tokens）；完整 inputSchema 仅在 ①技能 allowedTools 命中 ②快模型相关性预筛 ③本会话近期调用过 时注入，每轮工具描述预算 ≤ 8k tokens（对齐 08 篇 §4.3，避免撑爆上下文） |

## 6. 接口设计

### 6.1 REST（管理端，均需 admin:* 权限点并落审计）

| API | 权限点 | 说明 |
|---|---|---|
| POST /api/v1/apps | admin:app:publish | 登记应用（1） |
| PUT /api/v1/apps/{appId} | admin:app:publish | 更新元数据 |
| POST /api/v1/apps/{appId}/versions | admin:app:publish | 上传版本（manifest+包，预签名直传）（2） |

### 6.3 连接器调用与凭证（引用 03 篇 §5/§6）

| 路径 | 条件 | 流程 |
|---|---|---|
| A：用户级凭证（首选） | 目标系统支持 OIDC/Bearer 用户令牌 | app-registry 将用户 **OBO token 透传**给目标系统；凭证完全属于用户 |
| B：服务间凭证代持 | 目标系统只接受固定 API Key（如传统 OA） | 凭证只存**服务端 KMS**（authRef）；app-registry 在服务端解密（仅内存）并转发请求，**客户端与 Runtime 永远拿不到凭证**；每次转发携带用户上下文头（`X-BBW-Acting-User`/`X-BBW-Act`）供对方系统审计 |
| 共同 | 两条路径调用方均为 OBO token（sub=用户，act=agent 会话） | 服务端审计双写；app-registry 对 app.* 调用按 connector.rateLimit 限流（§7.3） |

反模式（03 篇 §6.5 重申）：禁止在客户端包内置任何固定 API Key；禁止绕过 app-registry 直连目标系统。

## 7. 边界 / 异常 / 安全

### 7.1 清单签名链

```
平台根密钥(离线保管, 客户端内置公钥)
   └─签发→ 应用发布密钥证书(publisher 主体, 有效期, 可吊销)
             └─签署→ manifest + package 摘要(ed25519)
客户端校验: 根公钥验证书 → 证书验签名 → sha256 比对包 → 通过才安装(§4.3[3])
吊销: 证书吊销列表随版本清单分发; 吊销即触发 app.revoked 语义
```

### 7.2 供应链审查要点（接入流程第 6 步清单）

| # | 检查项 |
|---|---|
| 1 | 发布者身份与发布密钥证书有效期、申请审批留痕 |
| 2 | 工具 schema 审查：无危险默认值、参数范围合理、description 不含诱导性指令文本 |
| 3 | oboScopes 最小化（scope 字典白名单内且逐项说明用途） |
| 4 | 连接器目标地址白名单（仅内网域名/IP 段） |
| 5 | 包内容扫描：病毒、密钥泄露（09 篇模式库）、scripts 高危调用审查 |
| 6 | 技能 allowedTools 最小化；SKILL.md 正文人工审读（防提示注入负载） |
| 7 | 风险级审批：含高危工具/高危技能的应用需二级审批人 |

### 7.3 运行时限流与资源

| 层 | 措施 |
|---|---|
| app-registry | 每 (app, user, tool) 令牌桶（默认 30 次/min，connector.rateLimit 可调）；超限 9003 |
| Runtime | 生态写类工具同 app 并发 1；总并发工具调用 ≤ 4（含内置） |
| 审计 | 连接器转发全量落服务端审计（subject=user, actor=agent:{session}, app 工具名） |

### 7.4 其它边界

| 场景 | 处理 |
|---|---|
| 离线首登（无任何缓存） | 仅内置工具可用；联网后补同步 |
| 安装中断（断电/杀进程） | `.new` 临时目录残留 → 下次启动清理重试（原子 rename 保证不半装） |
| 多设备 | 安装为设备级（user_app_state 含 device_id）；强制包每台设备各自安装 |
| 用户调离灰度部门 | eco_rollout 重算 → 下次校验不命中 → 工具移除（缓存 ≤10min 语义） |
| 撤销时正在执行的调用 | 以调用时刻校验为准放行完成，后续调用拒绝（与 03 篇 §9 权限窗口一致） |
